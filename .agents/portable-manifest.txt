# 框架可攜標記表 —— 哪些檔案搬得過去,以及怎麼搬。
#
# 格式:路徑<空白>標記。以 / 結尾的是目錄,涵蓋底下所有東西。最長前綴者勝
# (不是讀取順序 —— 順序決定的話換個排法就換個行為,那是隱形的)。
#
# 標記:
#   copy      框架的一部分,內容與專案無關,照抄
#   generate  內容綁這個 repo(sha、路徑清單),必須在目標 repo 重新產生;照抄會靜默壞掉
#   ask       混著框架與專案兩種東西,要人決定帶哪些
#   skip      專案自己的東西,只是剛好住在框架根目錄底下
#
# **範圍之內、沒有更具體標記的一律 copy**,而且安裝時會被列出來讓人確認。
# 沒標記不等於不帶 —— 那又是白名單。
#
# 代價不對稱:多帶是吵鬧的(到了新專案馬上發現不對),
# 少帶是靜默的(沒人知道少了一條規則)。所以預設偏向多帶。

# ── 各 repo 自己的根目錄檔 ────────────────────────────────────
# **上游的同名檔只屬於上游自己。** 這六筆每個 repo 都有一份,
# 內容是那個 repo 的事實(它的說明、它的相依、它的忽略規則、它的 hook)。
#
# 為什麼特別要緊:`.githooks/pre-commit` 在**每個** repo 都必須**兩段都接**
# (leak_scan + gate.py --pre-commit)。照抄過去等於用上游那一份蓋掉下游那一份,
# 而兩份的內容是各自 repo 的事實 —— 拆掉權威層的動作看起來像一次成功的更新,
# 影音第三輪 dry-run 攔到(票 15)。
#
# **本段 2026-08-18(票 51:⑥)更正,舊文不刪、照 F-036 記在這裡:**
# 原寫「在下游是**三層掛載**,上游這一份只有 leak_scan(ADR 0010 不自管)」。
# 兩句各錯一件事:
#   (1)「三層」—— 那個 hook 只有兩個階段,全庫沒有一處說得出第三樣是什麼。
#   (2)「上游這一份只有 leak_scan」—— **票 27(2026-08-14)之後就是假的**,
#       上游的 .githooks/pre-commit 現在兩段都接(實測 :16-17)。
# **結論(標 skip)沒變,錯的是支撐它的理由。** 而理由欄正是本檔自己說的
# 「讓漂移看得見的東西」(manifest.py:22)—— 一段解釋為什麼的文字引用了
# 一個後來變掉的事實,而**註解引用一個改掉的事實,什麼都不會發生**(F-099)。
#
# `.gitattributes` 標 skip 的已知後果:框架的 `*.py text eol=lf` 保證不隨安裝走。
# 那是 F-0013 已記載的殘留,雜湊比對因此做行尾正規化,不構成回歸。
