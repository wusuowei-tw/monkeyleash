# F-0016 —— R2 的內容豁免:綁內容,不綁站別

- **日期**:2026-09-07
- **票**:10(`docs/tickets/framework-updates/10-sync-needs-an-r2-exemption-bound-to-content.md`)
- **狀態**:已落地(權威層)

## 脈絡

同步要寫 `.claude/portable/*.py`、`.claude/hooks/*.py`,而那些在目標 repo 是**原始碼**。
下游停在前置站(`grill` / `spec` / `tickets`)時,R2 在 pre-commit 擋下整次同步。

在這之前的處置是**紙上流程**:由人手動把 `current_stage` 改成 `implement`,
同步做完再改回去。它的代價已經量到,不是推論:

| 輪次 | 時長 |
|---|---|
| 首輪 | **57 分 38 秒** |
| 次輪 | 累計逾 **1 小時 08 分** |

**窗口期間 R2 對整個 repo 都是開的**,不只對同步的那些檔案。
而且開窗/關窗都要寫 `.dev/pipeline.json`(進版控),於是每次同步至少多兩筆
**只為了流程狀態**的 commit —— 開窗這個動作本身就把工作樹弄髒,而 sync 的第一道
檢查是「目標工作樹不乾淨就拒絕」。

## 決定

**豁免綁內容,不綁站別。**

pre-commit 判定時,若一個 staged 檔案的位元組與**上游 provenance 釘住的那個 commit**
的同路徑物件**逐位元組相同**(行尾正規化後),R2 放行。

三個性質:

- **無法自我服務。** 條件是「這個位元組序列等於上游那份」,agent 造不出一個上游
  沒有的內容 —— 偽造要先改上游。這是同一個原則的第六次出現(閘門自我修改、
  票宣告接縫、legacy 清單、R3 的 HEAD 錨點、R3 的 upstream-provenance,以及這裡)。
- **爆炸半徑是零。** 站別豁免會把整個 repo 的 R2 打開一段時間;內容豁免只放行那些
  「反正就是上游那份」的檔案,差一個位元組就回到 R2 正常判定。
- **不需要記得關。** 沒有窗口,就沒有忘記關窗這個失效模式。

## 四個實作決定,以及為什麼

### 一、釘的是 provenance 那個 commit,不是上游 HEAD

`.dev/provenance.jsonl` 裡**該 path 最後一筆**的 `upstream_commit`
（即 `status.py` 印的 waterline,票 100)。

不用上游 HEAD:HEAD 會動,而「碰巧等於上游 HEAD」的本地檔**從來沒有被同步過**。
窄的一邊出錯是「擋住做對事的人」(出口:`sync.py --certify` 補證);
寬的一邊出錯是「放行一個從未被同步過的檔案」。

**代價,寫明**:手動逐檔同步一個上游更新過的檔案時,紀錄還釘在舊 commit,仍會被擋。
**選這一案等於宣告「手動逐檔同步不是支援路徑,同步走 `sync.py`」。**

### 二、判的是 staged 的位元組,不是工作樹

`git show :<path>`。commit 要判的是**要進 commit 的那一份**。
工作樹與 index 可以不同(`git add` 之後又改了一次),而讀錯對象的失敗方式是**靜默的**
—— 兩者多數時候一樣,只有「先 add 一份乾淨的、再把工作樹改壞」時才漏。

**取不到 staged 內容時不豁免,而且不退回工作樹** —— 退回去就是判錯對象,方向是 fail-open。

> R3 現有的 `upstream-provenance` 分支讀的是**工作樹**(`gate.py` 的 `upstream_backed`
> 預設路徑)。**本 ADR 不改它**;那是登記在票 10 §設計的候選票。

### 三、只豁免 R2,不豁免 R3

理由與 ADR 0004 相同:**寫測試不需要先解鎖任何東西。**
R3 另有自己的 upstream-provenance 分支(ADR F-0014),兩者互不取代。
實作上內容豁免**不 return**,判定照樣往下落到 R3。

### 四、只做權威層,不做前哨

前哨手上只有「編輯後的整檔內容」,沒有 index;而同步工具本來就不經前哨
(`sync.py` 用 python io 直接寫檔,不走檔案工具)。
**前哨那一側維持原樣** —— 停在非可寫站時,agent 用檔案工具寫原始碼照樣被擋。

## 記帳

每一次豁免逐筆進 `.dev/gate-exemptions.jsonl`,`reason` = **`upstream-identical`**。
與既有三個值(`ticket-declared`、`gate-self-modification`、`upstream-provenance`)
都分得開 —— 混在一起對帳又會得到一個解釋不了的數字(票 08)。
欄位集合與 `outcome` 語意不變,票 49 的讀法不必改。

## 已知邊界(原地登記,不擴大)

指標檔 `~/.claude/upstream-roots.txt` 決定「上游是誰」,而它**目前不在 G1 保護清單裡**
(2026-09-07 實查:清單 65 行,`upstream` 0 次命中)。改一行就能把上游指到一個
自己控制的 repo,於是「造不出上游沒有的內容」這個性質就不再成立。

**這是宣告的守備範圍,不是本 ADR 新開的洞** —— 它與票 89 A 錨共用同一個指標檔,
出口是票 89 第二階段(git 背書的錨)。本票不擴大處置,見票 10 §三。
