# ADR 0005:R2 在兩個時點問不同的問題

- 狀態:已採納
- 日期:2026-08-09
- 觸發:F-017(全輪唯一真誤擋),以及 fail-open 稽核票的不變式測試

## 背景

閘門有兩個評估時點:寫入時的前哨、提交時的權威判定。原始設計是同一條規則兩邊照跑。

R2 的規則是「**寫入**時必須在宣告可寫的站」。pre-commit 拿同一條去問「**commit** 時在哪一站」,
結果擋掉每一次合法提交 —— 實作完成後站別本來就會往 review / idle 走。

## 決定

**R2 在兩個時點問不同的問題,且此差異為刻意宣告:**

- 寫入時:「現在這一站可以寫原始碼嗎?」擋的是還沒談清楚就開始寫。
- 提交時:「你是不是還停在**前置站**(第一個可寫站之前)就在交原始碼?」
  擋的是碼寫在該寫之前。前置站集合由站別定義檔推導,不硬編碼。

宣告寫在**規則自己的定義裡**(`gate.py` 的 `RULE_DIVERGENCE`),指向本 ADR。
不在測試裡維護豁免清單 —— 那會退化成裝飾。新增一條分歧要動規則定義並寫 ADR,是看得見的動作。

## 與兩條不變式的關係

這個差異會產生「前哨擋、權威放行」:stage=idle 或 review 時,寫原始碼被擋、提交原始碼放行。
兩格各自都是正確行為,但照字面違反「權威不得比前哨鬆」。

因此不變式分成兩條:

1. **涵蓋性**(結構,不依賴語料):每條在前哨會評估的規則,在權威層也必須被評估到。
   用規則代號出現與否判定,不比較判決。抓的是規則被刪除或跳過 —— F-017 的形狀。
2. **宣告式分歧**(行為,依賴語料):權威比前哨鬆的每一個案例,其負責規則必須帶有
   機器可讀的分時點宣告並指向 ADR。未宣告的分歧 = 缺陷。
   抓的是規則還在、被評估、但判決被放水 —— 涵蓋性單獨看不見的變體
   (可以讓某規則在提交時被呼叫然後永遠回傳放行,涵蓋性照樣全綠)。

## 後果

- R2 是目前唯一宣告分歧的規則。新增第二條要動 `RULE_DIVERGENCE` 並寫 ADR
- 語料是證據不是樣本:每發現一種新的失效形狀就加一筆,F-017 那組輸入永久保留
- 反向(權威嚴於前哨)不斷言:R4/R5 只在提交時評估是合規的,不得為了對稱把成本推進前哨
