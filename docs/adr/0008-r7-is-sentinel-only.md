# ADR 0008 — R7 只活在前哨,而且那不是放水

日期:2026-08-10
狀態:已採納

## 決策

R7(Bash 寫入 repo 一律擋,請改用 Write/Edit)**只在 agent 前哨評估**,
權威層(pre-commit)不評估它。

## 為什麼不是缺陷

其他規則管的是**檔案內容**:R1 看 spec 裡有沒有程式碼、R3 看有沒有對應測試。
那些事實在 commit 時仍然存在,所以兩層都問得到。

R7 管的是**工具呼叫**。而「這個檔案是用 Bash heredoc 寫的,還是用 Write 寫的」
在提交時**已經不存在了** —— staged diff 裡只有內容,沒有來歷。
不是權威層放水,是**那個事實在那個時點不存在**。

這與 ADR 0005(R2 在兩個時點問不同問題)是同一類:規則的對象決定它能在哪裡被評估。

## 因此:繞過前哨就沒有第二道

R7 的擋下訊息**不套** `sentinel_footer()`。那句話寫「繞過前哨仍會在 commit 被擋」,
對 R7 是假的。宣稱有第二道而實際沒有,比沒有第二道更危險 —— 你會停止注意它。
同 ADR 0007 的處置:**擋不住就明說擋不住**。

## 涵蓋性不變式看不到 R7,這件事也要明寫

不變式的實作是比較 `check()` 兩次呼叫的 trace,而 R7 不住在 `check()` 裡
(它判的是指令字串,不是路徑)。所以**那條不變式對 R7 是盲的**。
宣告寫進 `RULE_DIVERGENCE` 讓它至少是**看得見的**,但要清楚:
這裡靠的是宣告,不是機器判定。

這是不變式自己的涵蓋邊界 —— 與維度 5 同一個形狀:
**機制的涵蓋範圍本身,需要另一個維度去列舉。**

## 殘留缺口(明寫)

`python foo.py` 這種「指令本身看不出在寫」的仍然穿得過去。
不假裝擋得住 —— 那正是本規則拒絕寫解析器的同一個理由:
**半套的解析器比零涵蓋更危險,因為零涵蓋你知道它是零。**

同一條缺口也存在於 G1 第一級(純文字比對):路徑寫在腳本檔內時,
指令字串只有 `python x.py`,比對看不到它。

## 每一次用到這條殘留路徑都要記一筆

**已接受的缺口若變成日常繞路的預設路徑,風險就與當初評估時不同 ——
不是分析變了,是使用頻率變了。**

當初接受它的理由是「偶爾、且補它的代價更高」。若它變成每天都走的路,
那個「偶爾」的前提就沒了,而 ADR 不會自己知道這件事。所以要記帳。

**同一個 session 內四次,其中兩次是寫入。** 這個數字本身就是訊號。

### 重新評估的觸發條件

累積到 **10 次**,或**任何一次不是唯讀且不是驗收用途**時,回頭重新評估:
是不是該讓驗收流程有一條**明示的**受保護資源存取管道(例如只有帶特定
環境變數時才允許,而那個變數由人設),而不是繼續靠「比對看不到」這件事。

現在**不**動它 —— 四次都是驗收與稽核用途,而且真正擋住破壞的是
「覆蓋只有人能做」(ADR 0009),不是這道文字比對。但記帳從今天開始。
