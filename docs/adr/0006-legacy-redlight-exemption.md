# ADR 0006 — 既有 .py 的紅燈豁免:凍結清單,以及它擋不住什麼

日期:2026-08-09
狀態:已採納

## 決策

R3 要求「寫 xxx.py 前必須有對應測試檔 **且** 有一筆『紅燈時實作尚不存在』的紀錄」。
機制上線前就存在的 .py 無法誠實提供後者(唯一辦法是刪檔、跑紅燈、再還原 ——
那正是本規則要擋的作弊樣式)。因此設一份凍結豁免清單,只豁免**後半**。

清單的入場券是「存在於 commit `9eeacc0` 的樹裡」,由權威層規則 **R6** 驗證。

## 為什麼不是「檔案已存在就豁免」

那個條件 **agent 隨時可以自己製造**:建一個空檔,下一次寫入就成了「既有檔案」,
自動進入豁免集合 —— 規則自帶開關。凍結清單則進不去,除非改寫 git 歷史。

同一個原則的第三次出現:閘門自我修改要在 ADR 裡宣告、接縫豁免要在票裡宣告、
既有檔案要在清單裡列冊。**豁免的來源一律是前一站的產物,不得在被擋住的當下新增。**

## R6 為什麼非有不可

清單檔落在 `.agents/`(非原始碼)、副檔名 `.txt`,`is_source_path` 對它回 False。
沒有 R6 的話,被 R3 擋下的人只要在清單末尾加一行就豁免到手 ——
**完全不必碰 git 歷史**,「無法自我服務」這個選擇本設計的唯一理由當場失效。

「有一條測試會抓到」不算守住:沒有任何機制強制那條測試被跑。
判定必須跟 R4/R5 同構,進 pre-commit。

## 本機制**擋不住**什麼(誠實宣告,不是遺漏)

1. **手改證據檔**。`.dev/test-runs.jsonl` 也在非原始碼目錄底下,
   直接 append 一行 `{"result":"red","impl_exists":false,...}` 就是一張合格紅燈。
   閘門擋順手作弊(先寫實作再補測試),不擋刻意偽造證據 —— 後者靠 code review。
   不假裝擋得住,比擋不住卻宣稱擋得住安全。
2. **同名撞號**。紅燈紀錄以 `tests/test_<base>.py` 為鍵,不比對實作路徑
   (紅燈當下實作依定義不存在,無路徑可比)。因此
   `tests/test_dataflows_config.py` 的一筆紅燈,會讓任何目錄下新建的
   `dataflows_config.py` 通過 R3。這是 basename 鍵的固有限制,已另立票。
3. **排水在機制上幾乎不會發生**。移除條件是「該檔案有了合格紅燈紀錄」,
   而合格紅燈要求紀錄當下實作不存在 —— 檔案還在,就產不出那種紀錄。
   實務上只有「刪掉重寫」會觸發。**清單因此接近永久,不會自己縮減**;
   排水測試的實際作用是絆線(擋住同名撞號造成的假排水資格),不是縮減機制。
   寫在這裡是因為「債務會隨時間縮減」這句話如果沒被更正,會變成一個假承諾。
4. **85 筆裡只有 7 筆真的在生效**。其餘 78 筆沒有對應測試檔,
   本來就被 R3 的**前半**擋著,豁免後半對它們沒有意義。
   清單的實際保護面比它的長度小一個量級。

## 與 ADR 0004 的張力

`.claude/hooks/gate.py` 與 `redlight.py` 都在清單裡(它們在上線 commit 的樹裡)。
意思是**對閘門本身的修改不需要紅燈證據** —— 包含削弱閘門的修改。
ADR 0004 說「R2 豁免、R3 不豁免」,那句話現在只對 R3 的前半成立。
這不是疏漏,是清單定義的必然結果,但爆炸半徑最大的兩個檔案剛好落在裡面,
所以在此明寫。守住它們的仍然是:R2 豁免會記帳並在 stderr 出聲、以及人的審查。
