```
721cb8f  (另一視窗)  F-122 票面裡的內容快照,是一份沒有人在守的副本

```

**兩則都經過 pre-commit,兩次都綠。**
權威層看得到檔案內容,但**不檢查 friction 號唯一性** —— 這一面從來沒有守衛。

處置照新訂的慣例(後到者改號):`F-122` → `F-123`,三處引用改指,原號留痕。
**而那是人做的,不是機器抓的** —— 抓到它靠的是我為了發下一個號去查最大號,
順手看到 `uniq -d` 回了兩個 122。**下一次沒有人去查最大號時,它不會被發現。**

## 為什麼這一條**適合**進權威層(理由要寫清楚)

**這句話會被拿去論證別的檢查也該進 pre-commit,所以判準要寫死:**

| 判準 | 本條 |
|---|---|
| **零誤報** | 兩個一模一樣的號碼就是撞號。**沒有灰色地帶** |
| **零判斷** | 不需要理解那兩則寫了什麼,只數字串 |
| **極便宜** | 一次 `grep` + 一個 set,對整份 log 是毫秒級 |

### 與 stale status 檢查的對照(這格是重點)

票 53 登記的「status 行要不要也有偵測器」**不該**用同一個理由進權威層:

> **那條誤報率高,所以只能當 lint;本條沒有灰色地帶。**

stale status 要判「票面說的與實際做的一不一致」,而「實際做了什麼」
本身要推論(commit 訊息?測試?檔案存在?)—— **推論會錯,而錯在權威層等於擋住做對事的人**,
那種規則最後會被整條關掉(票 24 的判準)。

**所以:進權威層的門檻不是「重要」,是「零誤報 + 零判斷 + 便宜」。**
重要但需要判斷的東西進 lint,不進權威層。

## 範圍:**只查重複,一條檢查一件事**

- ✅ **查**:同一份 `friction-log.md` 裡有沒有兩個相同的 `## F-NNN` 標題
- ❌ **不查連號**(缺號是正常的 —— 改號會留下空洞,見發號規則第 4 節)
- ❌ **不查格式**(標題長什麼樣不是本條的事)
- ❌ **不查跨 repo**(下游用自己的前綴,`TSI-001` 與 `F-001` 不衝突)

**一條檢查一件事。** 把連號與格式併進來的話,本條就不再是零誤報的
(缺號合法、格式會演化),而**混進一個會誤報的子判定,整條的可信度就跟著它走**。

## 實作註記

- 判定對象是**標題行**(`^## F-\d+`),不是內文提及 —— 內文引用重複是正常的
- **併記段不得誤判**:本檔已有一段 `## 併記於 F-118(…)`,
  它刻意**不**寫成 `## F-118 …` 正是為了不被本檢查判成撞號。
  這一格要有測試釘住(併記形態不算撞號)
- 下游 repo 的 `friction-local.md` 用自己的前綴,**判定要吃前綴不是寫死 `F-`**
- 失敗方向:讀不到檔案 → **fail-closed 當違規**(照家規)

## 驗收(兩方向)

- **方向 A**:人工造一份含兩個 `## F-999` 的 log → 擋,且訊息**點名是哪個號、哪兩行**
- **方向 B**:現行的 `friction-log.md` → 過(`uniq -d` 現在回空,已實測);
  且 `## 併記於 F-118` 那一段**不得**被判成撞號
- **負控**:缺號(如 `F-001` 跳到 `F-003`)**不得**觸發

## 本票不含

- stale status 偵測器(票 53 候選第二面,判準不同,見上)
- 票號 / ADR 號 / event id 的唯一性 —— **同一條判準適用,但一條檢查一件事**;
  要做另開票,理由見發號規則第 4 節那句「有效期到下一次有人寫入為止」
- 自動改號 —— **後到者改號是人的判斷**(誰先誰後要看 commit 順序,
  而機器擋下的時點是 commit 之前,那時順序還沒定)
