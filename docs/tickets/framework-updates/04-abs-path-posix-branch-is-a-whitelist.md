# 04 — G1 第二級的 ABS_PATH:POSIX 分支是頂層目錄的白名單

## 事實

```
ABS_PATH 的 POSIX 分支:/(?:home|tmp|var|etc|usr|opt|mnt|root)(?![\w.\-])(?:/…)?
```

`/tmpdata/x`、`/procedures/x`、`/srv/…`、`/data/…` 這些**不在名單上的頂層目錄**,
第二級**根本看不見** —— 不是豁免放行,是沒進視野。

兩者的差別要分清楚:
- **豁免**:看到了,但決定放行(可以逐條檢視、可以要求理由)
- **沒進視野**:連判斷都沒發生(沒有東西可以檢視)

後者正是這個 repo 一路在反對的白名單形狀。

## 為什麼當初是白名單

通用的 `/[^\s…]*` 會讓 `rm .cache/x.json` 裡的 `/x.json` 被當成絕對路徑 ——
每天誤擋幾十次(已記錄的第一次驗收就抓到)。
現在有了 `(?<![\w.\-/])` 這個左邊界,那個具體誤擋已經擋掉了,
但**改成通用之後還有沒有別的誤擋沒被評估**:

- `curl https://example.com/x` —— `//example.com/x` 前面是 `:`,不在左邊界排除集裡,會被當路徑
- 指令旗標裡的斜線、正則字面量、URL 片段

## 怎樣算做完

- 決定:維持白名單並明寫,或改通用並列出所有新的誤擋面
- 若改通用:要有一組**真實指令語料**(從這個 session 的歷史抓)跑過,
  證明誤擋率可接受 —— 不是憑想像列幾個例子
- 不論哪一種,結果要寫進 G1 的 docstring:第二級看得見什麼、看不見什麼

## 暫時的狀態

維持白名單,並在測試裡**明寫這個缺口**
(`test_a_path_under_an_unlisted_root_is_invisible_to_level_two`)——
擋不住就明說擋不住,而且用一條會紅的測試把「明說」釘住。

## 更正與同刀處置(2026-08-25,票 80 裁 A 同刀)

**上一節不刪、不改字**(F-036:保留舊文加註)。以下三件是它的更正與續寫。

### (c) 上一節引用的測試名**不存在**

上一節寫的 `test_a_path_under_an_unlisted_root_is_invisible_to_level_two`,
**全庫搜尋只出現在本檔這一處** —— 也就是說,它只存在於這句引用裡。

實際的測試是 [`tests/test_g1_guard.py:358`](../../../tests/test_g1_guard.py#L358):

```
test_an_unlisted_root_should_be_visible_to_level_two
```

**而且語意相反**:舊名寫的是現況(「看不見」),實際那條斷言的是
**期望行為**(「應該看得見」),靠 `xfail(strict=True)` 表達「現在還做不到」。
`strict=True` 的作用是:哪天真的看得見了,XPASS 會**算失敗**,
逼人回來刪 marker,而不是讓一條長期紅的測試爛成噪音。

> **判準句:引用一個不存在的測試名 = 釘子看起來有兩根、實際只有一根。**
>
> 這與盤點裡那批 stale status 行是**同一族**:
> **文字宣稱沒有機器在守。**
> 差別只在載體 —— 那批是「票面說已完成而實際沒有」,
> 本則是「票面說有釘子而實際沒有那根」。
> 兩者的共同形狀是:**一句關於機制的話,自己不是機制。**
>
> 附帶一個更難看見的半:名字錯**比沒寫更難發現**。
> 沒寫的話,讀的人會去找;寫了一個名字,讀的人就以為有人找過了。
> (同 F-082 的「遮一半比完全沒遮更容易過關」。)

### (b) 缺口描述更新:兩個實測樣本現在**狀態不同**

票 80 的兩個 live probe 樣本,原本並列為「一個未解缺口」,現已分岔:

| 樣本 | 狀態 | 備註 |
|---|---|---|
| `/cygdrive/d/x` | **已補**(2026-08-25) | `ABS_PATH` 白名單加 `cygdrive` 一格 |
| `//server/share/x`(bash UNC) | **仍 open** | 裁 A 明訂不動:與 `https://` 的 `//` 撞形 |
| `\\server\share`(PS UNC) | **仍未取樣** | 無樣本,不做宣稱 |

**不得再把它們寫成一個缺口。** 並列會讓讀的人以為處置相同,
而它們現在一個關了、一個刻意留著、一個根本沒量過 —— 三種狀態。

### (a) 路線**維持白名單**,本刀不改

裁二(a)逐字:「**加一格 ≠ 改通用,本刀不改路線**」。

證據是本刀落地後 `xfail(strict=True)` 那三條(`/srv/x`、`/data/x`、`/backup/x`)
**仍是 XFAIL、沒有 XPASS**:

```
88 passed, 3 xfailed in 0.36s
```

若加 `cygdrive` 這一格順手把路線改成通用,那三條會 XPASS → strict 判失敗 →
整套紅。**它們沒紅,所以路線沒動** —— 這句話由測試撐著,不由我宣稱。

**本票因此仍 open。** 未決的仍是原本那題:維持白名單並明寫,
還是改通用 + 用**真實指令語料**證明誤擋率可接受
(上一節「怎樣算做完」三條不變)。
