## ⚠ 母體在開工當天重量,**不採用 187**

票 69 五處寫著「187 行 / 27 檔」。**那個數字在本輪任何一個 commit 上都量不出來。**

逐 commit 實測(pattern `票\s*[0-9]+`,範圍 `tests/test_*.py`):

| commit | 行 | 檔 |
|---|---|---|
| `8552830` | 186 | 26 |
| `1332a24` | 186 | 26 |
| `cdda325` | 188 | 27 |
| `e50a979` | 185 | 27 |
| `e3fff5d` | 185 | 27 |
| `665966e` | 185 | 27 |
| `e7fd1ce` | 185 | 27 |

換一種 pattern 再量(`票 [0-9]+`,強制單一空格,範圍擴到 `tests/*.py`):
`cdda325` = 189、`e50a979` = 186、`e7fd1ce` = 186。

**兩種 pattern、七個 commit,沒有一格是 187。**

> **這不是「票 69 算錯了」,是「那個數字沒有基準」。**
> 一個沒有標明基準的預測,過期之後**看起來像算錯** ——
> 而對帳的人會去找一個不存在的缺陷。同族已經記過一次(`F-109`),
> 這是它作用在**母體估算**上的版本:母體會被引用,而**引用的人不會回頭重驗**。

**所以本票的第一個動作是重量,不是動手。** 重量時要一起記下:
pattern 逐字、範圍(`tests/test_*.py` 還是 `tests/*.py`)、commit sha。
三者缺一,下一個人就會再造一個 187 出來。

## 為什麼要修

`tests/test_source_hygiene.py` 的 H3 已經收了 `reason=` 那一半,理由逐字:

> **範圍限 `reason=`,不是整個 `tests/`。** 這個 repo 的 `tests/` 底下有
> 一百多行裸票號寫在 docstring 與註解裡,判準對它們一樣成立,而那是一次
> 獨立的掃除。`reason` 先做的理由是**它是唯一會離開這個 repo 的那一種**:
> docstring 的讀者在這個 repo 裡,`reason` 的讀者不在。

**「先做」不等於「另一半不用做」。** 而另一半的讀者確實在這個 repo 裡 ——
所以本票的緊迫性比 H3 低,**但它的量體比 H3 大兩個數量級**(197 處 vs 2 處)。

真正的成本不在「讀的人找不到票」,在**命名空間**:
裸「票 04」在 `.scratch/<feature>/issues/` 這個命名空間裡不是唯一的。
量化、影音各有自己的票 04,而測試檔會被讀、被引用、被複製。

## 這不是機械替換 —— 兩個理由

1. **同 repo 與跨 repo 的寫法不同。**
   同 repo:`framework-updates/04`。跨 repo:`agent-gates framework-updates/04`。
   而分辨一處裸票號指的是哪一個,**要讀上下文** —— 靜態替換做不到。
2. **改完沒有東西守著。**
   H3 的枚舉只走 `ast.walk` 找 `kw.arg == "reason"` 的字串常數,
   docstring 與註解在它的視野外。

   要補上守衛的話有兩條路,**兩條都有代價,動工時要裁**:

   | | 做法 | 代價 |
   |---|---|---|
   | 甲 | 把 H3 擴到 docstring / 註解 | 它掃的是**下游自己的**測試檔,而那些檔上游沒看過 —— 與 `test_source_hygiene.py` 標記表釘子撞同一個問題(擴大範圍 = 把上游判準加到下游自己的檔案上) |
   | 乙 | 接受它是一次性掃除 | 掃完的第二天就開始重新累積,而**沒有東西會說它又髒了** |

   > 甲的前提是「哪些文字是框架擁有的」有答案,而那一格是**票 53**。
   > 所以本票與票 53 有相依:**乙可以現在做,甲要等票 53。**

## 切法提案(動工時可改,但改要有理由)

**按檔切,不按票號切。**

按票號切會產生「同一個檔案被三刀各改幾行」的形狀 —— 而修的時候人就在那個檔案裡,
**「我剛剛看過這個檔案」感覺像是查過了**,於是同檔的其餘幾處會被跳過(`F-085`)。

| 刀 | 範圍 | 為什麼 |
|---|---|---|
| 1 | `tests/test_gate.py`(44 行,24%) | 單檔一刀。量體最大,而且它是規則本體的測試 —— 引用密度最高、跨 repo 引用最可能出現在這裡 |
| 2 | `tests/test_bash_write.py` + `tests/test_shadow_review.py` + `tests/test_user_layer.py`(60 行) | 次三大,合計 32% |
| 3 | 其餘 8–9 檔 | 每檔 ≤10 行 |
| 4(視情況) | 尾數與 `conftest.py` | 若第 3 刀太大再切 |

**每一刀的驗收都是「這一檔的裸票號歸零」**,不是「總數下降」——
總數下降對得起進度,對不起 `F-085`。
