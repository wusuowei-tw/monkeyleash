## 為什麼不記原文(裁決給定的理由,展開)

> 原文含路徑與個資,會讓 `shadow-log` 變成新的洩漏面,
> 而它已經是備份與 G1 的保護對象。

三件各自獨立的事實,合起來讓「記原文」變成不划算:

1. **指令原文含路徑**,而路徑含使用者名、專案名、有時是真實資料夾名 ——
   F-082 / F-085 那一族(**已經推上遠端的真實資料夾名**)正是這個形狀。
2. **`shadow-log.jsonl` 不進版控**(實測:`git ls-files .dev` 只有 5 個檔,
   不含它),所以它的存續靠週級人工備份 —— **備份會被複製到別的地方**,
   而複製會讓洩漏面跟著擴散。
3. **它是 G1 的保護對象**,也就是一個「不該被輕易改動」的檔案 ——
   往這種檔案裡塞更多敏感內容,等於提高它自己的處置成本。

> **判準:一個檔案越難刪改,往裡面寫東西就越要保守。**

## 要記什麼

| 欄位 | 內容 | 為什麼 |
|---|---|---|
| `cmd_sha256` | 指令原文的 sha256 | **同一條指令再出現時對得起來**,而雜湊本身不洩漏內容 |
| `cmd_head` | 前 N 字(**N 待定**) | 讓人看得出「這是哪一類指令」(`python -c`、`git commit`、`printf`) |
| `cmd_len` | 原文長度 | 前 N 字被截斷時,知道截掉了多少 |

### 設計時要先答的

1. **N 是多少?** 太短分不出類別,太長就是變相記原文。
   **判準不是「多少字夠用」,是「多少字之內不會出現路徑」** ——
   而 `cd "c:/Users/…"` 這種指令**第一個字就是路徑**。
   ⇒ **可能需要的是「前 N 字**再過一次 `leak_scan` 的遮罩**」,而不是純截斷。**
2. **`cmd_head` 要不要過現有的遮罩管線?** `leak_scan.py` 已有 pattern 清單。
   複用它是對的 —— **不要寫第二份遮罩**(兩份會漂移,而漂移的那天沒有人發現)。
3. **雜湊要不要加鹽?** 不加:同一條指令在不同 repo 要對得起來。
   加了就只能在同一個 repo 內比對。**傾向不加**,因為它不是密碼、是指紋。
4. **舊紀錄怎麼辦?** 新欄位缺席時,`shadow_review` 不得當成錯誤 ——
   否則本票一落地,現有 222 筆全部讀不動。**向後相容是硬需求**,
   而它需要一條測試(舊格式紀錄仍可讀)。
5. **`gate.py` 的哪一層有指令?** R7 是 Bash hook,拿得到 `tool_input.command`;
   而 R1–R6 的觸發物是**檔案寫入**不是指令 —— 那些紀錄要記什麼?
   **不要為了欄位齊整而編造一個「指令」** ——
   沒有的就是沒有,欄位缺席比欄位填「N/A」誠實。

## 已知的連帶

- **`shadow_review` 的 `record_id` 會改變。** 它是「除 `classification` 外全欄位」
  的雜湊(票 64),所以加欄位 = 舊紀錄與新紀錄的身分算法涵蓋不同欄位。
  **舊紀錄的身分不會變**(它們沒有新欄位),但這件事要有測試釘住,
  否則已發出去的套用卡會在某天指不到東西。
- 觀測動作會推高日誌筆數(F-070),而本票會讓每一筆變長 ——
  檔案成長速度變快,**而它靠週級人工備份**。

## 落地(2026-08-19)—— **設計與立案時不同,差在 `cmd_head`**

立案時寫的是 `cmd_head`(前 N 字)+ 偵察題 ①「N 是多少」與 ②「要不要過既有遮罩」。
**動工時兩題都答成了「不要那個欄位」。**

### 為什麼放棄 `cmd_head`

偵察題 ② 的答案是**做不到而且不該做**:

```
$ grep -n "^import\|^from" .claude/hooks/gate.py
ast / datetime / io / json / os / re / subprocess / sys / time      ← 全部標準庫
```

`gate.py` **只 import 標準庫**,不吃 `.claude/portable/`。而 `leak_scan.scan()` /
`scanner.scan_paths()` 的介面吃的是**檔案路徑**,沒有字串層的遮罩 API。
所以「複用既有遮罩」要嘛在 hook 裡加跨目錄相依(**import 失敗會讓閘門整支壞掉**),
要嘛自己寫第二份遮罩 —— **而票面自己寫過「不要寫第二份,兩份會漂移」**。

偵察題 ① 因此也失去意義:`N` 不論多少都不安全,因為
**`cd "c:/…" ` 的第一個字就是路徑**(票面自己舉的例子)。

### 改成:**枚舉動詞,認不得就不照抄**

```python
CMD_VERB_UNKNOWN = "<其他>"
CMD_VERBS = frozenset(...)          # python / git / cat / printf / Set-Content …

def command_verb(command):
    head = (command or "").strip().split()[0].lower()
    return head if head in CMD_VERBS else CMD_VERB_UNKNOWN
```

它達成 `cmd_head` 想達成的事(**看得出這是哪一類指令**),而**由構造保證不洩漏**:
輸出的值域是一個有限集合,裡面沒有任何來自使用者環境的字串。

> **這不是退回白名單。** CLAUDE.md 那條講的是**閘門**(列出不管的、其餘全擋);
> 這裡是**輸出的遮罩**,而遮罩的 fail-closed 方向是**少講** ——
> 所以 deny-by-default 才是對的方向,同 `leak-patterns.txt` 檔頭自己註明的
> 「方向與其他清單不同」。
> **漏一個動詞的代價是少一格資訊;多印一個的代價是洩漏。**

### 落地欄位

| 欄位 | 值 | 給不出指令時 |
|---|---|---|
| `cmd_sha256` | 指令原文的 sha256(**不加鹽** —— 跨 repo 要對得起來,它是指紋不是密碼) | **欄位缺席** |
| `cmd_verb` | 枚舉動詞或 `<其他>` | **欄位缺席** |
| `cmd_len` | 原文長度 | **欄位缺席** |

偵察題 ⑤(R1–R6 沒有指令)照票面的判準做:**欄位缺席,不填 `N/A`** ——
`N/A` 是一個值,而值會被統計、被比對、被當成「有記錄」。

### 13 條測試,其中三條是釘子

- `test_the_r7_call_site_passes_the_command` —— **直接讀原始碼**斷言呼叫點真的把
  `command` 傳下去。少了它就是票 56 那個形狀:**機制做好了但沒有東西保證它被走到**。
- `test_the_old_call_signature_still_works` + `test_records_without_a_command_omit_the_fields`
  —— 現有兩個呼叫點不傳 `command`,向後相容是硬需求。
- **`TestPOldRecordIdentitiesMustNotDrift`(在 `test_shadow_review.py`)** ——
  釘一個**黃金雜湊** `af5d40aa…`:舊形態紀錄的 `record_id` 不得改變。
  配一條負控(加了新欄位的紀錄**必須**算出不同 id),否則
  「`record_id` 忽略未知欄位」的實作會讓黃金那條永遠綠。
  > **已發出去的套用卡指的是身分。身分漂了,卡片就指不到東西 ——
  > 而那不會報錯,它只會變成「這張卡的 id 對不到任何一筆」。**

### 動工中被自己的閘門擋了一次(值得記)

第一版的 fixture 寫了一個「看起來像真的」的假路徑
(`cd "c:/Users/…/OneDrive/…" && cat token.txt`),
`tests/test_leak_scan.py::test_the_shipped_tree_is_clean` 當場轉紅 ——
它**命中了洩漏偵測的個人 pattern**。

```
[洩漏偵測] 這些檔案含個人身分或機密,擋下 commit:
  tests/test_shadow.py:279
     命中 pattern:個人 pattern #17(不顯示內容)
```

> **寫一個逼真的假機密,本身就是洩漏鄰近行為** ——
> 而「它是假的」這件事只有寫的人知道,掃描器不知道,讀的人也不知道。

改用合成 token(`ZZFIXTURE…`)。斷言強度不變:要證明的是「這些字不出現在輸出裡」,
而那與它們像不像真的無關。

**附帶的不對稱值得記下來**:個人 pattern 清單**不進版控、不上 CI**,
所以那一版 fixture **在 CI 上會全綠,只在裝了個人清單的機器上紅** ——
與票 62 的方向**正好相反**(那個是本機看不到、只有 CI 看得到)。
**兩個方向的盲區都存在,而它們不會互相補上。**
