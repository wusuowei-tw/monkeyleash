# 73 — `SKIP_BASENAMES` 類別豁免連內容一起免掃

**狀態**:**candidate**(立案,不動工)
**立案**:2026-08-23,開源偵察四裁之 4
**來源**:票 72(全史掃描的「未內容掃描」清單)

## 現象

`leak_scan.py` 的 `SKIP_BASENAMES = (".gitignore",)` 是**類別豁免**:任何 `.gitignore` 不進內容比對。
全史審查實測:`.gitignore` 歷史 4 版 + 現樹**從未經過內容掃描**,
而其中 1 版與現樹含下游 repo 真名(裁決 2 已定性為可公開,**所以這次沒事**)。

## 為什麼是缺口不是設計

F-062 的豁免理由是:`.gitignore` 列的是秘密檔的**形狀**(星號 + 憑證副檔名),掃它必然被憑證副檔名 pattern 假陽。
(本票第一版把那個副檔名寫成字面,**被 pre-commit 擋下** —— 它自己示範了同一條假陽;改描述式,不加豁免。)
**那個理由只管憑證副檔名那一組 pattern**,對個人 pattern、通用金鑰 pattern 不成立 ——
`.gitignore` 裡寫一行 `# 備份在 OneDrive/<真實資料夾>/` 會原樣穿過。
豁免的粒度(整檔)大於理由的粒度(一組 pattern)。與 CLAUDE.md「收了一個入口,回頭問同類入口」同族。

## 候選處置(不裁)

- A:豁免改綁 **pattern 組**而非檔案 —— `.gitignore` 只對「憑證副檔名」組免掃,其餘組照掃
  (`scanner.RuleGroup` 本來就帶 `exempt`,機制現成)
- B:維持類別豁免,但 `--review` 模式對 `SKIP_BASENAMES` 檔做一次性內容掃描並進報告
- 兩者不互斥;A 管 pre-commit、B 管公開審查

## 驗收要有的反控

`.gitignore` 裡放一行含個人 pattern 真樣本形狀(合成) → 擋;
放一行「星號 + 憑證副檔名」的 ignore 形狀 → 不擋(F-062 的假陽不得回來)。
