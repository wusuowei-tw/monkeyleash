## 第一則(預定 F-092)—— 寫報告的人是下一個洩漏者:F-067 首次實際攔截

**F-067 至今只活在散文裡。這是它第一次真的攔到人,而攔到的是 agent。**

### 現場

下游影音的票 20 收尾,agent 在票面的「未竟 / 待裁」段落**轉錄了洩漏偵測的命中內容**,
pre-commit 當場擋下該票檔自己。修掉之後**第二次又被擋** —— 這次是在一張
「未內容掃描檔案逐一定性」的表格裡引用了被掃描檔案的樣式字面,命中通用 pattern。

**兩次都是同一個動作**:為了把發現寫清楚,把發現的內容抄了一份。
第一次命中個人 pattern,第二次命中通用 pattern —— **兩種 pattern 都會咬報告**,
不是只有個人那份。

字面本則不轉錄(理由就是本則自己)。

### 為什麼這是 F-067 而不是新的一則

F-067 說的是:**個人 pattern 的命中內容印出來等於再洩一次**,
因為報告的外流面比原檔更大(log、CI 畫面、對話紀錄都算)。
這裡發生的正是它,只是主體從「掃描器的輸出」換成了「人/agent 寫的報告」——
**同一條規則的第二個出口**。所以本則掛在 F-067 底下當實例,不另立新形狀。

### 裂縫(**只記,先不加機制**)

**目前擋得住的只有「寫進檔案」那條路。**

| 路徑 | 有沒有閘門 |
|---|---|
| agent 把命中內容寫進票面 / friction / 報告檔 | **有** —— pre-commit 的 leak_scan 掃 staged |
| agent 在對話裡把命中內容講出來 | **沒有** |
| 人把命中內容貼進對話,再轉給另一個 agent | **沒有** |

第三條是實際存在的路徑(下游那次是 VS → Jeff → Claude)。
**閘門只看得到檔案**,而對話從不落地成檔案,所以那條路上什麼都沒有。

**不加機制的理由**(裁決者 2026-08-16):
把偵測塞進對話層,要嘛攔截所有輸出(代價與誤擋面都極大、且會被關掉),
要嘛只做半套 —— 而**半套的解析器比零涵蓋更危險**(R7 拒絕解析指令字串的同一條理由:
零涵蓋你知道它是零)。目前**先寫下來讓它看得見**,不假裝守得住。

### 可複用

- **寫發現的時候,你正握著那個發現的內容。** 洩漏偵測擋得住 commit,
  擋不住你把它講出去。
- **要描述形狀,不要轉錄字面。** 形狀足以讓人找到現場(檔名 + 行號),
  字面只多給了一份拷貝。
- **通用 pattern 一樣會咬報告** —— 別以為只有個人清單那份要小心。

## 第二則(預定 F-093)—— `git add -A` 掃走沒看過的異動,而 commit 看起來仍然乾淨

### 現場

下游影音的票 20 收尾,agent 用 `git add -A` 提交自己的三個異動,
**連帶把裁決者同時間改好、尚未提交的 `.dev/pipeline.json` 一起掃了進去**。

那次**內容剛好是對的**(值正是裁決者要寫的),所以沒有造成損害。
**危險不在這次,在下次。**

### 形狀

`git add -A` 是「把工作區的一切放進索引」,而 agent 對「一切」裡有什麼
**沒有任何知識** —— 它只知道自己改了哪幾個檔。差集就是:

- 另一個人同時在改的東西
- 前一個工序留下、還沒有人決定要不要留的東西
- 工具在背景產生的東西

**而提交完之後,commit 看起來完全正常。** 訊息是 agent 寫的、內容是 agent 的、
`git log` 一行漂亮的摘要 —— 沒有任何東西會說「這裡面有一個你沒看過的檔案」。

**與上游票 15 同型**:那次是 `.githooks/pre-commit` 從三層掛載降成只剩一層,
而整個過程「看起來還像一次成功的更新」。同一個形狀:
**出錯的方式是靜默的,而且外觀與成功一致。**

### 處置(**只記,先不加機制**)

**改習慣,不加規則**:提交一律**逐路徑指定**,不用 `git add -A` / `git add .`。
agent 只能提交它自己知道自己改過的路徑。

**為什麼不加機制**:要擋得住得知道「哪些異動是這個 agent 做的」,
而那個知識**在 git 裡不存在** —— 索引不記錄是誰放進去的。
做得出來的只有「禁用 `git add -A`」這種字串比對,而繞過它只要換個寫法
(`git add .`、`git add :/`、先 `add` 再 `add`),
**半套的攔截會讓人以為這件事被守住了**。同 R7 的判準。

### 可複用

- **「我沒有改它」不等於「我沒有碰它」。** 提交是一種碰。
- 判斷一個提交動作安不安全,問的不是「我改了什麼」,
  而是**「這條指令會帶走什麼」** —— 兩者的差集就是風險。
- **作者身分要與實際做事者一致。** 這與 provenance、與六站要的是同一件事:
  帳面上的責任人要是真的那個人。(下游那次的處置就是把它拆開重提:
  `reset --soft` → 移出該檔 → agent 只提自己的三個異動。
  三題查證都便宜才拆:是 HEAD、沒推、零引用。)

## 第三則(實得 F-094)—— 前哨跨界時讀的是來源視窗的 repo 狀態

**查核 `472b396` 的副產物。** 完整內容見 friction-log 的 F-094,這裡只記票根。

- hook 掛載走 `$CLAUDE_PROJECT_DIR`,而 `gate.py` 的 `ROOT` 由 `__file__`
  往上三層算(`gate.py:26`)—— 兩者相乘,跨視窗寫入時判定用的是
  **來源視窗**的 `pipeline.json` / 站別定義 / legacy 名單 / provenance。
- 實測:agent-gates 的 `gate.py` 回 `('implement','44')`,
  影音的回 `('review','20')`。
- `rel()` 產出帶 `../` 的跨界相對路徑,而 `is_source_path()` 對它回 `True`,
  於是 R2 拿錯的 repo 的站別判目標 repo 的檔案。**兩個方向都會錯。**
- 權威層(`git rev-parse --show-toplevel`)**是對的** ——
  所以 `472b396` 是**被權威層接住的,不是被守出來的**。
- 與 ADR 0008 是**鏡像**:0008 說「繞過前哨就沒有第二道」,
  本則是「前哨判錯 repo 而權威層接住」。
