而票 49 第一階段(R7 攔截帳本)整個建立在「上游全程 enforce」這個前提上:

### 一之二、🔴 硬條件:必須綁定「這是上游」,**不得對下游生效**

`shadow.json` 存在是**影子模式的合法狀態** —— ADR 0012 就是為此而設計的。
一條「一律擋」的規則會在三天後擋到每一個開了影子的下游。

**⚠ 反控缺一不可**:一個模擬下游的 repo 建了 `shadow.json`,**不得被擋**。

### 4-7 🔴 CI 紅了一條 —— **本機恆綠的那一條**(2026-08-28,`F-142`)

推上去之後 CI 在兩刀上都紅。照 `F-111`(「CI 紅了」分兩種,而整體顏色分不出是哪一種),
先問**哪一步紅的**:

```

本機(Windows)  1106 passed, 3 skipped, 3 xfailed
CI  (Linux)     1 failed, 1095 passed, 1 deselected, 3 xfailed
FAILED TestUpstreamMustNotBeInShadowMode::
       test_the_anchor_is_compared_after_normalising_separators_and_case
```

**紅的是我的測試,不是實作。** 那條斷言把分隔符與大小寫併成一句,
而 `.upper()` 那一半**只在 Windows 成立**(`os.path.normcase` 在 POSIX 是恆等函式)。

> **實作是對的,而且它對得正是因為它沒有無條件折疊** ——
> POSIX 分大小寫,無條件折疊會讓一個只差大小寫的 **Linux 下游被誤判成上游**。
> **測試要求的那個行為才是缺陷。**

**修法:拆成三條**(不是改成「跨平台都折疊」):

| 拆出來的 | 斷言 |
|---|---|
| 分隔符 | 兩平台都該過。**並註明它在 POSIX 上恆真**,不要讀成「都驗過了」 |
| 大小寫 | **逐平台寫死語意**:NT 必須比中,POSIX 必須**不**比中 |
| 平台無關的負控 | 真的不同的路徑,任何平台都不得比中 —— **少了它,一個「永遠回 True」的實作在兩邊都會綠** |

**不用 `os.path.normcase` 算期望值** —— 那是拿衍生欄位驗它的來源(`F-114`),恆真。

修後本機 `13 passed`(原 11 條 + 拆出的 2 條)。
