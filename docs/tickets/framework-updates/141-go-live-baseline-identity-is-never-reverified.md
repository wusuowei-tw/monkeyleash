## 命題

**`legacy_no_redlight()` 與 `read_go_live()` 都從同一份清單檔讀,
而清單第一行那個 go-live sha 的【身分】,在本輪已檢查的閘門路徑裡沒有被持續驗證。**

閘門只驗**那個 commit 存在**(`gate.py:1804`,`git cat-file -e <sha>^{commit}`),
**不驗它是不是核准的上線基準**。

> **`install.py` 在安裝時寫入當時 HEAD;本輪已檢查的閘門路徑
> 未找到持續驗證核准基準身分的機制。**

```python
    _, go_live = run(["git", "rev-parse", "HEAD"], target)
```

### 隔離 repo 的建構方式

一個臨時 git repo(repo 外,不碰真 repo),兩個 commit:

| 物件 | 內容 |
|---|---|
| **SHA1** —— 真正的上線基準 | 只含 `pkg/base.py`,**沒有**目標模組 |
| **SHA2** —— 較晚的 commit | `pkg/base.py` + **目標模組** `macro_audit/model.py` |
| **index 清單** | `# go-live: SHA1` + `pkg/base.py`(原本的合法清單) |
| **工作樹清單** | `# go-live: SHA2` + `pkg/base.py` + `macro_audit/model.py` |

`gate.py` / `redlight.py` / `pipeline-stages.yaml` 取自 HEAD,放進
`<repo>/.claude/hooks/` 與 `<repo>/.agents/` ⇒ `ROOT` 由 `__file__` 自然算出、**未 patch**;
`LEGACY_LIST` **未 patch**;站別用實檔 `.dev/pipeline.json`(implement / 133);
**唯一的 patch** 是 `UPSTREAM_ROOTS` 指向臨時 repo 內不存在的路徑。

排除的其他豁免:research(目標在 `macro_audit/`)、純套件標記(檔名 `model.py`)、
票宣告(無 `.scratch/`)、帳本回查與 provenance(兩檔皆不存在)、R8(內容 `x = 1`)。

## 成因定性

**`install.py` 在安裝時寫入當時 HEAD;本輪已檢查的閘門路徑
未找到持續驗證核准基準身分的機制。自動寫入不等於人工核准,
G1 保護清單仍未查。**

之後每一次判定都把清單第一行當成**前提**:
`read_go_live()` 取它、`check_legacy_list()` 用它當基準去驗每一筆條目 ——
**而攻擊改的正是那個前提本身。**

## 修法選項(**原始提案,未採納**)

> **以下三段為第四輪報告 §1.5 的原文,逐字複製,未改寫。**
> 標「原始提案,未採納」——**本輪不選基準錨定修法。**
> 原文之後另加兩條限制(見〈原文之後的限制〉),**限制不在原文內**。

| 選項 | 內容 | 代價 | 保證 |
|---|---|---|---|
| **甲** | **D 只做條目驗證**,並把宣稱縮成「擋條目造假」 | 最小;**基準造假這條路留著** | ④ 那一格擋得住,③ 擋不住 |
| **乙** | **D + 基準錨定**:go-live sha 另外釘一個**不可自助**的來源(例如 `# go-live` 必須是 HEAD 的祖先、或釘進一個 agent 改不動的位置) | 要回答「錨放哪裡才不可自助」——**這正是票 89 第二階段(git 背書的錨)的同一個問題**;跨 repo 可攜性要重新想(sha 綁產生它的 repo) | ③ 與 ④ 都擋得住 |
| **丙** | **不做 D**,改走同快照方案(B / E),並接受它們也不驗基準 | 不解基準問題,但至少 R3 與 R6 判同一份 | ③ 在**提交時點**會被 R6 那一份(index)擋;工作樹那一份不再有話語權 |

> **甲 不是「沒有價值」** —— ④ 那一格(條目造假、基準沒動)是**最日常的形狀**,
> 而現行工作樹路徑對它**完全沒有防護**。
> **但甲落地之後,不得把 D 寫成「補上了 ADR 0006 的入場券驗證」** ——
> ADR 0006 要防的是「**被 R3 擋下的人在清單末尾加一行就豁免到手**」,
> 而**加一行 + 換一個 sha 仍然到手**。

### 原文之後的限制(**2026-09-15 裁決加註,不在原文內**)

| # | 限制 |
|---|---|
| **一** | **「HEAD 祖先關係」本身不足以證明核准基準身分。** 一個**較晚、且含目標模組**的 commit **也可能是 HEAD 的祖先** ⇒ 乙案括號裡舉的那個例子(「`# go-live` 必須是 HEAD 的祖先」)**擋不住本票的攻擊形狀**。錨要錨的是**身分**,不是**可達性**。 |
| **二** | **同快照方案(丙)處理的是本輪量到的 index / 工作樹分歧。** 若 **index 那一份的 SHA 與條目【一起】被更換**,**不得據此宣稱仍會攔截** —— 那個組合**本輪沒有量過**。 |

⇒ **本輪不選修法。** 三個選項都還沒有可用的錨。
