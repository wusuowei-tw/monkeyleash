## 為什麼不等 F-050 實例

F-050 的「補擷取要有實際誤擋當證據」講的是**誤擋面** —— 誤擋看得見、
會被抱怨、等得到實例。漏擋不產生抱怨,等實例 = 永遠等下去。
本票的證據是主動探針(量化 F/G 兩案),不是抱怨 —— 這正是漏擋面
唯一等得到的那種證據。裁 4 已明確排除 F-050 適用性,本票不再重議。

## 三面,成本與確定度都不同,不得綁成一刀

- **cygdrive(`/cygdrive/d/x`)**:`_POSIX_DRIVE_MOUNTS` 共表加 `"cygdrive"`
  一格 —— 構造已為它留位(表旁註解:「加一個掛載點(如日後 cygdrive
  有實例)兩側同時獲得」),展開(`variants`)與收斂(`_canon`)同時獲得,
  雙向耦合測試(`TestVariantsAndCanonCoverTheSameForms`)自動涵蓋。近零成本。
- **bash 寫法 UNC(`//server/share/x`)**:要動 `ABS_PATH` 擷取,有設計風險:
  `//` 開頭與 URL(`https://…` 的 `//`)、協定相對寫法撞形;
  且 proj 通常是磁碟形式,UNC 幾乎恆判專案外 → 誤差偏擋方向,
  要對著票 79 裁決條件 b(路徑面不縮)想清楚再動。
- **PS 寫法 UNC(`\\server\share`)**:**未取樣**(量化明列無樣本,不做宣稱)。
  動手前先補樣本判現況,不隨 bash 側順手帶 —— 「想不到不等於不存在」
  的反面也成立:沒看過的現況不能當已知。

## 裁 A 落地(2026-08-25)—— **本刀只收 cygdrive,UNC 兩面未動仍 open**

**票號動過不等於整票收完。** 本票三面照票面「不得綁成一刀」各自結算:

| 面 | 狀態 |
|---|---|
| cygdrive(`/cygdrive/d/x`) | **已補,已擋**(本節) |
| bash 寫法 UNC(`//server/share/x`) | **仍 open** —— 裁 A 明訂不動 |
| PS 寫法 UNC(`\\server\share`) | **仍未取樣** —— 不做宣稱 |

### 成本估計被實測推翻:是**兩處**,不是「共表加一格」

票面(以及開票當時的盤點回報)寫「`_POSIX_DRIVE_MOUNTS` 共表加一格 ——
構造已為它留位」,依據是該表旁的註解「加一個掛載點兩側同時獲得」。
**動工前的唯讀探針量到:**

```
ABS_PATH.findall("rm -rf /cygdrive/d/x")  ->  []
```

`/cygdrive/d/x` **根本沒被擷取**。那句註解說的「兩側」是 `_canon()`(收斂)
與 `variants()`(展開),而**擷取是第三側** —— 它住在 `ABS_PATH` 的頂層目錄
白名單裡(`home|tmp|var|etc|usr|opt|mnt|root`),**那張白名單不由該表生成**。

**那句註解沒有寫錯。** 它精確地說了「兩側」,而讀的人(開票的我)
把它讀成了整條路徑都涵蓋 —— 因為讀的人要的是結論,
而「兩側」在當下讀起來就像「兩邊都好了」。
**這是 CLAUDE.md「說『構造保證』之前,先問這個保證是從方法推出來的,
還是從這次的資料看出來的」的一個新形狀:保證是從方法推出來的、而且是真的,
但它保證的範圍比引用它的人以為的窄。**

落地因此是兩處各加一格:

1. `_POSIX_DRIVE_MOUNTS = ("mnt", "cygdrive")` —— 收斂/展開兩側自動獲得
2. `ABS_PATH` 頂層目錄白名單加 `cygdrive` —— 擷取側

**白名單路線未改**(裁二(a)):票 04 的 `xfail(strict=True)`
(`/srv`、`/data`、`/backup`)落地後仍是 **XFAIL**,證明「加一格 ≠ 改通用」。

### 新增的機制條 —— 本刀真正的產出

`TestCygdriveIsExtractedAndBlocked::test_every_mount_in_the_table_is_extractable`

它把「表與擷取白名單要同步」從**註解**變成**紅燈**。
既有的雙向耦合測試(`test_every_form_canon_recognizes_is_also_expanded`)
**在 cygdrive 這一發是綠的** —— 它從表推導,表加了格之後兩側自動跟上,
唯獨擷取側不跟,而擷取側不在它的視野裡。
**一條從表推導的測試,只保證表推導得到的那幾側。**

落地時**故意先只改表、不改白名單**,讓新條自己叫一次(正對照,票 47 紀律):

```
AssertionError: 表裡有 'cygdrive',但 ABS_PATH 擷取不到:[]
```

## 同族半徑(2026-08-25,唯讀探針,不改碼)

**由來**:cygdrive/UNC 的根因是「路徑形式沒被收斂到同一種表示法」。
照 F-083(收了一個入口就問同類入口在哪),對三處已被點名、
但只有「半二」的同族判定各發一條探針,問同一個問題:
**換一種路徑寫法(磁碟機形式 / 大小寫 / 分隔符 / 前後綴邊界 / `..` 穿越),
它還認得出來嗎?**

規格:全程唯讀;只呼叫純讀函式(`is_source_path` / `_is_scratch` /
`SKIP_DIRS` 成員判定),**不呼叫 `check()`**(那條會寫
`gate-exemptions.jsonl`);不跑 pytest;探針落 repo 外。
**構造上不產生紀錄,不是事後標注** —— 事後標注依賴記性。
**每條自帶反控**:恆回 True 的判定與有效的判定在輸出上長得一樣。

### ③ `g1_guard.py` 的 `_SCRATCH_PREFIXES` —— **乾淨,全部安全方向**

反控成立(`/home/u/data` → False、`/tmp/x` → True,分得出來)。

| 變體 | 結果 | 方向 |
|---|---|---|
| `/tmpdata/x`、`/tmp_backup/x` | 不放行 | ✅ 邊界對 |
| `/tmp/../home/u/data` | 不放行 | ✅ `..` 先 normpath |
| `c:/…/appdata/local/temporary/x` | 不放行 | ✅ 片段帶邊界 |
| `c:/…/appdata/local/temp/../../../../windows/system32` | 不放行 | ✅ |
| `//tmp/x`、`/TMP/x`、`\tmp\x`(**違約輸入**) | 不放行 | ✅ 安全方向 |

最後一列值得記:這三種是**違反函式契約**的輸入(docstring 要求先小寫 +
斜線正規化),而它們**全部倒向誤擋**。契約違約時往安全方向倒,
是該函式 docstring 明寫的設計,**這次實測它做到了**。

> **「當時是好的」本身就是日後的參照物** —— 所以照裁決寫下來。
> 這一格的價值不在今天,在下次有人動 `_is_scratch` 時能對照。

### ① 量化 `scripts/backup_evidence.py` 的 `SKIP_DIRS` —— **乾淨,全部安全方向**

用法(該檔 307 行)是 `if name in SKIP_DIRS: continue`,對 `listdir` 回的
**單一目錄名**做字典成員判定 —— 所以「路徑寫法」在這裡收斂成「名稱寫法」。
反控成立(`agent-gates` → False、`.git` → True)。

`.GIT` / `.Git` / `.git/` / `.git.` / `.git `(後兩者是 Windows 會剝掉的尾綴)
**全部判成「不跳過」= 安全方向**:多走訪一個目錄,代價是慢,不是漏。
邊界也對:`.github`、`node_modules2` 都不誤中。
全表 9 項:`.git`、`.venv`、`__pycache__`、`data`、`database`、`logs`、
`node_modules`、`reports`、`research`。

### ② `gate.py` 的 `NON_SOURCE_DIRS` —— **⚠ 命中危險方向四筆,帶回等裁**

反控成立(`pkg/thing.py` → 要管、`docs/x.py` → 跳過)。
安全方向的三筆(`DOCS/x.py`、`Docs/x.py`、`./docs/x.py` 判成「要管」)不是問題。

**問題在反方向 —— 真原始碼可以寫成「非原始碼」的樣子:**

```
scripts/../pkg/thing.py   -> 判成非原始碼(跳過 R2/R3)
docs/../pkg/thing.py      -> 判成非原始碼
tests/../pkg/thing.py     -> 判成非原始碼
docs\..\pkg\thing.py      -> 判成非原始碼
```

成因是 `is_source_path` 只取 `r.split("/")[0]` 當 top,**沒有先 normpath**。

**這一筆是 F-086 的標準形狀**:同一份判準寫在 A 模組的註解裡,B 模組原地不動。
`_is_scratch` 的 docstring 逐字寫著 ——

> **先解 `..` 再比對。** 少了這一步,`C:/…/Temp/../../../../<目標>` 會命中片段
> → 豁免 → 放行……這與「許可前綴不能替後面那段背書」是同一條判準(F-051):
> **任何用子字串或前綴放行的地方都適用。**

而 `is_source_path` 的 docstring 自稱是「黑名單反轉後的**唯一判定點**」,
**它就是一個用前綴放行的地方**,而它沒有 normpath。
**註解不是機制 —— 寫在 `g1_guard.py` 裡的判準,不會讓 `gate.py` 變安全。**

**未取樣、不做宣稱的那一半(重要)**:本探針量的是**判定函式本身**答錯,
**沒有**證明真的有一條寫入路徑能把 `..` 形式送到這裡 ——
那要跑 `check()`,而 `check()` 會寫證據檔,違反本輪「構造上不產生紀錄」。
所以現況是:**謂詞答錯已證實,端到端可利用性未取樣。**
不寫成「有一個活的漏擋」,因為那會是拿一個沒量過的機制去描述一個量過的錯。

**帶回等裁**:要不要開票、以及要不要一併問「還有哪些地方用 `split('/')[0]`
或前綴放行而沒 normpath」。本輪不開票、不改碼(照裁決)。
