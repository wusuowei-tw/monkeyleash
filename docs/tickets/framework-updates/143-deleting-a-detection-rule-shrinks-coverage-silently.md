## 二、量測(**隔離流程;repo 外的拋棄式臨時 repo**)

### 2.0 第 0 步:先證明兩版清單真的有差

**完整清單**(2 條有效規則)· **削弱版**(拿掉打得到假秘密的那一條,
**保留**另一條有效且與測試字串無關的規則;兩版格式都合法)。

```
兩份皆完整   staged=['.claude/portable/leak-patterns.txt', 'app/config.env']
             目標被 skip=False  rc=1 = 命中(擋下)
兩份皆削弱   staged=['.claude/portable/leak-patterns.txt', 'app/config.env']
             目標被 skip=False  rc=0 = 無命中(放行)
```

⇒ 完整清單**抓得到**、削弱清單**抓不到**,且**目標確實列入掃描、未被 skip**。
(`rc` 三態分開記:**0 = 無命中放行 · 1 = 命中擋下 · 2 = 機制錯誤**。)

### 2.1 來源分歧 A / B(同一份已暫存的假秘密)

```
A:index 完整、工作樹削弱
    index 版含該條規則   : True
    工作樹版含該條規則   : False
    staged 清單          : ['.claude/portable/leak-patterns.txt', 'app/config.env']
    目標被 skip          : False
    **rc**               : 0 = 無命中(放行)

B:index 削弱、工作樹完整
    index 版含該條規則   : False
    工作樹版含該條規則   : True
    staged 清單          : ['.claude/portable/leak-patterns.txt', 'app/config.env']
    目標被 skip          : False
    **rc**               : 1 = 命中(擋下)
```

⇒ **現行 `leak_scan --staged` 用的是【工作樹】那份清單**(兩個方向都成立)。

**⚠ A 格逐字**:**index 完整、工作樹削弱 ⇒ 當次即漏掃。**
把工作樹那份削弱掉,**這一次提交的假秘密就掃不出來**。

**⚠ B 格逐字**:**index 削弱、工作樹完整 ⇒ 現行擋下;
而 index 候選原型放行(見 2.3)。**
⚠ **不得推廣成「工作樹能普遍防止同次削弱」** ——
**A 格正是反例**:工作樹被削弱時,同一次就漏。
B 擋得下來,只是因為**那一次工作樹那份恰好是完整的**。

### 2.2 延遲傳播(兩階段)

**第一階段** —— 只提交削弱清單 + 無害內容,**工作樹保留完整清單**,
**不混入任何會被完整清單抓到的假秘密**:

```
staged 清單            : ['.claude/portable/leak-patterns.txt', 'NOTES.md']
**未混入假秘密**       : True
這一次提交的掃描結果   : 0 = 無命中(放行)
工作樹清單含該條規則   : True
**HEAD 裡的清單**含該條 : False
```

**第二階段** —— 另一個臨時 clone 取得該提交:

```
clone 的工作樹清單內容 :
    | # 測試用通用清單(削弱版:少了雲端金鑰那一條)
    | ghp_[0-9A-Za-z]{36}
含該條規則              : False

clone 端暫存同一個假秘密後:
    staged 清單 : ['app/config.env']
    **掃描結果** : 0 = 無命中(放行)
```

⚠ **未掛真正的 hook** ⇒ 本節**只證明【傳播與掃描效果】**,
**不宣稱完整攻擊鏈已通過所有守衛**。
**其他守衛各自的檢查結果另列在 §三**(測試、CI、manifest、G1)。

### 2.3 index 候選原型(**只在拋棄式副本替換來源;尚未實作**)

**替換位置**:`leak_scan._read_patterns` 對 `PATTERNS_FILE` 的那一次呼叫,
改讀 `git show :.claude/portable/leak-patterns.txt` 的內容。
**正式碼一個字未動。**

| 情境:index 削弱 · 工作樹完整 · 假秘密已暫存 | rc |
|---|---|
| 現行(讀工作樹) | **1 = 擋下** |
| **候選原型(讀 index)** | **0 = 放行** |

⇒ **改讀 index 之後,削弱清單會在「引入它的那一次 commit」就生效。**
**兩個來源各有已量到的失效情境** ——
這正是票 133 第 15 格**裁決不改來源**的依據。

## 三附、清單的兩重身分(量到的)

| 問題 | 答案 |
|---|---|
| 它是**被判的東西**嗎? | **是** —— 它被追蹤、會隨這次 commit 進歷史 |
| 它是**用來判別人的控制資料**嗎? | **是** —— `load_patterns()` 用它決定別的檔案擋不擋 |

- **作為控制資料**:現行讀**工作樹** ⇒ 這次提交帶進來的削弱版**這一次不生效**,
  但**下一個人拿到的就是它**(§2.2)。
- **作為被判對象**:它自己**被 `SELF_PATHS` 豁免**(`should_skip` = True),
  所以**掃描端永遠不會檢查它的內容**。

⚠ **不宣稱「只有第 15 格涉及控制資料」** —— #8/#9(站別定義)、#10(legacy 清單)、
#12(帳本)、#13(provenance)都是控制資料。
**本票的特殊處是「偵測規則清單本身可以被削弱」**,
而**削弱之後沒有任何一層會因為『規則變少了』而出聲**。
