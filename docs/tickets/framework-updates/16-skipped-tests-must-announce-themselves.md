# 16 — 測試從 pass 轉 skip 沒有東西會出聲

**排程**:sync session 六步全部完成之後。不插隊。

## 現象(2026-08-13)

上游套件出現 3 個 `skipped`,先前那三條是 `passed`:

```
SKIPPED [1] tests/test_gate.py:286: 此環境無法建立 symlink
SKIPPED [1] tests/test_gate.py:294: 此環境無法建立 symlink
SKIPPED [1] tests/test_gate.py:308: 此環境無法建立 symlink
```

**我是比對前後總數才發現的。** 套件仍然「全綠」——
skip 不是失敗,summary 也不會強調它,而 CI 或人眼看到的是同一句「沒有紅」。

## 為什麼要緊

那三條測的是 **R4 的 symlink 分支**。CLAUDE.md 明說:

> 鏡像的實體形態由上游工具與檔案系統決定,不是本專案選的 ——
> 本機實測為檔案層硬連結,先前觀察過 symlink 佈局。**R4 不得假設任一形態。**

也就是說:R4 有兩個分支,而**現在只有一個被測到**,另一個靜默地沒有涵蓋。
這正是 F-033 那條的形狀(R4 只驗得出「內容不同」,驗不出「東西不見了」)
的下一層 —— 連「有沒有在驗」這件事本身都沒有訊號。

skip 的訊息本身是**誠實**的(它寫了原因),缺的是**轉換**的訊號:
「一直都是 skip」與「昨天還是 pass」在輸出上完全一樣。

## 範圍(兩件)

### 1. skip 轉換要出聲

- 維護一份**預期 skip 清單**(哪些測試在什麼條件下允許被跳過)
- 出現清單以外的 skip → 視為失敗,要人確認後才加進清單
- 判準與 legacy 清單、票宣告式豁免同構:**豁免要事先宣告,不得在被跳過的當下新增**
- 清單住哪裡要想:放測試裡會變成「自己給自己發豁免」,
  而 skip 是測試自己觸發的 —— 這條的「無法自我服務」比前幾次難設計

### 2. 查明本平台到底能不能測 R4 的 symlink 分支

- Windows 上建 symlink 需要開發人員模式或提權;**先查證這台機器的實際能力**
- **能測** → 補上必要的環境設定(寫進 `docs/machine-init.md`),讓那三條真的跑
- **不能測** → 明文標「此平台未測」,而且要標在**看得到的地方**:
  不是一句 skip 訊息,是一條會出現在每次執行摘要裡的宣告。
  同時要問:那 R4 的 symlink 分支靠什麼保證?
  (候選:CI 換平台跑、或安裝時的淨室驗證帶一次)

## 怎樣算做完

- 新增一個非預期的 skip → 套件紅
- 預期清單裡的 skip → 綠,但摘要裡看得到「有幾條被跳過、為什麼」
- R4 的 symlink 分支:有測,或有一條明文說「此平台未測」且指出它靠什麼守
