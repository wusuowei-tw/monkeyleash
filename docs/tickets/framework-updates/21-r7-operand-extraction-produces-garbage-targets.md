# 21 — R7 的逐運算元抽取對 Python 字串產生垃圾目標

**排程**:排隊,但**列 9/15 影子晉升評估前必辦**。
守衛設計變更,走完整流程。本批不修。

## 現象(量化 TSI-001 有完整記載,一 session 六次誤報)

票 19 把 R7 從「提到一個許可目標就整條免檢」改成「逐個抽出寫入目標」。
那修掉了一個 fail-open,但抽取器**看不懂引號**:它在整條指令字串上跑,
包含 `python -c "..."` 裡面的 Python 原始碼。

實測產生的垃圾目標:

| 來源 | 抽出的「目標」 |
|---|---|
| `print('a -> b')` 之類的箭頭 | `,` |
| `if i>7:` | `7:` |

## 為什麼比修之前更糟

修之前的訊息是**含糊但誠實**的:「這個 Bash 指令會寫入檔案,請改用 Write / Edit」。
現在的訊息是**具體而且錯誤**的:它點名 `,` 或 `7:` 是「沒有被許可的寫入位置」,
而那兩個東西根本不是路徑。

**這違反票 13 的判準**(fail-closed 的訊息必須說出是哪一個前提沒滿足)。
具體而錯誤比含糊而誠實傷害更大:含糊的訊息會讓人去查,
具體的訊息會讓人**相信**它,然後去找一個不存在的路徑。
與 F-046 同型 —— 那則是「讀到的是 import 違規,現場是括號沒閉合」。

## 根因

同一段位元組同時是「要被執行的東西」與「要被閱讀的東西」,
而抽取器只看得到前者(F-078 的可複用段已經寫下這句話)。
`REDIRECT_RE` 在整條字串上 `finditer`,分不出
「這個 `>` 是 shell 重導向」與「這個 `>` 在引號裡、是 Python 的比較運算子」。

## 候選方向(未裁決)

1. **抽取前先剝掉引號內容**:用 shell 詞法把 `'...'` / `"..."` 的內容遮成佔位符,
   再跑重導向與運算元抽取。風險:shell 引號規則有轉義、巢狀、`$(...)`,
   而「半套的解析器比零涵蓋更危險」是 R7 自己的原則。
2. **只對「看起來像路徑」的目標點名**,其餘退回含糊訊息:
   保住 fail-closed,但不謊報具體位置。實作最小,但等於承認抽取器不可靠。
3. **對 `python -c` / `node -e` 這類「整段程式碼當參數」的形狀特別處理**:
   它們的第一個引號之後全部是資料,不是 shell 語法。涵蓋面窄但精準。

## 與晉升的關係

影子模式的晉升靠誤擋率。**R7 的誤報會直接污染那個數字**,
而且方向是「看起來比較糟」—— 與 F-072 那則(樣本偏向看起來比較好)相反,
但同樣讓量測不可信。9/15 評估前必須有結論,否則算出來的比率
分不清「規則太嚴」與「抽取器在說謊」。

## 新標本(2026-08-14,票 26 調查途中,兩次)

同一個 session 又兩次,都是**唯讀診斷指令**:

| 指令片段 | R7 抽出的「目標」 |
|---|---|
| heredoc 裡的 `print("  LEGACY_LIST =", g.LEGACY_LIST)` | `,` |
| `echo "  -> $hp/pre-commit"` | `$hp/pre-commit`、`.git/hooks/pre-commit` |

第一條與上方表格的 `,` **完全同型**,來源同樣是引號內的 Python 原始碼。
第二條是新形狀:`->` 在 `echo` 的字串裡,而抽取器把箭頭後面那段當成重導向目標,
於是點名了**兩個**「沒有被許可的寫入位置」,其中一個還是變數字面 `$hp`(未展開)。

第二條特別值得留著:它抽出來的東西**看起來非常像路徑**,
所以候選方向 2(「只對看起來像路徑的目標點名」)**擋不住它** ——
`$hp/pre-commit` 與 `.git/hooks/pre-commit` 都會通過任何合理的「像不像路徑」判定。
這條把候選方向 2 從「實作最小」降級為「涵蓋不足」,選型時要算進去。

兩次都改走檔案工具,沒有繞道。

### 第三、四個標本(同 session,續)

| 指令片段 | 抽出的「目標」 | 分類 |
|---|---|---|
| `sed 's/…/<真實路徑>/g'` | `/g` | **誤擋** —— 唯讀診斷,`/g` 是替換旗標不是路徑 |
| `git commit -m "$(printf … )"` | `)` | **見下,不算誤擋** |

### ⚠ 第四個標本要分開計數(9/15 FP 率的計算方式)

第四個標本是**我自己違規輸入引發的**:家規早就寫著「訊息含標點走 `-F` 從草稿區」,
而我用了 `-m` 加行內 `$(printf …)`。**那一次擋是對的** ——
R7 攔下一個本來就不該那樣寫的指令。

但它抽出來的目標仍然是 `)`,一個垃圾。所以它同時證明兩件事:

1. **抽取器的問題與輸入的正當性無關** —— 就算指令本來就該被擋,
   抽取器點名的東西照樣是錯的,訊息照樣把人指向不存在的位置(票 13 判準)
2. **但它不是誤擋** —— 那條指令不該通過

**兩個論點都要保住,所以分開計數:**

| 計數桶 | 這一則算不算 |
|---|---|
| 抽取器產生垃圾目標(本票的核心證據) | **算** |
| 9/15 影子晉升的**誤擋率(FP)** | **不算** —— 那次擋是對的 |

把它算進 FP 率會讓「規則太嚴」的數字虛胖,而票 21 開頭就寫著
R7 的誤報會污染那個數字、且方向是「看起來比較糟」。
**用一個我自己造成的違規去證明規則太嚴,是把量測弄髒的另一種方式。**

### 第五、六個標本,以及四型分類

| 指令片段 | 抽出的「目標」 | 型 |
|---|---|---|
| `winget install --id FiloSottile.age` | **(解析不出寫入目標)** | **無目標仍擋** |
| `echo "原始 N B  ->  密文 M B"` | `密文` | 中文裡的 `->` |

第五個(winget)與前四個都不同:**指令正當**(已授權的安裝)、
**擋下也不全錯**(winget 確實寫系統),但 R7 **說不出它在保護什麼**。
前面幾個是「抽出垃圾目標」,這個是「**抽不出任何目標,仍然擋**」——
訊息因此完全無法指導行動,票 13 的判準在這裡整條落空。

第六個與 **F-078 完全同型**,而 F-078 記的正是
「中文技術文字用 `A -> B` 描述流程極常見,**規則的誤報率跟寫作語言相關**」。
同一個形狀在同一天出現三次,不是巧合,是那條耦合的日常表現。

**同一個工作日累計六個,分四型:**

| 型 | 次數 | 例 |
|---|---|---|
| 引號內的原始碼 | 1 | `print("x =", y)` 抽出 `,` |
| 中文/shell 字串裡的 `->` | **3** | `$hp/pre-commit`、`)`、`密文` |
| sed 的替換旗標 | 1 | `/g` |
| 抽不出任何目標仍擋 | 1 | winget |

### 第七、八個標本(換機器演練,卡點 #6a)

演練當天在**筆電**又撞兩次,都是 `REDIRECT_RE` 對字串字面量裡的 `>`:

| 形狀 | 說明 |
|---|---|
| `->` 在中文技術文字裡 | 與 F-078、與桌機那三次同型 —— **第四次以上** |
| **跳脫的 `2>&1`** | 新形狀:重導向寫在引號裡當字面量,抽取器分不出「這是要執行的」與「這是要被讀的」 |

**歸屬照 ADR 0008 的既有定性**:R7 只活在前哨、且刻意不做完整解析,
所以字面量誤擋是**已知代價**,不是新缺陷。但它們照樣進 FP 帳 ——
「已知」不等於「不計數」,否則那個代價永遠不會被量出來。

跳脫的 `2>&1` 值得單獨留著:它是**使用者刻意寫成字面量**的重導向,
也就是說 —— **連「作者明確表示這不是要執行的」都無法讓抽取器改變判斷**。
候選方向 1(先剝引號)對它有效,候選方向 2(只點名像路徑的目標)對它無效。

### 這句話本身是 9/15 評估的素材

**六個標本全部來自一個正常工作日** —— 沒有一個是為了測試 R7 而刻意構造的。
它們出現在寫測試、查證據、驗匯出、裝工具的日常路徑上。

所以評估晉升時要問的不是「誤報率是多少」,而是
**「一個正常工作日會撞幾次,以及撞到時人做了什麼」**。
今天的答案是六次,而每一次的處置都是繞去檔案工具或拆開指令 ——
沒有一次改變了我要達成的事,只改變了我用什麼形狀去達成。

**那正是 F-031 描述的那條路的起點:規則沒有擋住任何實際危險,
卻穩定地增加繞路成本 —— 而繞路成本累積起來,規則會被關掉。**
(第五個標本要分開看:那一次擋是對的,只是說不出理由;
它不進誤擋率,但它進「撞擊次數」。)

# 二審覆蓋對照(2026-08-14):八形狀 × 抽取器

形狀編號沿用二審(A–H)。**全部實測,不是推論。**

## 設計邊界:C / D —— R7 不做執行期路徑解析(票 29 體例)

```
cd /tmp && rm thing.py     擋 ✓  目標 thing.py
rm ../../thing.py          擋 ✓  目標 ../../thing.py
```

**兩者都被接住**:動詞閘觸發、目標抽得到、fail-closed 生效。
缺的不是攔截,是**解析深度**。

| | 現況 | 判定 |
|---|---|---|
| **C `cd` 跳目錄** | 報 `thing.py`,**讀起來像 repo 內**而實際在 `/tmp` | 擋是對的(往嚴倒);**位置誤導歸票 13** |
| **D `../` 穿越** | 目標原樣顯示 `../../thing.py`,**traversal 看得見** | 訊息誠實,無須處理 |

**這是決定,不是待辦:R7 不追蹤執行期 cwd、不做 `..` 正規化。**
理由是 R7 的立身之本 —— 那需要模擬 shell 狀態,而**半套的模擬比零涵蓋更危險**。

**分工寫明**:`..` 正規化歸 **G1 第二級**(`_is_scratch` 先 `posixpath.normpath`
再比對,理由是「許可前綴不能替後面那段背書」F-051)。
G1 的範圍是**專案外**,R7 的範圍是**專案內** —— 兩層各自解各自那一半,
而 R7 這一半刻意不解析,因為它 fail-closed。

## A / B:fail-closed 成立,而且在本機是活的

```
rm $target                          擋 ✓  目標 $target            ← 誠實:報字面
rm ${DIR}/thing.py                  擋 ✓  目標 ${DIR}/thing.py
rm $(cat list.txt)                  擋 ✓  目標 $(cat、list.txt)    ← 碎片
Remove-Item (Get-Content list.txt)  擋 ✓  目標 (Get-Content        ← 碎片
```

**A 的姿態是對的** —— 不解析變數,直接報字面,人看得懂「這裡有個變數」。
**B 是碎片**,擋得住但名字是垃圾(本票主症)。

**POSIX 例子在本機完全相關,不是理論**:Bash 工具跑的就是 git bash,
`$(...)`、反引號、`${VAR}` 全部有效;PowerShell 工具則有 `$var`、`(Get-Content ...)`。
**兩套語法在這台機器上都是活的。**

## H:抽取器**分不出讀/寫方向**(修正版敘述)

```
cp thing.py backup.py          目標 = thing.py、backup.py   ← 兩個都報
Copy-Item thing.py backup.py   目標 = thing.py、backup.py   ← 票 36 後改為全取
```

**分不出方向是事實**,而票 36 落地後**過度回報的實害已在許可層消解**:

```
Copy-Item .cache/x.json pkg/thing.py   擋 ✓  目標 = pkg/thing.py
```

`.cache/x.json` 是許可目標,**被正確過濾掉,沒有出現在訊息裡**。
也就是說:只被讀的來源若在許可清單裡就不會被點名;
不在許可清單裡的來源會被一起點名 —— 那是過度回報,但**方向是 fail-closed**。

**處置:訊息標注「來源/目的未區分」,不做 per-cmdlet 語意表。**
語意表要為每個 cmdlet 記住哪個參數是讀哪個是寫,那是一張**永遠不完整的表**,
而不完整的表就是 R4 的形狀(讀起來在守,實際只守一部分)。

## 三種 skip 語境的對照(硬約束的落點)

| 語境 | 解析/讀取失敗時 | 對不對 |
|---|---|---|
| **R7 抽取器** | ~~動詞認得但抽不到 → 回空 → 放行~~ → **票 36 已改為 refuse** | ✅ 修正後正確 |
| `scanner._globally_skipped` | 依副檔名/路徑**類別**跳過(`.png`、`.git/`) | ✅ 那是**類別豁免**,不是解析失敗 —— 兩者不可混談 |
| `scanner.read_text_or_none` | 讀不到位元組 → **計為違規**(`UNREADABLE`) | ✅ fail-closed |

**leak_scan 那邊早就統一過同一個病** —— `scanner.py` 開頭寫著
「一邊讀不動就 fail-closed,另一邊 `except: continue` 靜默跳過」。
**R7 這邊直到票 36 才補上。**

> 判準:**「這一類東西我不管」與「這一個東西我看不懂」是兩件事。**
> 前者可以跳過(類別豁免,列得出來),後者必須擋(解析失敗,列不出來)。
> 把後者做成前者,就是 fail-open。

## 怎樣算做完

- `python -c "print('a -> b')"` 之類的唯讀診斷不再被擋
- 真正的寫入(`> out.txt`、`rm -rf x`)照擋,訊息照樣點名**真的路徑**
- 抽不出可信目標時退回含糊但誠實的訊息,不謊報位置
- 六次誤報的實際指令形狀各有一條測試(TSI-001 有記載)
