## 一、事實(2026-08-31 實測,不是讀碼推的)

### `_target_allowed()`(`gate.py:528`,`BASH_ALLOWED_TARGETS`)

```
/tmp/x                                -> ALLOW    對照
/tmp/../etc/passwd                    -> ALLOW   🔴
.dev/x.jsonl                          -> ALLOW    對照
.dev/../.claude/hooks/gate.py         -> ALLOW   🔴
build/x                               -> ALLOW    對照
build/../../Windows/System32          -> ALLOW   🔴
src/x.py                              -> deny     對照(反控成立)
```

### `_allowed_cmd_prefix()`(`gate.py:426`,`BASH_ALLOWED_CMDS`)

```
git commit                            -> ALLOW    對照
python .claude/portable/install.py    -> ALLOW    對照
python .claude/../evil.py             -> ALLOW   🔴
gitfoo push                           -> deny     對照(票 76 A1 的邊界成立)
pipx run x                            -> deny     對照
python evil.py                        -> deny     對照
```

## 二、🔴 最貴的那一筆

> ### **`.dev/../.claude/hooks/gate.py` 拿到 `.dev/` 的豁免。**
> ### **一條寫向守衛自己的 Bash 指令,靠證據目錄的豁免過關。**

`.dev/` 那一列的理由欄逐字寫著「**流程證據,由機制自己追加(append-only),
不是人在編輯**」。那句話是對的 —— **而它替一個完全不同的目的地背書了**,
因為判定只問「字串裡有沒有 `/.dev/`」。

## 三、根因:**兩個函式,兩種不同的鬆法**

| 函式 | 怎麼比 | 缺了什麼 |
|---|---|---|
| `_target_allowed()` | **子字串包含**(`needle in haystack`) | **正規化,而且連前綴邊界都沒有** —— 它是這兩者裡比較鬆的那一個 |
| `_allowed_cmd_prefix()` | 前綴 + 邊界(票 76 A1 已修) | **只缺正規化。** 邊界擋得住 `gitfoo`,擋不住 `..` |

`BASH_ALLOWED_CMDS` 八項裡**只有 `python .claude/` 是路徑形態**
(唯一以 `/` 結尾的那一項),所以第二個函式的爆炸面比第一個小很多。
