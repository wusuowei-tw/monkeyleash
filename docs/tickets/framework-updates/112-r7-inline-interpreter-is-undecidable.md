## 二、為什麼這是缺口

**R7 的偵測這一側結構上是白名單。**

ADR 0003 的規矩是**黑名單 + fail-closed**:列出不管的東西,其餘全管,新東西預設被守。
而 `WRITE_CONSTRUCT` 是一份**寫入構造的白名單** —— 新的寫入形狀預設**不**被守。

這與 R7 自己的原則不衝突,要分清楚兩件事:

| | 對象 | 現行判準 | 正確方向 |
|---|---|---|---|
| **偵測**(有沒有在寫) | 整條指令字串 | **白名單**(列舉構造) | 過度涵蓋 |
| **抽取**(寫到哪) | 目標 token | 抽不出來就 refuse | 誠實 |

`gate.py:325-335` 已經寫下「**偵測要過度涵蓋,抽取才要誠實**」——
**這一格是偵測側沒有做到那句話。**

## 四、設計方向(照裁決:**擋並出聲**)

> **不可判定 ⇒ 擋,而且訊息要說「我判不出來」,不是說「你違規了」。**

三條硬規矩:

1. **不解析那段程式碼。** 一個字串參數裡的 Python / JS 是**資料不是 shell 語法**;
   要判斷它會不會寫檔就得寫一個直譯器語意的分析器,而
   **「半套的解析器比零涵蓋更危險」是 R7 自己的原則**(`gate.py:325-335`)。
2. **訊息說出是哪一個前提沒滿足**(票 13 判準):
   「這條指令帶了一段內嵌程式碼,我判不出它會不會寫檔」——
   **不得寫成「你寫了檔」**,那是具體而錯誤的訊息,而人會相信它然後去找一個不存在的寫入。
3. **給出口,而且是唯一那一個**(見下節)。訊息不給出口的話,
   人會發明繞路 —— 票 13 的活標本就是這樣長出來的。

**待裁的兩個尺度**(不要在寫碼時順手決定):

- **觸發面**:只認 `python -c` / `node -e`,還是「已知直譯器 + 已知程式碼旗標」的表?
  (前者漏 `perl -e`、`ruby -e`、`sh -c`、`powershell -Command`;後者要列舉來源,
  照 F-083 的判準:**去查各語言的旗標,不要憑印象**)
- **例外**:唯讀診斷佔了本 repo 絕大多數的真實用量(見刀一),
  要不要給一個「寫成 `.scratch/` 腳本檔」以外的窄門?**建議不要** —— 窄門會變成常用門。

## 十、落地(2026-09-07)

### 規則編號:掛在 R7 底下,不新開 `[R10]`

`rule_codes()` 的 docstring 自己寫了判準:
「`[R2/commit]` 這種帶子類的歸到 R2 —— **子類是同一條規則的不同時點,不是新規則**」。

本條與 R7 是**同一個對象**(工具呼叫)、**同一個出口**(改用檔案工具 / 腳本檔)、
**同一層**(sentinel-only)—— 差別只在問法:
**R7 問「寫到哪」,本條問「判不判得出來」。**

機器面的第二個理由:新開 `[R10]` 會讓 `rule_codes()` 多一條,而
`verify_gates.py` 要求**每一條規則都有一個淨室情境**;R7 在那裡本來就是特例
(前哨規則,commit 擋不到它)。硬造一個新編號等於在淨室裡多一個必須特判的規則,
**而它的特判理由與 R7 一字不差** —— 那是同一件事的第二份定義(票 29 的形狀)。
`tests/test_gate.py::TestInlineInterpretersAreUndecidable::test_the_rule_stays_inside_r7` 釘住這件事。

### 與 ADR 0008(R7 sentinel-only)的關係

> **本票是把 sentinel 既有的姿態往前延伸一步,不是開始解析程式碼。**

ADR 0008 說 R7 只活在前哨,因為它的**對象是工具呼叫** ——
「這個檔案是用 Bash 還是 Write 寫的」在提交時已經不存在了。
本條的對象完全相同(一個 Bash 工具呼叫),所以它**必然**也只活在前哨:
commit 看得到 staged 檔案,看不到那個檔案是被 `python -c` 寫出來的。

R7 對「寫到哪」抽不出來時的姿態是 **refuse 並明說**
(`unallowed_write_targets` 的「解析不出來時回一個佔位項(= 擋)」)。
本條是同一個姿態用在**上一個問題**上:

| 問題 | 抽不出來時 |
|---|---|
| 這條指令**寫到哪**? | 回佔位項 → 擋(既有) |
| 這條指令**有沒有在寫**? | **擋**(本票) |

**沒有引入任何解析。** 本規則讀的只有:指令位置的 token、以及後面有沒有一個
「後面是程式碼」的旗標 —— 兩者都是 shell 語法層的東西,
**引號裡那一段一個字元都沒有被讀**。這一點寫進了實作的 docstring 與擋下訊息本身
(「本規則不解析引號裡的程式」),讓下一個讀的人不會以為這裡開了一個解析器。

**ADR 0008 的兩句話仍然逐字成立**:R7(含本子類)繞過前哨就沒有第二道;
所以擋下訊息**不套** `sentinel_footer()` 之外那句「commit 會擋」——
沿用既有的 R7 出口(`gate.py` 的 R7 分支自己印那段),本票不動它。
