# 票 163 —— R7／G1 三個殘留缺口：git -c、許可前綴帶重導向整段放行、G1 看不懂 $HOME 形態

**狀態**：候選，待排程。

## 來源

票 158 A-R0（2026-10-22）附帶發現；Jeff 2026-10-22 約 16:48（美東）裁「立候選票」（裁決助手記錄，非逐字原話）。

## 三個缺口

### 1. `git -c key=val …`

- **現象**：不需要任何環境變數前綴，就能用 `git -c key=val …` 改變 git 的行為（例如 `core.hooksPath`、`diff.external`）。
- **讀碼依據**：R7 的許可清單 `BASH_ALLOWED_CMDS` 以 `git` 為前綴整段許可；`_allowed_cmd_prefix` 只看指令開頭，不看 `-c` 帶進來的設定。〔讀碼推論，未實驗〕
- **風險**：票 158 A3 收緊的是「指令位置前的 `VAR=value`」，而 `git -c` 達成同一類效果（字串上看不出來的行為改變），卻落在許可前綴之內，不受 A3 影響。`core.hooksPath` 一類設定直接碰到權威層的掛載點。
- **可能修法（只列不選）**：
  - (a) `git` 許可前綴排除帶 `-c` 的形式（`-c` 之後才算許可）；
  - (b) 只放行一份列名的 `-c` 鍵（比照 A3 的例外變數表）；
  - (c) 不改，只記帳（比照 A3 的量測）。

### 2. W3：許可前綴帶重導向整段放行

- **現象**：`python .claude/x.py > pkg/a` 被許可前綴整段放行（票 158 C0-3 已知，記為 W3）。
- **讀碼依據**：`bash_write_violation` 在「每一段都以許可前綴開頭」時直接回 None，不進目標抽取；重導向目標因此從未被看過。〔讀碼推論，未實驗〕
- **風險**：方向與票 158 A3 相反——帶 `PYTHONIOENCODING=utf-8` 前綴的同一條指令會掉出許可清單而進目標抽取、被擋；不帶前綴的反而放行。同一個寫入，嚴格度取決於一個與寫入無關的前綴。
- **可能修法（只列不選）**：
  - (a) 許可前綴只免除「指令本身」，重導向目標照樣抽取比對；
  - (b) 許可前綴帶重導向時一律擋；
  - (c) 維持現狀，在 ADR 0008 明寫為殘留缺口。

### 3. G1 第一級看不懂 `$HOME` 形態

- **現象**：G1 第一級的 `variants()` 只產生 `~` 形態，不產生 `$HOME`、`$env:USERPROFILE`、`%USERPROFILE%`；用這些寫法指到受保護路徑時比對不到。
- **讀碼依據**：票 158 A-R0 讀 `g1_guard.py` 的 `variants()`（立案時未重讀）。〔讀碼推論，未實驗〕
- **風險**：G1 掛在使用者層，在沒有安裝 gate 的 repo 也生效；那些 repo 沒有 R7 兜底，G1 第一級是唯一一道。
- **可能修法（只列不選）**：
  - (a) `variants()` 加產這三種形態；
  - (b) 比對前先展開環境變數寫法；
  - (c) 指令含 `$HOME`／`$env:`／`%…%` 且指向使用者層時一律擋。
- **注意**：G1 改動走 ADR 0009 的人覆蓋流程（草稿、全套驗收、附 diff，覆蓋只有人能做）。

## 限制

- 任何修法都要照 F-031「沒有門的牆會被整條關掉」留出口。
