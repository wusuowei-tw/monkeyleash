# 24 — 「Untested by decision」豁免可被代理人自助

**排程**:票 23 之後、票 22 Phase 2 之前。**本票只開票,不動碼。**

**缺陷家族**:**豁免可被代理人自助**。
與「豁免來源不可自我服務」是同一個遞迴 —— G1 把保護清單列進保護清單、
`check_legacy_list` 把凍結清單綁到 go-live 樹,都是這一族的既有解。這一條是漏掉的那個。

## 現況(全部已驗證)

R3 的豁免宣告 `**Untested by decision:**` 從 `.scratch/<feature>/issues/` 讀
(`gate.py:675`,前哨路徑;`gate.py:1311-1313` 是呼叫點,命中即 `note_exemption` 記一筆並放行)。
提交路徑走 `logged_exemption_backed`(`gate.py:694`),它**不採信紀錄本身**,
會回頭打開紀錄指名的票確認 —— 判準是對的。

問題在那個「回頭打開」打開的是什麼:

| 事實 | 位置 |
|---|---|
| `.scratch/` 在 `.gitignore` 裡,**不進版控** | `.gitignore:27`(`/.scratch/`) |
| 目前 `.scratch/framework-updates/issues/` 是**空的**;實際的票住在進版控的 `docs/tickets/<feature>/` | 已列舉 |
| 提交時的確認只做 `os.path.exists(p)`,**完全不碰 git** | `gate.py:713-716` |
| 豁免紀錄本身也不進版控 | `.gitignore:18`(`/.dev/`) |
| `ticket_untested_modules` 與 `Untested by decision` 在 `tests/` 底下**零測試涵蓋** | 已查 |

**於是整條豁免鏈:宣告在未追蹤目錄、紀錄在未追蹤目錄、確認只看工作樹檔案存不存在。**
從頭到尾沒有任何一環留下版控痕跡。

## 為什麼「今天是空的」不等於安全

`ticket_untested_modules` 讀不到宣告時回 `(set(), None)` = 不豁免,方向是 fail-closed。
所以**此刻沒有任何東西被解鎖** —— 這是本票排在票 23 之後而不是之前的理由。

但「空著」是狀態,不是機制。`.scratch/` 是**代理人可寫**的位置:
被 R3 擋住的當下,建一個 `.scratch/<feature>/issues/<票號>-x.md`、
寫一行 `**Untested by decision:** <模組名>`,豁免就到手了,
而且**不會出現在任何 diff、任何 review、任何 clone 裡**。

這正好推翻那段程式碼自己寫下的理由:

> 豁免不是 gate.py 自己開的後門 —— 它去讀一個**前一站產物裡已經存在的決定**。
> 要新增豁免必須回頭改票,**那是看得見、會被審查的動作**。

在 `.scratch/` 底下,改票**不是**看得見的動作。理由與實作對不上。

同一份檔案裡的 `check_legacy_list` 把同型問題解對了,而且把理由寫死了:

> 清單檔本身落在 `.agents/`(非原始碼)、沒有任何規則守它,被 R3 擋下的人
> 只要在末尾加一行就豁免到手 —— 完全不必碰 git 歷史,
> 而「無法自我服務」正是選這個設計的**唯一**理由。
> 「有一條測試會抓到」不算守住:沒有機制強制那條測試被跑。

**那段話逐字適用於本票。** 差別只在它綁了 go-live 樹,這裡沒綁任何東西。

## 修法方向(候選,本票內議,未裁決)

1. **宣告改讀進版控的 `docs/tickets/<feature>/`。**
   最小改動,與 repo 現況一致(票本來就在那裡)。
   但「檔案在版控目錄裡」不等於「已經 commit」—— 未 staged 的新檔一樣存在於工作樹。
   → 單獨用它只把位置搬對,自助性沒解掉。
2. **要求宣告必須存在於已 commit 的票檔**(照 `check_legacy_list` 的形狀,綁 git 物件而非工作樹)。
   解得徹底,代價是前哨要能問 git,而前哨在 pre-commit 之前跑,基準點取哪個要議
   (HEAD?go-live?)。R3 的紅燈判定已經在讀 `head_content_hash`,有現成先例。
3. 兩者合併:位置搬到 `docs/tickets/`,**且**確認綁 HEAD。

決定時要回答的問題,不是「哪個好寫」,而是 —— **被 R3 擋住的代理人,
能不能靠自己造出一個滿足這個判定的東西?** 能,就還沒修完。

## 一併納入範圍

- `ticket_untested_modules` 與 `logged_exemption_backed` 的**零測試涵蓋**。
  現行沒有任何測試證明豁免會被授予、或會被拒絕 —— 修完之後照樣得有紅燈,
  否則下一次改動把它改回自助也不會有人發現。
- `PROTOTYPE_RE`(`gate.py:119`)也指向 `.scratch/`。**只查不改**:
  確認它是不是同一族(未追蹤位置決定放行與否),是的話在本票補一節,不是的話寫下為什麼不是。

## 選型定奪(2026-08-14):候選 2,綁已 commit 的內容

**候選 1(只把位置搬到 `docs/tickets/`)單獨用不成立。** 判準只有一條 ——
**被擋住的代理人,能不能靠自己造出一個滿足這個判定的東西?**
未追蹤的新檔在哪個資料夾都一樣好造,搬位置只換了洞的地址。

採候選 2,形狀抄 `check_legacy_list`(綁 go-live 樹),它的理由逐字適用。

### 三個實作細節,每個都是一次可能的半修

1. **綁的是「宣告已在 HEAD」,不是「路徑被 commit 過」。**
   只驗路徑的話,可以先 commit 一張空票、再把宣告加在工作樹上 ——
   洞原封不動,只是多一步。所以讀的是 **HEAD 的那一版內容**(`committed_declaration`)。
2. **兩個時點都要綁。** 前哨走 `ticket_untested_modules`、提交走
   `logged_exemption_backed`,只修一半等於沒修:留著的那一半就是繞道
   (在被擋當下造一張票,讓另一個時點來認它)。**鬆的那一邊定義整條規則。**
3. **位置不綁死** —— 見下方跨 repo 證據。兩個位置都找,做事的是 commit 這個條件。

### 順帶消掉的重複

宣告的解析原本在前哨與提交路徑**各有一份副本**,已抽成 `declared_untested()`。
兩份會分岔,而分岔在豁免判定裡的後果是一邊放行一邊擋(ADR 0003)。
取 HEAD 內容也統一成單一入口 `head_blob()`,`head_content_hash` 改為呼叫它(F-080)。

### 使用上的後果(誠實寫出來)

**豁免要生效,票必須先 commit。** 也就是「宣告」與「用掉宣告」至少分兩個 commit。
那不是副作用,那就是這條規則要的東西 —— 與 R3 docstring 早就寫著的
「宣告在前,不得在被擋當下新增」一致。

## 2c:同一個豁免位置,上游不受審查、下游受審查

實測四個 repo 的 `.scratch/` 版控狀態:

| repo | 追蹤中的 `.scratch/` 檔數 | gitignore |
|---|---|---|
| **agent-gates** | **0** | `.gitignore:27 /.scratch/` |
| TradingAgents | **31** | 無 |
| 台股分析師影音 | **21** | 無 |
| 台股資訊收集 | **3** | 無 |

**只有框架自己的 repo 把豁免宣告放在不進版控的位置。** 三個下游 repo 反而
把它進版控 —— 方向剛好反了,而 F-0014 說的是「上游自己做不到的紀律不得要求下游」,
這裡是上游的紀律**低於**下游。

這也解釋了為什麼綁死資料夾名字會出事:綁 `.scratch/` 則 agent-gates 永遠找不到票
(它的票在 `docs/tickets/`),綁 `docs/tickets/` 則三個下游全部失效。
兩種失效方向都是 fail-closed,但**擋的是做對事的人**,而那種規則最後會被整條關掉。

## 3. `PROTOTYPE_RE` 只查不改的結論:**同族,但不是同一個缺陷**

`PROTOTYPE_RE = ^\.scratch/[^/]+/prototype/`(gate.py:119),用在
`is_source_path()` 裡 —— 命中就不算原始碼,於是 R2 / R3 都不管它。

**同族**:豁免綁**路徑**,而那個路徑代理人自己寫得進去。
形式上確實是「代理人可以靠選擇寫在哪裡來取得豁免」。

**但不是同一個缺陷**,差別在爆炸半徑:

| | 豁免解鎖了什麼 |
|---|---|
| Untested by decision | **生產碼路徑的寫入** —— 半徑是整個 repo |
| `PROTOTYPE_RE` | **只有 `.scratch/<feature>/prototype/` 底下** —— 正則錨了 `^`,豁免到不了那個目錄以外 |

**自我服務只有在「你給自己的東西伸得出去」時才危險。**
prototype 的豁免伸不出去:那些檔案要進生產線必須被移出該目錄,
而移出就是一次普通的寫入,照樣受 R2 / R3 判定。

這正是 `pipeline-stages.yaml` 給 `research` 站寫下的同一條理由:
「把豁免爆炸半徑縮到零 —— 不管誰宣告 research,都寫不了生產碼」。
`PROTOTYPE_RE` 是那條原則的既有實例,**不需要改**。

> 判準記下來:**路徑型豁免的安全性,取決於它涵蓋的範圍是不是它自己所在的範圍。**
> 涵蓋自己 = 封閉,安全;涵蓋別處 = 開放,就是票 24 這種洞。

## 落地紀錄(2026-08-14)

紅燈先行:`tests/test_gate.py::TestUntestedByDecisionCannotBeSelfServed`,
**3 紅 3 綠**,`ticket_id 24`、`impl_hash` 為改動前的 `gate.py`。

少了它們,「一律不豁免」的實作也會讓三條紅轉綠,而那是把功能拿掉不是修好。

## 怎樣算做完

- 前哨與提交兩條路徑的豁免判定,**都不再只靠工作樹檔案存不存在**
- 有一條測試模擬「代理人在未追蹤位置自己造宣告」→ **必須擋**(這是本票的核心紅燈)
- 有一條測試證明**合法**的豁免仍然授得出來(否則就是把功能拿掉,不是修好)
- 訊息說得出是哪一個前提沒滿足(F-046 / 票 21 的判準)
- `PROTOTYPE_RE` 的結論寫進票裡,不論結論是哪一邊
