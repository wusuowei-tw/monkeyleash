# 24 — 「Untested by decision」豁免可被代理人自助

**排程**:票 23 之後、票 22 Phase 2 之前。**本票只開票,不動碼。**

**缺陷家族**:**豁免可被代理人自助**。
與「豁免來源不可自我服務」是同一個遞迴 —— G1 把保護清單列進保護清單、
`check_legacy_list` 把凍結清單綁到 go-live 樹,都是這一族的既有解。這一條是漏掉的那個。

## 現況(全部已驗證)

R3 的豁免宣告 `**Untested by decision:**` 從 `.scratch/<feature>/issues/` 讀
(`gate.py:675`,前哨路徑;`gate.py:1311-1313` 是呼叫點,命中即 `note_exemption` 記一筆並放行)。
提交路徑走 `logged_exemption_backed`(`gate.py:694`),它**不採信紀錄本身**,
會回頭打開紀錄指名的票確認 —— 判準是對的。

問題在那個「回頭打開」打開的是什麼:

| 事實 | 位置 |
|---|---|
| `.scratch/` 在 `.gitignore` 裡,**不進版控** | `.gitignore:27`(`/.scratch/`) |
| 目前 `.scratch/framework-updates/issues/` 是**空的**;實際的票住在進版控的 `docs/tickets/<feature>/` | 已列舉 |
| 提交時的確認只做 `os.path.exists(p)`,**完全不碰 git** | `gate.py:713-716` |
| 豁免紀錄本身也不進版控 | `.gitignore:18`(`/.dev/`) |
| `ticket_untested_modules` 與 `Untested by decision` 在 `tests/` 底下**零測試涵蓋** | 已查 |

**於是整條豁免鏈:宣告在未追蹤目錄、紀錄在未追蹤目錄、確認只看工作樹檔案存不存在。**
從頭到尾沒有任何一環留下版控痕跡。

## 為什麼「今天是空的」不等於安全

`ticket_untested_modules` 讀不到宣告時回 `(set(), None)` = 不豁免,方向是 fail-closed。
所以**此刻沒有任何東西被解鎖** —— 這是本票排在票 23 之後而不是之前的理由。

但「空著」是狀態,不是機制。`.scratch/` 是**代理人可寫**的位置:
被 R3 擋住的當下,建一個 `.scratch/<feature>/issues/<票號>-x.md`、
寫一行 `**Untested by decision:** <模組名>`,豁免就到手了,
而且**不會出現在任何 diff、任何 review、任何 clone 裡**。

這正好推翻那段程式碼自己寫下的理由:

> 豁免不是 gate.py 自己開的後門 —— 它去讀一個**前一站產物裡已經存在的決定**。
> 要新增豁免必須回頭改票,**那是看得見、會被審查的動作**。

在 `.scratch/` 底下,改票**不是**看得見的動作。理由與實作對不上。

同一份檔案裡的 `check_legacy_list` 把同型問題解對了,而且把理由寫死了:

> 清單檔本身落在 `.agents/`(非原始碼)、沒有任何規則守它,被 R3 擋下的人
> 只要在末尾加一行就豁免到手 —— 完全不必碰 git 歷史,
> 而「無法自我服務」正是選這個設計的**唯一**理由。
> 「有一條測試會抓到」不算守住:沒有機制強制那條測試被跑。

**那段話逐字適用於本票。** 差別只在它綁了 go-live 樹,這裡沒綁任何東西。

## 修法方向(候選,本票內議,未裁決)

1. **宣告改讀進版控的 `docs/tickets/<feature>/`。**
   最小改動,與 repo 現況一致(票本來就在那裡)。
   但「檔案在版控目錄裡」不等於「已經 commit」—— 未 staged 的新檔一樣存在於工作樹。
   → 單獨用它只把位置搬對,自助性沒解掉。
2. **要求宣告必須存在於已 commit 的票檔**(照 `check_legacy_list` 的形狀,綁 git 物件而非工作樹)。
   解得徹底,代價是前哨要能問 git,而前哨在 pre-commit 之前跑,基準點取哪個要議
   (HEAD?go-live?)。R3 的紅燈判定已經在讀 `head_content_hash`,有現成先例。
3. 兩者合併:位置搬到 `docs/tickets/`,**且**確認綁 HEAD。

決定時要回答的問題,不是「哪個好寫」,而是 —— **被 R3 擋住的代理人,
能不能靠自己造出一個滿足這個判定的東西?** 能,就還沒修完。

## 一併納入範圍

- `ticket_untested_modules` 與 `logged_exemption_backed` 的**零測試涵蓋**。
  現行沒有任何測試證明豁免會被授予、或會被拒絕 —— 修完之後照樣得有紅燈,
  否則下一次改動把它改回自助也不會有人發現。
- `PROTOTYPE_RE`(`gate.py:119`)也指向 `.scratch/`。**只查不改**:
  確認它是不是同一族(未追蹤位置決定放行與否),是的話在本票補一節,不是的話寫下為什麼不是。

## 怎樣算做完

- 前哨與提交兩條路徑的豁免判定,**都不再只靠工作樹檔案存不存在**
- 有一條測試模擬「代理人在未追蹤位置自己造宣告」→ **必須擋**(這是本票的核心紅燈)
- 有一條測試證明**合法**的豁免仍然授得出來(否則就是把功能拿掉,不是修好)
- 訊息說得出是哪一個前提沒滿足(F-046 / 票 21 的判準)
- `PROTOTYPE_RE` 的結論寫進票裡,不論結論是哪一邊
