## 目標(驗收標準)

一台全新 Windows 機器,**15 分鐘內**把開發環境復原到可工作狀態。
劇本必須被**實際演練過**——`docs/machine-init.md` 寫得很細,但從未實測過,
而它自己第二節就寫著「複製檔案不算裝好」。**沒演練過的復原劇本與沒有劇本的差別,
只在於前者會讓你以為自己有。**

## 三項硬約束(已定案,不得偏離)

1. **不用 symlink。** `<使用者家目錄>/.claude/` 維持正本(canonical 純檔案),
   改做**單向匯出/匯入**腳本。
   理由:symlink 會讓 dotfiles repo 的 working tree 變成**第二條可寫路徑**——
   那是自助豁免漏洞的標準形狀(與「豁免來源不可自我服務」同一個遞迴)。
   附帶:Windows symlink 還要開發者模式;R4 的 symlink 測試在本機本來就 skip。
2. **演練環境必須 Windows 原生**。~~第二個本機使用者帳號,或 Windows Sandbox。~~
   **(Aug 14 增補裁決)改用真實的第二台機器 —— Jeff 的 Windows 筆電。**
   不用 WSL2/Linux —— **驗證錯的作業系統會產生假摩擦**(cp950 與路徑那一整族教訓)。
   驗收標準不變:照 `machine-init.md` 從零開始,**15 分鐘內可開工**。
   演練通過後筆電轉為**正式第二工作機**。
   > 換成真機器讓演練更真:第二使用者帳號共用同一份已安裝的執行環境與登錄檔,
   > 「這台機器本來就有」的東西會被誤當成「劇本裝好的」。真機器沒有那個假設。
3. **最小加密**:低敏感檔案進私有 repo 即可;只有個人 leak-pattern 清單用 age 加密,
   金鑰進密碼管理器 + 紙本各一份。

### Phase 1 的四個實質發現

**發現 1 —— 兩個 repo 沒有任何 remote,合計 78 個 commit 只存在這台機器上。**
其中一個還帶著兩個**整包未追蹤的目錄**。
雲端同步目錄有一份,但**同步不是備份**:刪除會傳播,而且它沒有版本語意。
這是本次盤點裡最大的單點風險,也是**最便宜的一步**——開私有 remote 推上去,不必等 Phase 2。

**發現 2 —— G1 保護清單只列目錄,`<資料目錄>` 根目錄的憑證檔沒被涵蓋。**
G1 第一級是**前綴比對**;清單裡沒有涵蓋根目錄那一層,於是散在那裡的多份憑證檔
(不只候選清單寫的那一份,實際是**五份**,含一份現行有效的)**目前沒有 G1 保護**。
家目錄底下幾個憑證存放目錄同樣不在清單裡。
→ 這不是本票要修的東西,但**要開票**。修法是加進保護清單,而那一步只有人能做(ADR 0009)。

**發現 3 —— `leak_scan` 的 `CERT_EXT` 漏掉兩種憑證副檔名(PKCS#8 私鑰與 PKCS#7 簽章包)。**
`CERT_EXT` 是「副檔名即判定、不掃內容」,那條路徑是 F-062 紅燈換來的
**二進位憑證唯一可靠攔截點**。這兩種副檔名不在裡面 → 退回**內容比對**那條較弱的路徑。
本機實際存在這兩種檔案,實測是 PEM 文字,通用 pattern 的私鑰標頭式**應該**打得到——
但「應該打得到」不是「保證擋得住」,而 F-062 的教訓正是別依賴內容比對。
→ **要開票**。

**發現 4 —— 兩邊的影子/豁免證據都沒有 off-machine 副本。**
本 repo 的 `.gitignore` 擋掉整個 `/.dev/`;quant 那邊 `shadow-log.jsonl` 與 `shadow.json`
也各自被 gitignore。另有三份影子基線 `.jsonl` 散在工作台根目錄,**不在任何 repo 內、沒有任何規則管它們**。
→ **9/15 的影子晉升評估要靠這些數字。磁碟壞在 9/15 之前,晉升評估就沒有樣本。**
與票 21 是同一個晉升前提的兩面:票 21 管樣本**乾不乾淨**,這一條管樣本**還在不在**。

### 二之一、Phase 3 必跑:保護清單的**存在性**檢查

`g1_verify` 與唯讀探針的前四段,探針字串都是**從條目本身組出來的**,
所以一條打錯字的路徑照樣全綠 —— `machine-init.md` 第二節末已經用人話警告過:

### 三、雙機引入的新問題(**本票不解,記錄待議**)

`machine-init.md` 目前假設「一台機器」。雙機常態化之後至少有兩件事沒有答案:

1. **保護清單在兩台機器上會分歧** —— 清單是照**該機器實際存在的路徑**寫的
   (machine-init 第二節末的關鍵警告),筆電的磁碟結構與桌機不同,
   所以兩份清單**本來就不該相同**。那 sha 核對要核什麼?
   → 這與跨機器 provenance 信任是同一個問題的兩面,歸那張獨立的 guard 設計票。
2. **證據檔(`.dev/`)在兩台機器上各自增長** —— 影子晉升要靠合併後的數字,
   而 append-only 的兩份紀錄怎麼合併、合併後票號會不會撞,沒有設計。
   → 9/15 晉升評估之前必須有答案,與 R5 同一個期限。

## Phase 2 —— 單向 export/import 腳本(station-④ TDD,真紅燈先行)

盤點推出來的三個硬約束,**不是設計偏好**:

1. **匯出腳本讀不到保護清單與影子安全閥。** 它們在 G1 保護清單裡,第一級無豁免、不分讀寫,
   由 agent 執行時會被擋。
   → 要嘛這兩項由人手動複製、要嘛腳本只由人在自己的終端機跑。
   **這一點必須先裁決,它決定腳本長什麼樣。**
2. **匯入端不得無腦覆蓋保護清單。** machine-init 第二節末已寫下這條:
   清單是文字比對,抄舊機器的路徑到新機器上等於白列,
   而 `g1_verify` 全綠**不會**告訴你這件事(它只證明「清單裡每條被命中時擋得住」)。
3. **匯出目標 repo 必須先裝洩漏偵測**,否則「低敏感但含絕對路徑」那批會把使用者名稱推上去。

### 具名原則:**預設值是為某一種代價結構挑的,換了結構就得重挑**

`portable-manifest.txt` 的預設是 `copy`,理由寫在它自己表頭:
「多帶是吵鬧的(到了新專案馬上發現不對),少帶是靜默的」。

**在 `~/.claude/` 這個 payload 上,那個不對稱是反過來的:**

| | 框架檔 | 使用者層 |
|---|---|---|
| 多帶 | 吵鬧 | **把憑證推上雲端 —— 靜默且不可逆** |
| 少帶 | 靜默 | 吵鬧(換機器當場發現) |

**同一個預設值,搬到相反的不對稱上就變成缺陷。**
所以重用既有碼時要問的不只是「這段程式碼做的事對不對」,還有
**「它的預設是為哪一種代價結構挑的」**。

而票 15 已經預先解決了:`explicit_mark` 未命中回 `None`,
「要不要有預設,由各呼叫端明確選」。所以這裡只要**選「沒有預設」**,
不必改任何既有碼,分岔的可能性為零。

### 重用的邊界(F-080 前置的實際結果)

| 元件 | 處置 |
|---|---|
| `manifest.load_table` 的解析器(最長前綴、格式錯誤要吵) | **參數化重用** —— 加 `allowed=` 換詞彙,預設 `None` 保持既有行為 |
| `manifest.explicit_mark`(沒有預設的查詢) | 直接重用 |
| `manifest.mark_for` / `mark_in` / `DEFAULT_MARK` / `in_scope` | **拒絕**(見上) |
| `sync.Refused` / `sync.file_hash` | 直接重用 —— sha 定義只有一份,人工核對才算得出同一個值 |
| `sync.update(..., apply=False)` 的 dry-run 預設 | 重用其形狀,直接支撐「先算後報再寫」 |

複製一份 parser 出去會違反 `load_table` 自己寫下的理由
(「同一件事只留一個實作,連『格式錯誤要吵』這件事也一起繼承」)。

### 具名原則:「依構造唯讀」與「已驗證未動」是不同強度的兩句話

這次**沒有做前後 sha 配對**,回報的是「依構造唯讀」(只有 `os.walk` +
`zipfile.write`,沒有任何寫入路徑),不是「已用雜湊驗證未被動過」。

理由不是省事:**`test-runs.jsonl` 每跑一次測試就變**。
對一個會自然變動的證據檔做前後配對,得到的差異是**噪音而不是證據** ——
而一份看起來像驗證、實際上量的是別的東西的報告,比不做驗證更糟
(F-032:綠的原因不是你以為的)。

> **說弱而真的那一句,勝過說強而空的那一句。**
> 判準:報告的強度要對得起實際做過的觀測。
> 「我沒有做那個驗證」是可以寫出來的;「我做了」而其實量的是雜訊,不行。

前面票 27 的負控是另一半的示範:那次**做得成**配對(四份帳本前後位元相同),
因為那個操作預期不改變任何東西,而且沒有背景寫入者。
**同一種驗證,在會變動的對象上就失效** —— 選不選它取決於對象,不是取決於嚴謹度。

zip 內以 repo 名分頂層目錄,因為**證據脫離它的 repo 就失去意義**:
`test-runs.jsonl` 只有配上「哪個 repo 的哪張票」才解釋得動。

> 在此之前那些數字只存在於這台機器,而票 21 管的是樣本乾不乾淨、
