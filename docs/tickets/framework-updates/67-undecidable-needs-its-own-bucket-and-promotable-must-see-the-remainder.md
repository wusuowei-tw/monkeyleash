# 67 — 「無法判定」要有自己的桶,而 `promotable` 必須看得見未判定的餘量

**狀態**:**已落地(2026-08-19)** —— 11 條測試,紅燈先行。見文末〈落地〉。
**立案**:2026-08-19,裁決第 2 項
**相依**:票 65(第六桶已落地)、票 63(讀得到日誌)
**⚠ 期限**:**9/16 是自動轉正日**。本票不解,R7 會帶著一個由偏樣本算出來的
`0.0%` 假陽率自動轉正。

---

## 裁決給定的三條

1. 加「無法判定」桶
2. **不進假陽率的分子,也不進分母** —— 它是**判定不能**,不是判定結果
3. `print_status` 單獨列一欄;9/15 評估報告要寫明「72 筆無法判定,因日誌未記指令」

## 立案時沒看到、套用後才現形的第四條

2026-08-19 套用第一批(130 筆刻意 refuse)之後,量化的 `--status` 印出:

```
R7   已分類 130  真陽   0  刻意 refuse 130  誤報   0  假陽率   0.0%  -> 可轉正
```

**`可轉正`。** 而同一份日誌裡還有 **72 筆 R7 沒判**,誤報全部在那裡面。

`promotion_status` 的判定是:

```python
d["promotable"] = (n >= MIN_CLASSIFIED and d["fp_rate"] < MAX_FALSE_POSITIVE_RATE)
```

`n` 是**已分類**筆數。所以:

> **一條規則可以靠「只判對自己有利的那一群」把自己判成可轉正。**
> 而判的順序完全合理 —— 先判機械上判得出來的那一群,那正是本輪做的事。

**這不是本輪造成的缺陷,是本輪讓它現形。** 舊的五類時代它一樣成立,
只是那時一筆都還沒判,所以 `per` 是空的、沒有任何規則顯示可轉正。

### 所以本票要多做一件

> **`promotable` 必須把「這條規則還有多少筆沒判」納入。**

`MIN_CLASSIFIED ≥ 10` 這個條件原本的用意是「樣本要夠」,
但它問的是**絕對數**,不是**涵蓋率** —— 130 筆已分類 / 202 筆總數 = 64%,
而剩下 36% 恰好是機械規則判不動的那一群,**也就是最可能含誤報的那一群**。

**候選判準**(設計時決定,本票不預設):

| | 判準 | 問題 |
|---|---|---|
| (a) | 未判定筆數 > 0 → 一律不可轉正 | 最嚴。但「無法判定」若是永久狀態(日誌沒記指令,救不回來),這條會讓 R7 永遠不可轉正 |
| (b) | 涵蓋率門檻(例如已判定 ≥ 90%) | 要選一個數字,而選它的依據是什麼? |
| (c) | 未判定 → 一律不可轉正,**但「無法判定」桶不算未判定** | 把「判過了、結論是判不出來」與「還沒判」分開 —— 與裁決第 2 條同一個精神 |
| (d) | 不改 `promotable`,只讓 `--status` 大聲印出未判定筆數 | 訊息不是機制;而 9/16 是自動的,沒有人一定會去讀 |

**傾向 (c)**,理由是它與裁決第 2 條同構:
**「判不出來」是一個判定結果,「還沒判」不是。**
前者可以進晉升決策(它是關於證據的事實),後者不行(它是關於進度的事實)。

⚠️ **但 (c) 有一個要先答的**:若 72 筆全部標成「無法判定」,
R7 就會是「已判定 202 / 202,其中 72 筆判不出來,假陽率 0.0%」→ **可轉正**。
**那與 (d) 的結果一樣。** 所以 (c) 還需要一句:
**「無法判定」的比例本身要不要是一個門檻?**
—— 一條有 36% 判不出來的規則,它的 0% 假陽率代表什麼?
**這一題本票必須答,不能留給實作時順手決定。**

## 為什麼那 72 筆判不出來(事實,不是推測)

日誌一筆的欄位集合(全 222 筆聯集):

```
['at_commit', 'message', 'rule', 'ts', 'verdict']
```

**沒有指令原文。** 實測:`python` 出現在 0/202 筆 R7 的 `message` 裡,
`git ` 0/202,`&&` 0/202,`bash` 0/202。

一筆的原樣:

```json
{"ts": "2026-08-15T03:47:37.702840+00:00", "rule": "R7", "at_commit": false,
 "verdict": "would-block",
 "message": "[R7] 這個 Bash 指令會寫到沒有被許可的位置(1]),請改用 Write / Edit。"}
```

> **`1]` 是不是一個真的寫入目標?從這筆紀錄看不出來。**

fail-closed 那一群是唯一例外:它的 `message` **自述判定理由**
(「引號或跳脫使目標無法可靠切分」),而理由本身就是分類依據。

**救不回來的部分**:記指令是票 68,而票 68 只對**未來**的紀錄有效。
這 72 筆的指令已經不存在了。

(五類時代)對檔案第 1~66 筆做過人工判定,**但只留下三個總數,沒有逐筆答案**
(實查:`.scratch/` 與 `docs/audits/` 零命中)。
機械分群與它在同一區間差 **5 筆**(27 對 32),**而那 5 筆對不回去**。

> ADR 0012 補遺 §2 自己寫過:「建議清單要留存,不能當成一次性的中間產物。」
> **那句提醒寫下來了,而它要保護的東西沒有被保護。**
> 這是**憑記憶**這條路徑在同一份資料上失敗過一次的直接證據。

## 裁決(2026-08-19)—— 那一題的答案

> **「無法判定」的比例就是門檻,而門檻放在「可判定率」上。**
>
> ```
> 可判定率 = (真陽 + 誤報 + 刻意 refuse) ÷ 總筆數      >= 90%
> ```
>
> 「無法判定」**進分母、不進分子**。
> 轉正要**同時**滿足三條:`已分類 ≥ 10`、`假陽率 < 5%`、`可判定率 ≥ 90%`。

理由:

> **36% 判不出來的規則,它的 0% 假陽率不代表它準,
> 只代表我們只看了它願意讓我們看的那部分。**

**選項 (a)(未判定 > 0 就不可轉正)隨之解掉**:可判定率長期低 = 證據不足,
本就不該自動轉正;而票 68 落地後新紀錄可判定,比例會自己爬上來 ——
所以這不是一條「永遠擋住 R7」的規則,是一條「**擋到證據夠為止**」的規則。

### 90% 這條線畫在哪(照票 34 的先例寫)

**線畫在實測證據的邊界上,不是猜一個好聽的數字。**

| | 值 | 它是什麼 |
|---|---|---|
| 明顯不夠的那一側 | **64%** | 2026-08-19 量化 R7 的實況(130 / 202) |
| 顯然足夠的那一側 | **100%** | 全部判得出來 |
| 畫線處 | **90%** | 容得下一成雜訊,容不下一整群系統性盲區 |

> ⚠️ **這個數字沒有跨規則的實證支撐** —— 目前只有 R7 一條有夠多的樣本。
> 它是一條**保守的預設**,不是量出來的最適值。**明寫,不假裝它是量出來的。**

**什麼條件重畫**:當**第二條規則**累積到 ≥100 筆且完成分類時,
拿兩條的可判定率分佈回來重評。

> **重畫的依據是分佈,不是誰被擋住了。**
> (票 34 的同一句:證據邊界往前移一格,線才跟著移 ——
> 而不是去爭論「這條規則應該要過」。)

## 落地(2026-08-19)

紅燈先行:先紅 11 條 → 實作 → 該檔 58 條全綠、全套 912 passed。

| 改 | 內容 |
|---|---|
| `CLASSES` | 加 `"7": "無法判定"` |
| `UNDECIDABLE_CLASS` / `MIN_DECIDABLE_RATE` | 新增具名常數(門檻要看得見、改得動 —— 票 34 先例) |
| `promotion_status` | **三個分母**:`total`(含未判定)/ `classified` / `decidable`;新增 `unclassified`、`undecidable`、`decidable_rate`;`promotable` 加第三條 |
| `print_status` | 每條規則兩行:計數行(含**未判定**與**無法判定**)+ 判定行(假陽率、可判定率) |

**假陽率的分母改了**:由 `classified` 改為 `decidable`。
有測試把兩者的差別釘死(5 筆誤報 + 5 筆無法判定:舊算法 50%、新算法 **100%**)——
少了它,「不進分母」這句話會退化成註解。

**三條閘門各自都能單獨否決**,有一條測試逐條驗過(只差筆數 / 只差假陽率 /
只差可判定率),否則其中一條會是裝飾。
外加一條正對照(三條全滿足 → `可轉正`),否則「永遠回 False」的實作全綠。

**釘住 (c) 那個漏的那一條**:把餘量全標「無法判定」之後
(`已分類 202/202`),仍然**不可轉正** —— 因為它們不進 `decidable`。
少了這條測試,(c) 會退化成 (d)。

## 追加(2026-08-26,裁決三):**同一族第三層 —— per-rule 的零分類**

### 現象(量化 8/26 實測)

```
影子日誌 476 筆,已分類 130
R7  總 400  已分類 130  未判定 270 …
(表上只有 R7 一行)
```

**476 − 400 = 76 筆對不上。** 那 76 筆不是被歸進 R7,是**整行沒有印出來**。

### 根因

`promotion_status` 先算全量 `totals`(每條規則各幾筆),
但 `per` 只在遇到**有 `classification` 的紀錄**時才 `setdefault` 建鍵;
而 `print_status` 走 `for rule in sorted(per)`。

> **一條規則只要一筆都沒分類過,它在表上就不存在 ——
> 與「這條規則從來沒有記錄過」逐字相同:都是不存在。**

### 判準句

> **這是同一支工具、同一族的第二次。** 票 63 才剛修過「讀取失敗偽裝成空日誌」,
> `TestDStatusSeparatesEmptyFromUnclassified` 修的是**整份日誌**那一層;
> **per-rule 那一層原地不動。**
>
> **修好一層之後,要問的是下一層有沒有同一個洞。**
> 這一次沒有人回頭問 —— 是靠對帳時「476 與 400 對不上」才撞出來的,
> 而**兩個數字剛好都被印出來是運氣,不是設計**。
>
> 而它為什麼是必修:**這份輸出就是 9/15 晉升決策的依據。**
> 一條有 76 筆待判的規則看起來像不存在,決策者不會知道有東西要判 ——
> **留白被讀成蓋章**,與那 72 筆是同一句話。

### 落地(2026-08-26)

修在 `promotion_status`(**不是列印層的旁路**):`totals` 裡的每條規則都
`setdefault` 進 `per`。理由寫在碼旁 —— 回傳值缺那條規則的話,
**任何別的消費者**(CI 檢查、批次卡工具)照樣看不到它。

`print_status` 對零分類的規則**單獨印一行**:

```
  R2   總  76  **零分類** -> 無資料(這 76 筆還沒有人判過)
```

走完整格式會印出「假陽率 0.0% 可判定率 0.0% -> 留影子」——
三個數字全是**除以零的預設值**,而它們看起來與「量過了,結果是 0」一模一樣。
**不能在修這個病的同一支函式裡又製造一次。**

紅燈 5 條(含一條釘根因:`promotion_status` 的**回傳值**要有那條規則,
不是只有輸出有),另一條負控原本因「讀到幾筆」不同而假綠,
已收緊成斷言 `R2 in out_with and R2 not in out_without`(F-103)。

## 追加(2026-08-26,裁決六):**可判定率的分母是 per-rule,不是整份日誌**

```
MIN_CLASSIFIED = 10        MAX_FALSE_POSITIVE_RATE = 0.05        MIN_DECIDABLE_RATE = 0.90
```

`d["total"] = totals.get(rule, …)` —— **是該規則的 total**。

對 R7(total = 400):

```
可容忍的「無法判定」上限 = 400 × (1 − 0.90) = 40 筆
```

**不是 47。** 47 來自 `476 × 0.10`,那是拿**整份日誌**當分母。
