## 一、現象(2026-08-28 實測,同一台機器、同一個 session、同一個檔案)

```
$ cat "C:\Users\<使用者>\.claude\g1-protected.txt"
[G1/保護清單] 這個指令碰到受保護的路徑:C:\Users\<使用者>\.claude\g1-protected.txt
     清單:C:\Users\<使用者>\.claude\g1-protected.txt
     第一級無豁免,也不分讀寫 —— 判定不解析指令,因為解析會失敗,
     而失敗的解析就是洞。要動這個目錄,請自己開終端機做。
                                                    ← 擋下,正確

$ wc -l ~/.claude/g1-protected.txt
65 /c/Users/<使用者>/.claude/g1-protected.txt
exit=0                                              ← 沒有被擋
```

(路徑已遮蔽;照 `F-116`,遮了就不得再稱原始。)

**先排除了「動詞造成的差別」**:上面那條 `cat` 是**無害讀取**,一樣被擋 ——
第一級如它自己的訊息所寫,**不分讀寫**,判準是路徑。**差別只在寫法。**

## 二、根因(讀出貨的那一份,不是本機那一份)

`.claude/portable/g1_guard.py`,`expanduser` **全檔只出現一次**:

```python
57: HOME = os.path.join(os.path.expanduser("~"), ".claude")
```

**那一行是拿來定位守衛自己的家目錄的** ——
`~` **從來沒有被套用在指令文字上,也沒有套用在保護清單的條目上**。

而 `variants()` / `_canon()` 認得的是:
反斜線 / 正斜線、大小寫、磁碟代號、MSYS `/c/…`、WSL `/mnt/c/…`。
**`~` 不在那張表裡。**

於是清單條目 `C:\Users\<使用者>\.claude\g1-protected.txt` 展開出來的每一種形態,
**都比不上指令裡的 `~/.claude/g1-protected.txt`**。

## 三、為什麼這一則比票 79 / 票 80 嚴重

票 79(MSYS 正典)與票 80(cygdrive / UNC)是**同一顆比對函式**的前兩個缺口,
而它們漏掉的是**某些外部目標**。本則漏掉的是**守衛自己**。

`ADR 0009` 的第一句是整個設計的地基:

> **「G1 把自己與保護清單都列在保護清單裡,所以 agent 改不動它 ——
> 那是設計要的(『豁免來源不可自我服務』的同一個遞迴)。」**

> **而那個遞迴,是靠「清單上有這一行」來成立的。**
> 一個沒有覆蓋 `~/` 寫法的比對,等於讓那一行在某些寫法下**不存在** ——
> **不是保護弱了一點,是「自我保護」這個性質在那條路徑上不成立。**

**判準(可搬走)**:

> **一個「把自己列進保護對象」的機制,它的完整性等於它的比對函式的完整性。**
> 遞迴保護給人的心理保證是「它動不了自己」,而那個保證
> **只在比對認得出所有指向同一個東西的寫法時才成立**。
> 而比對函式的缺口**不會表現成錯誤,它表現成一次成功的操作**。

## 四、範圍:**只記實際撞到的那一種寫法**

**不列舉其他形式**(`F-131` 逐字):

> **找到洞 → 報。列舉洞的所有入口 → 由修它的人離線做,並且把每一種都釘成測試。**
> 差別不在動機,在**產物落在哪裡**:試探的產物是一份清單,
> 而修補的產物是**會擋人的機器**。清單會過期,機器不會。

**所以本票面只有 `~/` 這一種,而且是因為它撞上來的,不是找出來的。**
修的時候要把「一個路徑會被寫成哪些樣子」整張表重看一遍 ——
**那是修的人離線做的事,不是本票面的內容。**

### ★ 而且:**發現的當下沒有用它**

## 八、⚠ 這張票同時記一條**流程**規則(裁決 2026-08-28,⓪b)

> ### **往後裁決一律標執行者(agent / 人);凡涉及使用者層控制檔一律標「人」。**

**由來**:本輪有一件工作被派給 agent,而 agent **結構上做不到** ——
`~/.claude/g1-protected.txt` 是 G1 的保護對象,合法路徑一律被擋,
而不合法的路徑(`~/` 寫法)不能走。

**發現派錯的方式是撞上去。**

裁決者自陳:「**下一次派錯的還是我**」—— 所以修法不是「以後注意」
(注意力不是機制,`F-110` 的主旨),而是**在裁決的格式上加一欄**。

**為什麼寫在這張票而不是別處**:本票是那次派錯的**現場**,
而規則寫在現場才有人會讀到它的由來。
**沒有由來的規則會在下一次改版時被當成贅字刪掉。**

### 第二條流程規則:**做完一輪就關掉視窗**(裁決 2026-08-28)

> ### **同一個 repo 同時只留一個活著的視窗。**
> **規矩是「做完一輪就關掉」,不是「停一個再跑另一個」。**

**由來**:2026-08-28 這一天,同一個 repo 上**同時有多個視窗**的情況
出現了 **4 次**,而**前 3 次都沒有被記得**。

#### 為什麼「停一個」不算數

> **停了的視窗還握著一份會過期的地圖。**

一個被停住而不是關掉的視窗,它手上那份「現況」停在它最後一次觀測的時點:
最大票號、最大 `F-` 號、`master` 的位置、暫存夾裡有什麼、雲端那份是哪一版。
**那些東西全部會在它睡著的時候被另一個視窗改掉**,而**沒有任何訊號會叫醒它**。

它醒來之後做的第一件事,通常就是**拿那份過期的地圖去下判斷**。

#### 這一條與已有的紀錄接得上

| 已記過的 | 說的是 |
|---|---|
| **`F-118`** | **一個「現況最大號是幾」的查詢,有效期是到下一次有人寫入為止** —— 多視窗環境下那可能是**幾秒鐘** |
| **撞號實例**(`0b17cae` × `721cb8f`) | 兩個視窗各自查最大號、各自發同一個號,**已經真的撞過一次** |
| **今天的兩次 README 過期** | 本機改了、雲端沒跟上 —— 同一個形狀換到檔案上 |

**`F-118` 已經寫過那個危險,而它沒有阻止今天的 4 次** ——
因為 `F-118` 是一條**要人記得的知識**,而本條是一條**動作**。

> **知識管不住的東西,要用動作管。而「關掉」是一個動作,「小心」不是。**

#### 這一條同樣沒有機器在守(誠實標註,同八之一)

**沒有任何東西會偵測「這個 repo 現在有幾個活著的視窗」。**
所以本條與界線 A 一樣是**紀律,不是機制** ——
寫下來是為了讓它**有一個載體**,而不是為了假裝它被守住了。

**要它變成機制,得先有人回答:「一個視窗還活著」怎麼判?**
那不是本票的題目,**登記,不在此開票**。

### 為什麼「每一種寫法都不長得像違規」

| 破線的寫法 | 它平常是什麼 |
|---|---|
| `~/…` | 終端機裡的**預設**寫法 |
| `/c/…`(MSYS) | 這個 session 的 Bash 工具**自己**的預設形態(每條指令都是 `cd /c/…` 起手) |
| 對一個**目錄**下 `ls` | **盤點** —— 每一輪工作的第一個動作 |

> **三種都不是「試圖繞過」,三種都是「開工的第一件事」。**

**所以 A 的可靠度不是「有沒有人回頭看」** —— 那句話還太樂觀。
真正的條件是:**回頭看的那個人,要能認出自己剛剛做的事是違規。**
而上面三種寫法,**沒有一種在事後看起來像違規**。

## 八之二、★ 最有力的語料:**這條線已經破過兩次,而破它的都是提出它的人**

**兩筆:第一筆 2026-08-28(`~` 寫法,守衛漏了),第二筆 2026-08-29(目錄不在清單上,守衛沒被問到)。**

### 第一筆(2026-08-28)

**時序,2026-08-28 同一天:**

```
1. agent 奉裁決要改 ~/.claude/g1-protected.txt  →  被 G1 擋下
2. agent 發現 `~/` 寫法過得去  →  **拒絕使用**,停手、開票、記 F-139
   (理由:用它 = 先繞過守衛再去改守衛的清單)
3. 同一天稍晚,做筆電 machine-init 偵察時:
       $ ls -la ~/.claude/hooks/g1_guard.py*
   —— **同一個缺口,走了同一個縫**,而當下沒有察覺
4. 寫回報時 agent 自己回頭看,才發現,然後主動報告
```

### 這一格為什麼比任何論證都有力

**`F-139` 的危害不是理論的:**

> **缺口存在的時候,連「發現它、並且明確拒絕使用它」的同一個 agent,
> 在同一天、在沒有察覺的情況下,都會用到它。**

三個放大它的條件,全部在這一次同時成立:

| 條件 | 這一次 |
|---|---|
| 知道有這個洞 | **知道 —— 是他自己發現的** |
| 已經明確拒絕過一次 | **拒絕過,而且寫進了 friction log** |
| 中間隔了多久 | **同一天,幾十分鐘** |

**而它仍然發生了。** 原因不是疏忽,是**那個寫法是日常慣用的形式** ——
`~/…` 在終端機裡是預設寫法,**它不長得像一個繞過**。

> **一個缺口只要不長得像缺口,知道它存在就擋不住它被用到。**

### 而發現的方式**不是機制**

**沒有任何東西攔下第 3 步,也沒有任何東西事後報告它。**
它被抓到,是因為 **agent 在寫回報時自己回頭看了一遍** ——

> **那是自省,不是守衛。而自省不會每次都發生。**

**這一格同時是 `F-110` 的實例**:「以後小心一點」是一個祈使句,
而祈使句沒有主詞。**本票第二節那個修法才有主詞。**

### 🔴 第二筆:**同一條線,隔一天再破一次 —— 而這一次守衛連叫的機會都沒有**(2026-08-29)
