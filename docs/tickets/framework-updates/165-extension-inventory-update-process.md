**狀態**：候選（方案 2 最低版本為設計基線；證據存放與核准紀錄寫入權限已裁；C1 等其餘設計題仍待裁；未授權實作）

## 問題

- R10 的 synced 名冊（`.agents/extension-inventory.json`）自 10/08 起八次不符：10/08、10/14、10/21、10/26、10/27、10/28（三次：A-o-R2、A-q-R、A-s-R）。形狀皆為「某一個 skill 的檔＋`manifest.json`」。〔實讀，票 158 D1／A-o-D1～A-s-R 報告與名冊 git 歷史〕
- `manifest.json` 13 筆皆帶 `updated_at`〔實讀，票 158 A-o-D2／R2 形狀審查〕。「每有一個 skill 更新，總清單就重寫」〔推測，來源與觸發機制未確認〕。
- 審查與登記之間，同步樹可能又有變動。10/28 實例：D2 審完到 R 開工約半天內，`manifest.json` 再變，`computer-use/SKILL.md` 也出現不符。〔實讀〕
- 每次都靠人工三站（D1 診斷、D2 形狀審查、登記），而且每次都卡住無關的 commit。票 158 A-o 因此卡了一天。

## 現況程序

1. **偵測**：pre-commit R10 擋下（混合 commit 以 HEAD 名冊比對使用者層同步樹）。
2. **D1 唯讀診斷**：前後快照、探針兩輪（間隔 ≥60 秒）、與前例比對。
3. **D2 形狀審查**：三道雜湊（讀前、分析用 bytes、讀後）；只出統計，不出內文。
4. **Jeff 核准**。
5. **登記**：A-o 檔退出暫存 → 一般 Edit 寫名冊 → policy-only commit → 探針 `verified=True`。
6. **接回**：重新 add、核對 index blob、提交原 commit。

## 待 Jeff 裁的設計題（只列，不決定）

1. 固定流程要做成一支腳本，還是一份 runbook。

4. 登記次數的計數基準：可查歷史，還是人工序數。
5. 同步的頻率、來源與觸發機制都未確認（B 項）；若要查，需要另外授權讀 mtime 或同步紀錄。本票所有「同步程序又跑一輪」的字樣，都只表示「同步狀態有變動」。

## 需求（只限本票名冊更新流程）

- U1 減少名冊更新時的反覆人工登記。
- U2 保存名冊變更的證據。
- U3 保存核准的證據（誰、何時、依據）。
- U4 名冊異常時，界定影響範圍。
- U5a 核准證據綁定一批特定檔案版本。
- U5b 名冊登記／提交時，只接受與核准證據相符的版本；不符則舊核准不得沿用。
- U6 中斷後保存已完成與待辦；接續以保存的證據與狀態核對為準，同一視窗不作安全保證。
- U7 自動化只做蒐集、比對、整理紀錄，不代表核准。

共通限制：不放寬 R10；不新增名冊欄位；不自動核准。

## 設計方向：方案 2 最低版本（v3）

**狀態**：Jeff 2026-10-28（美東）同意方案 2 為設計方向，最低版本為設計基線；**未授權實作**（裁決助手記錄，非逐字原話）。

**原則**

- 人工啟動。影子日誌只是可選觸發來源，本版不做。
- 本票新工具**不改 index、不寫正式名冊、不提交**；只做讀、比、記與前後核對。
- 改 index、寫名冊、policy-only commit、接回，由 **VS 依授權照現有程序操作**，原有授權與守衛照舊。
- 本版不自動化 D2 形狀審查；工具只產差異與指紋。若要自動產形狀統計，須另列範圍、限制與讀取授權，且不取代人的內容判斷。

## 已裁：證據存放與核准紀錄寫入權限

Jeff 2026-10-28（美東）採用以下方案（裁決助手記錄，非逐字原話）。

**一、證據存放與保護**

- 完整證據包、存檔點、候選名冊、核准紀錄，存放於**持久、本機、不進版控**的位置。
- 位置須同時符合：①不會被例行清理；②能以固定相對路徑重新找到；③不進版控、不隨 push 公開。
- 依既有協定，.scratch/ 在收票時會列出留物並由 Jeff 手動刪除，不符合條件①。
- 公開版控只考慮另行檢查過的遮罩摘要；本版不做。
- 本版暫不做：串鏈、簽名、公開證據包。理由：沒有外部可信錨點時，串鏈可被整條重算，不是防竄改保證。

**二、核准紀錄寫入權限**

- 由代理人明確代記。每筆須寫明：「代理人代記、非 Jeff 逐字原話」、對應的聊天時間、所核准的證據包指紋。
- 每次都須 Jeff 對指定批次（指名證據包指紋）明確核准；不得概括授權。
- 限制：代記**不是獨立的人類授權證明**。工具依核准紀錄決定是否進入 S5 重驗與 S6 登記，偽造代記可能使流程進入登記。
- 現有緩衝（非防偽，只是多一道核對）：S6 仍由 VS 依授權、照原有守衛操作；S6' 登記後重新核對現場。
- 升級路徑：日後若做方案 3（程式強制核對核准），再另議 Jeff 親手寫入或簽名。
