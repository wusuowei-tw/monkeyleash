# 36 — R7 抽取失敗時放行:動詞認得、目標抽不到 = fail-open

**狀態:已關閉(2026-08-14)。** 四個 fail-open 全部關上,全套 663 passed。

## 兩處更正入檔(F-036:舊文保留,加註)

### 一、裁決給的 `if not bad:` 是**錯誤修法**

它會連合法的許可目標一起擋 —— `rm -rf /tmp/scratch`、`python x.py > /dev/null`、
`Remove-Item .cache/x.json` 都是「抽到目標、而目標被許可」,`bad` 同樣是空的。
照那一行改,R7 會開始每天擋掉正當指令,然後整條被關掉(F-031)。

**正解是三態**:抽到且有不許可的 → 擋;抽到且全部許可 → 放行;**一個都沒抽到 → 擋**。
所以要追蹤的是 `saw_target`,不是 `bad` 空不空。

> **`saw_construct` 與 `saw_target` 混成一個名字,就是這個洞的根。**
> 「有沒有寫入構造」與「抽到了目標沒有」是兩件事,而舊碼用同一個變數回答兩個問題。
> **命名的混同會變成判定的混同**,而且它不會在讀碼時跳出來 ——
> 那個變數在兩處各自看起來都合理。

### 二、症狀相同不代表根因相同

加上 `saw_target` 之後,`rm -- -weird.py` 兩條轉綠,而 `Copy-Item` 兩條**仍然放行**。
那個洞有**兩個根**:

| 根 | 機制 |
|---|---|
| **抽不到** | 運算元全被當旗標跳過 |
| **抽到了錯的** | PowerShell 只取第一個位置運算元 = **來源**;來源剛好許可 → 目的地從未被看 |

**只修前者會留下後者,而兩者的症狀是同一個字:放行。**
發現第二根的是測試,不是讀碼。

**排程**:**緊急插隊。** 活洞,而且是回歸。

**來源**:票 21 二審的覆蓋對照實測。

## 現象

```
rm -- -weird.py                        擋=False  目標=(空)
rm -rf --preserve-root -- -x.py        擋=False  目標=(空)
Copy-Item .cache/x.json pkg/thing.py   擋=False  目標=(空)   ← 寫進 pkg/thing.py
Move-Item .cache/x.json pkg/thing.py   擋=False  目標=(空)   ← 而且來源會消失
```

## 機制

`unallowed_write_targets` 只在 `not saw_construct` 時補佔位項。
**動詞認得時 `saw_construct=True`**,若運算元全被跳過 → `bad` 為空 → 回 `[]` →
`bash_write_violation` 的 `if not bad: return None` → **放行**。

兩條進入路徑:

| 路徑 | 怎麼觸發 |
|---|---|
| **G(`--` 後置)** | `--` 之後的檔名以 `-` 開頭,被當旗標跳過,運算元掃空 |
| **H+G(方向)** | PowerShell 分支**只取第一個位置運算元**,而 `Copy-Item A B` 的第一個是**來源**;來源剛好許可 → 不進 `bad`,**目的地從頭到尾沒被看過** |

## 歸因:這是票 29 的回歸

票 29 為了避免票 21 的垃圾目標(`-Value hello` 被當成寫入目標),
把 PowerShell 的抽取**收窄**成「只認可列舉的位置」。

**收窄本身是對的,錯在沒有配 fail-closed 的底。**
收窄之後「抽不到」變成常態(可列舉的位置沒命中就什麼都沒有),
而底層仍然是「抽不到 → 回空 → 放行」。

> ### 具名教訓候選
>
> **收窄抽取必須同時鋪底,否則「不亂猜」退化成「不擋」。**
>
> 收窄的動機永遠是**訊息品質**(別報垃圾目標),
> 而收窄的代價落在**涵蓋率**(報不出來的東西變多了)。
> 兩者不在同一個人的注意力裡:改的時候在看訊息,而破的是攔截。

**併 F-082 第三標本**:F-082 說「修好一個偵測器之後回頭重掃既有資料」,
這一則是它的規則側對偶 —— **收窄一個入口之後,回頭問誰接住漏下來的**。
票 29 當天問了「還有哪些同類動詞」(F-083),**沒問「抽不到的時候誰接住」**。

## 修法:三態,不是兩態

裁決給的 `if not bad:` **一行不夠** —— 它會連合法的許可目標一起擋:
`rm -rf /tmp/scratch`、`python x.py > /dev/null`、`Remove-Item .cache/x.json`
都是「抽到目標、而目標被許可」,`bad` 同樣是空的。

| 狀況 | 應有姿態 |
|---|---|
| 抽到目標,有不許可的 | 擋,點名 |
| 抽到目標,**全部許可** | **放行** |
| **一個目標都沒抽到** | **擋(解析失敗)** ← 現在是放行 |

所以要追蹤的是「**有沒有抽到任何目標**」(`saw_target`),不是「`bad` 空不空」。
`saw_construct`(有沒有寫入構造)與 `saw_target`(有沒有抽到目標)是兩件事,
而現行程式碼把它們混成一個變數 —— **那個混同就是這個洞的根**。

### 修一次不夠:`saw_target` 只關掉一半

加了 `saw_target` 之後,`rm -- -weird.py` 兩條轉綠,
而 `Copy-Item .cache/x.json pkg/thing.py` **仍然放行**。

原因:PowerShell 分支**抽到了東西,只是抽錯的那個** ——
它取第一個位置運算元(**來源**),而來源剛好許可,
於是 `saw_target=True`、`bad` 空 → 放行。**目的地從頭到尾沒被看過。**

所以第二刀是**取所有位置運算元,不只第一個**。
那不會把 `-Value hello` 的 `hello` 抓進來 —— `-Flag` 分支已經連值一起跳過,
走到那裡的只有裸的位置運算元。

> **教訓的第二層**:第一刀補的是「抽不到就擋」,而這個洞有一半是「**抽到了錯的**」。
> 兩者的症狀相同(放行),根因不同 —— 只修前者會留下後者,而測試會告訴你。

### 修完的實測

```
rm -- -weird.py                        擋 ✓  (解析不出寫入目標)   ← 誠實,不捏造路徑
rm -rf --preserve-root -- -x.py        擋 ✓  (解析不出寫入目標)
Copy-Item .cache/x.json pkg/thing.py   擋 ✓  pkg/thing.py         ← 點名真正被寫的那個
Move-Item .cache/x.json pkg/thing.py   擋 ✓  pkg/thing.py
cp .cache/x.json pkg/thing.py          擋 ✓  pkg/thing.py         ← POSIX 對照不變
```

`.cache/x.json` 沒有出現在訊息裡 —— 它是許可目標,被正確過濾掉了。
**過度回報的疑慮在許可清單這一層就消掉了**,不必等票 21 的方向標注。
