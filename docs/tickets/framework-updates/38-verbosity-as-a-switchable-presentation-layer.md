# 38 — 白話段詳略做成可切換的展示層

**排程**:**排隊,不動工。** 只保存構想。

**動工條件:出現第二個使用者。** 在那之前這是一個為想像中的讀者做的抽象 ——
也就是 code-review 的 smell 清單裡那條 Speculative Generality。
一個使用者的偏好用改一行文字就能調,不需要一層機制。

**來源**:票 37 落地時提出。票 37 把回報格式寫死在 `CLAUDE.md` 框架段,
硬上限 5 行、比喻只解釋一次 —— 這些數字對第二個讀者未必合適。

## 構想

白話段的**詳略程度**做成可切換:同一份證據,同一套紀律,只換前面那段講多細。

## 形狀約束(這才是本票要保存的東西,不是「做一個開關」)

### 1. 可切換的只有詳略,核心紀律不進樣式檔

**不可切換的三條**(被擋即停 / 附原始擋下訊息 / 不用宣稱句)**必須留在
`CLAUDE.md`**,不得搬進任何樣式設定。

理由:一旦它們住在樣式檔裡,「換一個回報樣式」就等於「靜默關掉安全網」——
而那是 fail-open,是這套東西已經記錄過三次的同一個形狀。

**判準留在這裡**:任何做成可切換的東西,先問「關掉它會不會讓別的規則失效」。
會的話它不是展示層,是判定邏輯,不得切換。

### 2. 實作必須一次做完,半套會斷腳

若走 output style 路線,**三件事同一批做完**:

1. 樣式檔本身,frontmatter **必須**有 `keep-coding-instructions: true` ——
   漏了會**取代**內建工程指令而不是附加,而且不報錯
2. settings 的 `outputStyle` 指向它
3. **portable-manifest 補一行分類** —— 這是最容易漏的那一件

漏第 3 件的後果(票 37 已盤點):`.claude/settings.json` 標 `copy` 會散佈,
而 `.claude/output-styles/` 不在該表任何前綴內、`in_scope()` 為 False、
`uncovered_neighbours()` 也照不到它 → 下游拿到一個**指向不存在樣式**的設定,
**全程無訊息**。

上游有一道保險:`test_upstream_manifest.py` 會對未分類的追蹤檔案紅。
**但那道紅只存在於上游**(該測試自身標 `skip`,不出貨)。

### 3. 對外散佈的形狀多半是 plugin,不是裸 output-styles 資料夾

裸資料夾靠 sync 帶,而 sync 帶的是 manifest 涵蓋的東西 ——
上一節那個「兩半分住兩張表」的問題會一直在。

plugin 打包把樣式與其宣告放進**同一個發布單位**(`plugin.json` 的 `outputStyles`
欄位、`output-styles/` 目錄),兩半綁在一起走,不會只到一半。

代價:需要 marketplace 或 `--plugin-dir`,是新的基礎設施;
且使用者層的 `plugins/` 標 `never`,不隨機器搬 —— 換機器要重裝。

## 怎樣算做完

- 條件成立(第二個使用者出現)才進入評估
- 若做:三件事同批交付,缺一不算完成
- 不論做不做,**核心紀律留在 `CLAUDE.md` 且不可切換**這條不得被協商掉
