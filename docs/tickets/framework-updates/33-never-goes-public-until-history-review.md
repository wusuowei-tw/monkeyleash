# 33 — agent-gates 立「轉公開前置 = 歷史審查」,並預先登記已知項

**排程**:穿插。**無紅燈**(ADR + 登記)。

**來源**:換機器演練卡點 #16。

## 現象

票 22 的演練文件把**真實備份資料夾名**寫進版控,並已推上遠端。
違反 `machine-init.md` 自己的紅線(「本檔所有範例都是佔位符」)。

**原文遮了使用者名稱、沒遮資料夾名。**

> **遮一半比完全沒遮更容易過關。**
> 完全沒遮會被 leak_scan 的個人 pattern 攔下;遮了使用者名稱之後,
> 剩下的資料夾名不在當時的 pattern 裡,於是**掃描全綠**。
> 部分遮蔽騙過的不是人的眼睛,是**機器的比對** —— 而人看到「有遮」就放心了。

## 怎麼撿到的

**#13 修好之後,新 pattern 回頭照出來的。** 不是演練腳本要找的。

判準因此成立:**修好一個偵測器之後,回頭重掃既有資料。**
新規則的第一次全量掃描,問的不是「以後會不會再犯」,是「**以前犯過幾次**」。
已立為 CLAUDE.md 常駐檢查項(標本見 F-082)。

## 決定(裁決 2026-08-14)

1. **不改寫歷史。** 桌機當時凍結中,協調成本大於收益;而 repo 是 private,
   暴露面就是「有權限的人」,與現狀相同。
2. **改立門**:agent-gates 比照 TradingAgents 的 ADR 0011,
   立「**轉公開前置 = 歷史審查**」。
3. `#16` 的資料夾名 **@`f0c17fe`** 預先登記為該審查的**已知項** ——
   將來真要轉公開時,這一筆已經在清單上,不必重新發現。

## 為什麼是「立門」而不是「現在洗」

與 TradingAgents ADR 0011 同一條不對稱:

- 保持私有、將來想公開 → 那時再做歷史審查,成本可控
- 先公開、之後發現有東西 → **收不回來**

**選擇要看不對稱,不是看機率。**

差別在於 agent-gates 的立場更微妙:**這個 repo 原本就是為了公開而寫的**
(machine-init 的紅線寫著「這個 repo 要公開」)。所以本 ADR 不是說它永不公開,
而是說**公開這件事現在有一道前置**,而那道前置是逐 blob 的歷史審查。

## 要產出什麼

- `docs/adr/00NN-going-public-requires-history-review.md`
  - 前置條件按順序:全樹掃描乾淨 → **全歷史掃描乾淨** → 才討論改寫要不要做
  - 掃描要用**當時的**上游 `leak_scan`,不是寫 ADR 時的版本
  - 已知項清單,首筆:`#16` 的備份資料夾名 @ `f0c17fe`
- 已知項清單放哪要想一下:**它本身列的就是敏感字串**。
  建議只記「commit sha + 哪一類」,**不記字串本身** ——
  與個人 pattern 清單不進版控同一個理由。

## 怎樣算做完

- ADR 落地,前置條件可執行(不是「要小心」這種話)
- 已知項清單的**格式**不洩漏它要保護的東西
- 與 TradingAgents ADR 0011 互相引用(同一條原則的兩個實例)
