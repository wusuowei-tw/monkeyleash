### 3-1 兩台各出一份「指紋清單」(**不出原文**)

兩台各跑同一段(**輸出只有條數與雜湊前 10 碼,沒有任何 pattern 內容**)。
**10 碼不是 12 碼** —— 六之一記的三個期望指紋是 10 碼,長度不一致會產生
一組永遠對不起來的數字,而對帳的人會去找一個不存在的缺陷(`F-109`):

```
python -c "import hashlib,io,os; p=os.path.expanduser('~/.claude/leak-patterns.local.txt'); L=[l.split('#',1)[0].strip() for l in io.open(p,encoding='utf-8')]; L=[l for l in L if l]; print(len(L)); [print(hashlib.sha256(l.encode('utf-8')).hexdigest()[:10]) for l in sorted(L)]"
```

**實測結果(2026-08-28,裁決者側):桌機 18 條、筆電 19 條。**

> ### 🔴 **而差集是 5 條,不是 1 條。**
>
> `19 - 18 = 1` 會讓人以為「筆電多一條」。**實際是筆電獨有 3 條、桌機獨有 2 條。**
> **數字對得上不代表集合相同** —— 票 85:123 的硬條件,在這裡第二次兌現。
> 照「誰多誰少」去補,會補錯 3 條又漏掉 2 條,而**兩邊的條數看起來會變成一樣**。

### 3-2 比對 —— **不是看誰多,是看兩邊的差集**

把兩份指紋清單放一起,取**雙向差集**:

- 只在筆電有的 → **要合併回桌機**(這裡面就有 K1 / K2 那一條)
- 只在桌機有的 → **筆電缺的**,合併之後兩邊要一致

> ### ⚠ **合併不是覆蓋。**
> 桌機 18 條、筆電當時 16 條起算,而**兩邊各自長過**
> (票 84 §4-5 在桌機加了舊帳號那一條:35 → 43 行)。
> **照「還原」做會把桌機這 18 條裡的新增直接蓋掉,而那是無聲的。**

### 3-3 合併:**一行一次,用 `Add-Content` 追加**

> ### ⚠ **更正(2026-08-28):本節原本寫「走 age 匯出/匯入」。那是錯的。**
> 舊文保留在本票的「三之一」,照 `F-036`。

**做法(與已經發給 Jeff 的那份一致):**

對 3-2 算出來的「只在筆電有的」每一條,在**桌機**上各下一次:

```
Add-Content -Path "<家目錄>\.claude\leak-patterns.local.txt" -Encoding UTF8 -Value '<那一行>'
```

**一行一次,共三次。** 本次的差集是 **3 條**(見「六、合併後驗收」)。

- `-Encoding UTF8` 不是可選的 —— `Add-Content` 預設走系統 ANSI 碼頁,
  非 ASCII 的資料夾名寫進去會變成別的位元組,而 pattern 從此永遠打不中。
- 用**單引號**包 `-Value`:PowerShell 的雙引號會展開 `$`,而 regex 裡有 `$`。
- **追加,不是覆寫。** 桌機自己那 18 條一個字都不動。

> ### 🔴 **前提:這條指令只在【檔案已經存在】時是安全的。**
>
> 實測(2026-08-28):`Add-Content -Encoding UTF8` 對**已存在**的檔案追加 ——
> 不寫 BOM ✓;對**不存在**的檔案 —— **建出一個帶 BOM 的檔**(`239,187,191`)。
> 而 `_read_patterns` 用 `utf-8-sig` 讀,BOM 本身不會出事,
> **但若有人改用 `Set-Content` 或在新機器上第一次建檔**,
> docstring 警告的那個失效就會發生:**第一條 pattern 從此永遠不命中,完全無聲。**
>
> **在新機器上第一次建這個檔,用 `[IO.File]::WriteAllLines`,不要用 `Set-Content`。**
> **驗收**:前三位元組**不得**是 `239,187,191`。

### 3-4 為什麼**不**走 age(回答「有沒有不能取代的理由」:**沒有,而且它是錯的工具**)

| | age 匯出/匯入 | `Add-Content` 追加 |
|---|---|---|
| 語意 | `user_layer.import_` 的 docstring 逐字:「**把匯出的內容放進新機器的 `~/.claude/`**」—— **那是覆蓋** | **追加**,桌機既有的 18 條不受影響 |

| 前置 | 要 age 公鑰 + **私鑰**,而私鑰是紙本(`machine-init.md` 硬條件二) | 無 |
| 保密面 | 明文不經螢幕 | 明文經過螢幕與剪貼簿 —— **但兩台都是 Jeff 自己的機器,那個字串本來就在兩台上** |

> **age 的價值在「搬一整份到一台沒有它的機器」,不在「把 3 行併進一份已經存在的清單」。**
> 票 39 裁決 2 鎖的是「**真實字串不進版控**」,而 `Add-Content` 沒有違反那一條 ——
> 它寫的是使用者層檔案,不是版控。

**⇒ 統一成 `Add-Content`。** 本節取代原本的 age 寫法。

| **要防的東西不在這裡** | pattern 是好的,這棵樹剛好乾淨 | 要一個**已知會被它打中**的樣本 —— 而那要人知道它在防什麼 |
| **它本身就壞了** | 例如寫壞的 regex、或帶了 BOM(`_read_patterns` 檔頭記過這個形狀:BOM 會讓第一條 pattern 從此永遠不命中而**完全無聲**) | 同上 |

> ### **一條從來不命中的 pattern,與一條不存在的 pattern,在報告上長得一模一樣。**

**⇒ 不刪。** 裁決逐字:

> **那會把一個未解的問題變成一個消失的問題。**

**刪掉之後**,「A 從來不命中」這件事就不再有載體 ——
下一次有人數個人 pattern 條數,會看到一個乾淨的 20 條,
**而沒有任何東西記得曾經有過一條不會叫的**。

**同族**:`g1_verify.py` 的 `KNOWN_GAPS` 桶(把缺口編碼成**有票號的已知項**,
而不是刪掉);以及本表「期望值」那一節的第三種語意 ——
**留白比蓋章誠實,而刪除連留白都不是。**

**要分辨它需要什麼**:一個 A **應該**打中的樣本。而那要人知道 A 在防什麼,
所以**這一格與 `friction-log.md:1626 / :1639` 那兩行是同一次人工判讀**,
一起做。

## 六之二之二、✅ 查證:**`leak_scan` 認註解行,但只認【整行】的**(2026-08-28 實測)

**問題**:三條要「註解掉不刪除」,而我們比指紋時用的 `^\s*#` 過濾是**我們自己的**,
不是 `leak_scan` 的剖析器。**要驗不要推。**

**做法**:合成 pattern(`ZZ*`,不碰真的那份),餵給 `_read_patterns` + `RuleGroup`。

```
檔案 6 行,其中 4 行看起來像 pattern
_read_patterns 讀出:2 條  ->  ['ZZACTIVE', 'ZZINLINE']

ZZACTIVE0001   活的 pattern      -> 命中      OK
ZZHASHED0002   行首 # 註解掉      -> 不命中    OK
ZZINDENT0003   縮排後 # 註解掉     -> 不命中    OK
ZZINLINE0004   行內 # 註解        -> 不命中    <- 🔴 但理由完全不同
```

### ✅ 結論一:**行首 `#`(含前面有空白)確實會被忽略 —— 註解掉可行**

`_read_patterns` 逐字:`if not line.strip() or line.lstrip().startswith("#"): continue`。
**實測與原始碼一致。**

### 🔴 結論二:**註解必須是【獨立的行】,絕不能寫在 pattern 後面**

行內註解那一條 **`_read_patterns` 照樣收下了** ——
它仍然是一條**活的 pattern**,而註解文字被編進 regex,
於是它變成一條**永遠不會命中的死條目,而且完全無聲**。

> ### **`# 在行首 = 停用;`#` 在行尾 = 悄悄變成一條不會叫的規則。**
> **兩者在檔案裡看起來幾乎一樣。**

**同族,而且原始碼自己記過**:`_read_patterns` 的 docstring 警告 BOM ——
「BOM 會變成第一條 pattern 的一部分,那條規則從此永遠不命中,
少了一條規則而且**完全無聲**」。**行內註解是同一個失效,不同的成因。**

### 結論三:壞掉的 regex **不會靜默**

`RuleGroup.__init__` 走 `re.compile`,語法錯直接丟 `re.error`
-> `leak_scan` 整支失敗 -> **fail-loud** ✓。所以打錯字不會變成一個安靜的洞。

### ⇒ 給 Jeff 的寫法(**執行者:人**;本輪只查證,不動手)

**每一條註解成三行 —— 說明在上、停用的 pattern 獨立一行:**

```
# --- 2026-08-28 停用(票 91):自筆電合併,在【這台機器】上誤報 ---
#     B 打中 31 處 / 10 檔;C 打中 4 處 / 2 檔;A 打中 0 處
#     35 處經裁決者逐一判定【全部不敏感】;27/31 那一行含 C:\projects
#     不刪除:刪掉會把一個未解的問題變成一個消失的問題
# <原本那一行,整行照抄,前面加 "# " 與一個空格>
```

**⚠ 三條硬性寫法要求:**

1. **`#` 一定在行首**(前面可以有空白,但 pattern 不能在 `#` 之前)
2. **不得把說明接在 pattern 後面** —— 那會留下一條活的死條目
3. **原本那一行整行照抄,不要順手改** —— 之後要復原時,
   **改過的那一行復原不回原來的行為**,而復原的人不會知道

**驗收(改完跑一次)**:`load_patterns()` 的個人組應為 **18 條**(21 − 3)。
條數不對就是有一條沒被註解掉,或有一條被連帶弄壞了。
