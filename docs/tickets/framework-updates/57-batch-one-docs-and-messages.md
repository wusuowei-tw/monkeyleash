## 卷首:傳遞層也在做「基礎設施 = 特殊處理」(第五次)

**這一段不是本張的工作項,是本輪所有票共用的前提。** 批二立案時引用本節,不重述。

`sync.py` **完全不碰權威層**:

| 檔案 | 標記 | 後果 |
|---|---|---|
| `.githooks/pre-commit` | `skip`(`.agents/portable-manifest.txt:33`) | sync 不搬 |
| `bootstrap.sh` | `skip`(`:32`) | sync 不搬 |
| `.git/hooks/pre-commit` | 不進版控(git 設計) | 任何工具都搬不了 |

判定點在 `sync.py:463`:

```python
        mark = mark_for(rel, marks)
        if mark != "copy":
```

**所以同步再多次,下游的權威層都不會被修好、也不會被裝上。**

而本輪十項裡有三項 —— **①(install.py 不認識 hooksPath)、⑤(層數計數)、⑧(CI 守衛測試不可攜)** ——
要修的東西**全部住在 `skip` 桶**,而 `skip` 的語意就是「同步不管它」。

> **修好上游不會讓下游變好,而綠燈長得一樣。**

**這是「基礎設施 = 特殊處理」這個習慣的第五次,而這一次它在傳遞層。**
CLAUDE.md 的常駐檢查項記著前面幾次(`.claude` 整個在非原始碼清單、
`find_implementation` 跳過點開頭目錄、`scripts/` 在非原始碼清單),
共同根因寫得很清楚:

> **「基礎設施 = 特殊處理」這個習慣** —— 它在多數情境是對的(跳過 `.git` 省時間),
> 所以會被無意識套用;而閘門、hook、安裝器恰好全住在那些位置。

**前四次都在「判定層」:某條規則跳過了某類路徑。這一次在「傳遞層」:
某條運送管道跳過了某類路徑。** 形狀相同,受害者不同 ——
前四次的後果是「這個 repo 的規則有洞」,這一次的後果是
**「所有下游 repo 的規則永遠不會被修好」**,而且它不會出聲。

**每一筆 `skip` 都是一次「這個我不管」的宣告。** 那些宣告逐筆看都對
(每個 repo 的 CI 是那個 repo 的事實、每個 repo 的 hook 是那個 repo 的事實),
**合起來就是「框架管不到框架自己的傳遞」**。
與 F-066 同一個形狀:每一步都對,合起來是錯的。

## ⑦ 的現況證據(本張唯一動到程式碼的一項)

### 一、`_r7_head` 的「逐段」那句掛在 `if mixed:` 底下

`gate.py:679-685`:

```python
    if mixed:
        head += ("     **許可是逐段比對的**(`&&` / `;` / `||` 各算一段),"
                 "而這幾段不在清單裡:%s\n"
```

而 `mixed` 的定義在 `gate.py:708`:

```python
    mixed = any(seg_ok) and offenders
```

**`any(seg_ok)` 要求「至少有一段是許可的」。** heredoc 那條路徑上一段都不許可
(`python - <<'PY'` 的 `python` 不在 `BASH_ALLOWED_CMDS` 裡 —— 清單裡只有
`python -m pytest` / `python -m pip` / `python .claude\`),於是 `mixed` 為假,
**那句解釋一個字都不會印。**

F-097 記下的實測擋下訊息原文就是這個樣子:

```
[六站閘門/前哨] [R7][enforce] 這個 Bash 指令會寫到沒有被許可的位置((引號或跳脫使目標無法可靠切分))。
     請改用 Write / Edit。
```

**兩行,沒有「逐段」二字。**

### 二、訊息說的「各算一段」與實作切的東西不是同一件事

`gate.py:702`:

```python
    segments = [s.strip() for s in re.split(r"&&|\|\||;", cmd) if s.strip()]
```

`re.split` **對引號、heredoc 內文、跳脫一律無視**。訊息寫的
「`&&` / `;` / `||` 各算一段」讀起來像在講 shell 的指令分隔符,
而實作切的是**整條字串裡的每一個分隔字元**,包含資料裡的。

> **照訊息推論會得到「整條以 `git` 開頭就安全」,而實測不是。**

### 三、歸屬:票 13 那族,而票 13 修過的是另一條分支

票 13 的落地表(`13-r7-has-no-deletion-exit.md:168`)寫著
`| 1 | R7 逐段許可 | **A 修好** |`。**那次修的是 `mixed` 分支。**
heredoc 走的是 `not mixed` 那條,**沒被涵蓋** ——
所以這不是回歸,是**同一張票的涵蓋缺口**。

判準原文(`13-r7-has-no-deletion-exit.md:55`):

> **fail-closed 的訊息必須說出是哪一個前提沒滿足。**

### 四、修法邊界:只改訊息(票 13:70 的定調照樣適用)

> `- 不改判定邏輯,只改訊息。逐段比對維持原樣(它是對的)。`

**本張動的是訊息的「印不印」與「印什麼」,不動 `bad` 的算法、
不動 `segments` 的切法、不動任何回傳值。**

`if mixed:` 改成 `if offenders:` **是訊息的發出條件,不是判定** ——
`bash_write_violation()` 對同一條指令的擋/放結論在改前改後完全相同。
**這一句要寫在這裡,否則下一個讀 diff 的人會以為判定邏輯被動過。**
