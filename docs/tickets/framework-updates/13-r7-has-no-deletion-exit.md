# 13 —(已作廢,前提是錯的)R7「沒有刪除出口」

## 結論先講:R7 有刪除與改名的出口,是我把指令寫壞了

原本這張票斷言「R7 把寫入收口了,卻沒給刪除一條出口」,並據此把
`tests/test_install_defaults.py` 的改名、ADR 的 `F-` 改名都判為做不到。

**那個斷言是錯的。** 實測(2026-08-13,裁決者指出後):

```
git mv docs/adr/0013-... docs/adr/F-0013-...      -> 通過,無輸出
```

`git` 本來就在 `BASH_ALLOWED_CMDS` 裡。我先前寫的是:

```
cd "c:/Users/.../agent-gates" && git mv A B        -> 被 R7 擋
```

`bash_write_violation()` 的比對是**逐段**的:

```python
segments = [s.strip() for s in re.split(r"&&|\|\||;", cmd) if s.strip()]
if segments and all(any(seg.startswith(p) for p in BASH_ALLOWED_CMDS) ...):
    return None
```

第一段 `cd "..."` 不以任何許可前綴開頭 → 整條落出許可清單 →
掉進 `WRITE_CONSTRUCT` 檢查 → `mv` 命中 → 擋。

逐段比對本身是**對的**:少了它,`git status && rm -rf x` 會整條被許可。
錯的是我的指令形狀,以及我從一次失敗直接推論出「規則缺一條出口」。

## 真正的缺陷(移到本票範圍)

擋下訊息說的是:

> 這個 Bash 指令會寫入檔案,請改用 Write / Edit。

**那句話把人指向錯的修法。** 現場是「你的 `cd` 前綴讓許可清單失效」,
而訊息叫人去改用檔案工具 —— 而檔案工具**沒有**刪除/改名,
於是照著訊息做的人會得出「這件事做不到」的結論,然後發明一條繞路
(本票原本的結論:留著不刪,兩個檔案並存)。

這與 F-046 是同一個形狀:**擋得對,但訊息讓人去檢查一個沒問題的地方。**
代價在這裡具體化成一張寫錯前提的票、一個沒必要的重複檔案,
以及一條差點被改掉的守衛。

## 範圍

- R7 擋下時,若**某一段**命中許可清單而其他段沒有,訊息要指出是哪一段落出去,
  並提示「許可是逐段比對的」。現在的訊息完全不提這件事。
- 不改判定邏輯,只改訊息。逐段比對維持原樣。

## 怎樣算做完

- 擋下 `cd X && git mv A B` 時,訊息點名 `cd X` 是落出許可的那一段
- 擋下 `rm -rf x`(整條都不在許可清單)時,訊息維持現在的樣子
- 兩種形狀各一條測試
