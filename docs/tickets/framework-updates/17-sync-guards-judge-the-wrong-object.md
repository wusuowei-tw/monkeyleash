# 17 — sync 的兩道護欄各自判錯對象

量化 repo 盤點揭出。兩件都是**護欄本身**的缺陷,修畢量化才開窗。

## 一、`refuse_if_dirty` 判錯對象(第六例)

| | |
|---|---|
| 規則要問 | 我的寫入會不會**壓到未提交的變更** |
| 實際量 | **整棵樹**(含內嵌 repo 內部)有沒有髒 |

量化的 `data_collector` 是**內嵌 git repo**(gitlink,**無 `.gitmodules`**)。
它內部的髒在 sync 的寫入面之外 —— sync 從不寫那條路徑底下的東西 ——
但 porcelain 仍報 `modified content`,於是**永久拒絕**。

### 為什麼不能靠 `--ignore-submodules=dirty`

現行程式已經傳了那個旗標,而本機實測(git 2.53.0.windows.2)它**行為正確**:

```
內部 modified + untracked        -> --ignore-submodules=dirty 抑制(乾淨)
內部前進、外層未記錄 gitlink     -> 報 " M inner"(髒)
```

量化那邊卻永久拒絕,代表**旗標語意在不同 git 版本/組態下不一致**。
一道護欄的正確性掛在「哪個 git 版本」上,那個依賴本身就是缺陷:
它會在別人的機器上安靜地翻面。

### 修法:明確比對,不依賴旗標

外層樹狀態用 `--ignore-submodules=all`(完全不理內嵌 repo 的任何訊號),
gitlink 另外**逐條明確比對**:

```
HEAD 記錄的 sha  vs  index 的 sha    不同 -> 已 stage 未提交的 bump -> 髒
index 的 sha     vs  內部 HEAD       不同 -> 內部前進未記錄        -> 髒
內部 modified / untracked                                          -> 不算髒
```

兩個比對都是「**外層對這個 gitlink 的記錄還沒塵埃落定**」,
與 sync 的問題(會不會壓到未提交變更)對齊。內部狀態從不進入判定。

讀不到內嵌 repo(不是 git repo、權限問題)-> **fail-closed 當髒**:
問不出來不等於乾淨。

## 二、`unmigrated_friction` 對同號多則失明

現行實作用集合差:

```python
sh = set(HEADING.findall(來源))
th = set(HEADING.findall(目標))
return sorted(th - sh)
```

量化本地有**兩則 `## F-046`**(本地的 hook-session 那則 + 上游同號那則)。
集合把兩則塌成一員,於是 `th - sh` 把 F-046 整個消掉 ——
`F-047` 搬走之後 sync 會**放行,並靜默刪掉本地那則 F-046**。

**撞號正是這道護欄的獵物,而它被撞號打穿。** 這道護欄存在的唯一理由就是
「本地條目不能被覆蓋刪掉」,而它用的資料結構恰好對「同號多則」不可見。

### 修法

抽標題時保留**行號與重複**,任一側出現重複 token 就**拒絕**,
並點名是哪個號碼、在哪兩行(票 13 判準:說出是哪一個前提沒滿足)。

不自動判斷「哪一則該搬」—— 同號的兩則是**兩件不同的事**,
分辨它們需要讀內容,那是人的判斷。護欄的職責是讓它現形,不是替人決定。

## 怎樣算做完

- 內嵌 repo 內部髒 + 外層乾淨 → **放行**,且證明 sync 從不寫入內嵌路徑
- 外層髒 → 拒絕(不變)
- gitlink 內部前進未記錄 → 拒絕
- 目標有兩則 `## F-046` → 拒絕,訊息點名號碼與兩處行號
- 來源有重複號碼 → 同樣拒絕(兩側都驗)
