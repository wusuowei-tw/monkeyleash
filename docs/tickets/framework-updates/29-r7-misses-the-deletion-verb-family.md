# 29 — R7 漏掉 PowerShell 的刪改動詞家族,而 G1 只管專案外

**排程**:**第一張辦**(執行順序第 1)。活洞優先 —— 這是本批唯一「現在就能穿過去」的。
守衛設計變更,完整流程,紅燈先行。

**來源**:換機器演練卡點 #11(定級:高)。

## 現象

`R7` 的 `WRITE_CONSTRUCT` 收了 PowerShell 的寫入動詞 ——
`New-Item` / `Set-Content` / `Add-Content` / `Out-File` / `Clear-Content` ——
**漏掉 `Remove-Item` / `Move-Item` / `Copy-Item` / `Rename-Item` 整個刪改家族**。

而 G1 第二級**只管專案外**的破壞性動詞(`專案內刪除 exit=0` 是刻意的,
理由寫在 `g1_guard.py`:第二級必須寬鬆,否則每天擋幾十次然後被關掉)。

**兩層的空隙疊在一起:專案內用 `Remove-Item` 刪檔,同時穿過 R7 與 G1。**

## 這不是「多一個沒收到的動詞」

R7 的整條理由是**收口**:「入口收成一個,走檔案工具的話 R1–R6 全部適用」。
一個能繞過那個收口的動詞,讓 R1–R6 對它完全不適用 ——
**不是涵蓋少一塊,是那條路上沒有任何規則。**

而且方向特別差:漏掉的是**刪除**。寫入被漏掉還留著檔案可以事後看,
刪除被漏掉之後**沒有東西可以看** —— 與 G1 保護清單把備份排第一的理由同一條
(「原檔被刪、備份還在,復原得回來;備份被刪、原檔還在,**你不會立刻發現**」)。

## 怎麼撿到的(判準值得記)

**繞路撿到的,不是演練腳本要找的。**
當時探針四被 R7 搶答,我去找「哪個動詞能穿過 R7 以隔離 G1」時量到的。

**收了一個入口,就回頭問它的同類入口在哪。**
`WRITE_CONSTRUCT` 收寫入動詞時,沒有人問「PowerShell 還有哪些動詞會動到檔案」——
而刪、搬、複製、改名,每一個都動得到。已立為 CLAUDE.md 常駐檢查項(標本見 F-083)。

## 紅燈計畫

| # | 紅燈 | 守什麼 |
|---|---|---|
| 1 | `Remove-Item x.py` **被擋**(現行放行) | 核心紅燈 |
| 2 | `Move-Item a.py b.py`、`Rename-Item`、`Copy-Item` 各一條 | 同族不得只補一個 |
| 3 | 訊息點名**動詞**與**目標**,而不是含糊帶過 | 票 13 判準 |
| 4 | **反控**:唯讀 PowerShell(`Get-ChildItem`、`Test-Path`)照常放行 | 少了它,「一律擋 PowerShell」也會讓 1–3 全綠 |
| 5 | **反控**:既有寫入動詞的行為零變化 | 回歸網,不是宣稱 |
| 6 | G1 第二級「專案內刪除放行」**維持不變** | 那是刻意的寬鬆(g1_guard 的註解寫了理由);本票補的是 R7 那一層,不是把 G1 收緊 |

第 6 條是本票最容易做錯的地方:**看到洞就把兩層都收緊,會把 G1 第二級變成每天擋幾十次的東西,然後它會被關掉。** 洞在 R7,補在 R7。

- 訊息形狀與既有 R7 一致(點名、給替代路徑)
