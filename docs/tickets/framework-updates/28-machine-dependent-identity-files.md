# 28 — 分類表表達不了「機器相依的身分檔」

**排程**:執行順序第 2。守衛/資料設計變更,完整流程,紅燈先行。

**來源**:換機器演練卡點 **#13(定級:最高)** + **#2**。

## 標題句

> **檔案是好的 ≠ 它保護的是這台機器。**

## 現象(#13,實測)

使用者層分類表有四個桶,而**它們表達的是「怎麼搬」,不是「搬過去還準不準」**:

| 檔案 | 桶 | 意思 |
|---|---|---|
| `g1-protected.txt` | `human` | 腳本不碰,人工複製 + **逐條覆核** |
| `leak-patterns.local.txt` | `age` | 加密後**腳本照搬** |

**但兩者的機器相依性完全相同。** 保護清單列的是這台機器的實際路徑;
個人 pattern 列的是這台機器的使用者名稱、資料夾名、往來對象形狀。
**兩份都會在新機器上指向不存在的東西。**

演練實測:匯入之後,16 條個人 pattern **全是舊機器形狀,本機身分一條都沒涵蓋**。
而且:

- **警告不響**(那條警告只在檔案**缺席**時觸發,檔案在就不說話)
- **pattern 全數編譯成功**(語法沒問題,只是保護錯了對象)
- **掃描回 0**(沒有命中,因為它認不得這台機器的身分)

**三個綠燈疊在一起,而涵蓋率是零。** 這與票 25 的假保護、票 26 的假綠同一族:
每一層檢查都在回答「格式對不對」,沒有一層在問「**它保護的是誰**」。

## 現象(#2,同根)

匯出的 `settings.json` 帶著**舊機家目錄的絕對路徑**
(G1 掛載寫的是 `python "<家目錄>/.claude/hooks/g1_guard.py"`)。
原樣匯入 = machine-init 第 5 項的掛載指向一個不存在的路徑 =
**G1 整層靜默失效**,而檔案在、格式對、`settings.json` 讀得動。

**與 #13 是同一個缺口的兩個實例**,所以併一張票:
分類表說得出「怎麼搬」,說不出「**搬完之後誰要回頭看**」。

## 兩個候選方向(票內定奪)

1. **第五個桶**(例如 `review`):語意是「搬過去,但**匯入後必須人工覆核**」。
   `age` 與 `human` 保持原意,新桶只表達「機器相依」這個正交性質。
   風險:桶會變成兩個維度混在一個欄位裡(怎麼搬 × 搬完要不要看)。
2. **`age` + 覆核旗標**:維持四個桶,另加一欄或一個標記字尾。
   風險:表格式要改,而解析器與 `portable-manifest.txt` 共用(票 22 的重用結論)。

**判準不是哪個好寫,是:匯入完成之後,人有沒有被強制看到那份清單。**
`import_` 已經有「人工步驟未完成不回報成功」的機制(票 22 紅燈 6),
新桶/旗標應該掛在**同一個出口**,而不是另開一條提醒管道 ——
兩條提醒管道會分岔,而分岔的那天不會有人發現。

## 紅燈計畫

| # | 紅燈 | 守什麼 |
|---|---|---|
| 1 | 標為機器相依的項目,**匯入後出現在待辦清單裡**(現行不出現) | 核心 |
| 2 | 待辦清單**點名該項**與**為什麼要覆核**,不是含糊一句 | 票 13 判準 |
| 3 | `settings.json` 含**非本機**家目錄絕對路徑 → 被標示 | #2;這一條可獨立於桶的設計先做 |
| 4 | 個人 pattern 清單「全部不命中本機身分」→ **出聲**(現行靜默回 0) | #13 的核心觀測 |
| 5 | **反控**:機器無關的項目不得被誤標成要覆核 | 少了它,「全部都要覆核」也會讓 1–4 全綠,而那等於沒有分類 |

第 4 條要小心設計:「一條都沒命中」不必然是錯(乾淨的機器本來就不該命中)。
**可測的形狀是「pattern 清單裡的具體 token 一個都不出現在本機的身分面上」**,
而不是「掃描結果為空」。這一條的紅燈怎麼寫,是本票最需要想清楚的地方 ——
寫錯會變成一條吵鬧而無意義的警告,然後被關掉(F-031)。

  不必解決 —— 但不能繼續假裝不存在
