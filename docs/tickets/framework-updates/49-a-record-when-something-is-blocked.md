## 現況證據

### 頭條一:沒有通用的攔截帳本

全 repo **唯一**一筆有紀錄的實際攔截是 **R3**
(`.dev/gate-exemptions.jsonl`,`outcome=blocked`,`blocked_by=R3`)。

所以清冊的第 4 欄(「擋過沒有」)對多數規則**不可回答** ——
而原因是「**沒有東西在記**」,不是「查過沒有」。這兩者在表上長得一樣。

### 頭條一之二:**被批准的豁免也有一半沒有紀錄**(2026-08-18 加入,票 57 實測)

前一段講「攔截沒帳本」。這一段講**同一本帳裡,兩條豁免待遇不同** ——
而少的那一條是**放行**的那一條。

**實測**(票 57 ⑦ 那一輪,對 `gate.py` 與 `manifest.py` 各做了編輯):

| 豁免 | 觸發的檔案 | 進帳本? | 程式位置 |
|---|---|---|---|
| **R2 自我修改**(`GATE_SELF`) | `.claude/hooks/gate.py` | **是** —— 4 筆,`reason: gate-self-modification`、`outcome: granted` | 記帳走 `log_exemptions` |
| **R3 legacy 清單** | `.claude/portable/manifest.py` | **否 —— 一筆都沒有** | `gate.py` 的 R3 legacy 分支:`if r in legacy_no_redlight(): return None` |

那兩行直接 `return None`,**不進 `bucket`**,所以 `log_exemptions()` 收不到它。

> **擋下來的事你會看到(commit 失敗),放行的事你不會。**

`.agents/legacy-no-redlight.txt` 現在有 **9 個檔案**靠它繞過 R3 **整條**
(紅燈紀錄 + 測試檔存在,兩半都免)。**每一次繞過都沒有留下任何紀錄。**
問「這半年 legacy 豁免被用了幾次、用在哪些檔案上」——**無法回答**,
而原因與頭條一完全相同:**沒有東西在記**,不是查過沒有。

#### 附帶問題(本張要回答,不是順帶提一句)

**為什麼 `GATE_SELF` 記帳而 legacy 不記?**

兩條都是「這個檔案免受某條規則管」,性質同類,待遇不同。
**最可能的解釋是設計時只想到前者** —— `GATE_SELF` 是寫 ADR 0004 時
連同帳本一起設計的,legacy 清單是票 26 後來補的,而補的時候
**沒有人問「這條豁免也要記嗎」**。

若屬實,那不是「legacy 漏了記帳」這一個缺口,而是
**「新增一條豁免時,沒有任何東西提醒它要接上帳本」** ——
下一條豁免會用同樣的方式漏掉。**本張要處理的是後者。**

### 頭條二:當時的設定也沒有紀錄

F-083 掃出 **9 處**「決定規則行為卻不進版控」的檔案。

> **每一次判定,都是「一份不進版控的設定」對「一份不進版控的輸入」做出的,
> 而結果也不進版控。三樣缺一就無法複現,而現在三樣都缺。**

唯一例外是 `.dev/gate-exemptions.jsonl` —— **它進版控,而它剛好就是唯一留得下證據的那一個。**
兩件事是同一件事的兩面。

### 為什麼範圍是「被擋」而不是「每一次判定」

輸入**不是均勻缺失的**:

| 判定結果 | 輸入後來去了哪 |
|---|---|
| 通過 | 變成 commit —— **留得下來** |
| 被擋(pre-commit) | **從未落地** |
| 被擋(前哨) | **那筆寫入根本沒發生過** |

> **輸入唯一留不下來的情況,正是最想事後複驗的那一種。**

通過的已經有紀錄(commit 本身),被擋的一筆都沒有 —— **而它們是全部的爭議來源。**

### 那筆紀錄要帶三樣

**設定指紋 + 被拒的輸入 + 擋下的理由。**

### 先例

量化 `dc-01`:「**內容不進版控、指紋進版控**」。
理由是**可複現性**,不是完整性 —— 少了它結論無從證偽。

指紋綁的是**那一次判定**,不是某個時間點;於是設定 / 輸入 / 結果同處一筆,
而那九個檔**不需要**進版控。

### 寫進哪個檔:**新檔 `.dev/intercepts.jsonl`,不併進 `gate-exemptions.jsonl`**

**兩個理由,都是硬的:**

1. **schema 不相容。** `exemption_record()` 的鍵是**豁免形狀**的:
   `file` / `module` / `declared_in` / `reason` —— 全部來自 `ex` 這個豁免物件。
   一次 R7 攔截**沒有 `file`**(它的觸發物是指令),四個鍵全部填不出來。
2. **會弄壞 `ledger_verify` 的鏈驗證。** 那支工具逐筆讀
   `content_hash` → `result_hash` 串成鏈,**逐段驗接續**(v2 的存在理由)。
   插進一筆沒有這兩個欄位的紀錄,鏈就斷在那裡 ——
   而那條鏈是票 58 / 票 47 三次有界突變的收尾依據。

> **把兩種語意塞進同一個檔,省下的是一個檔名,付出的是一支已經在用的驗證工具。**

### 欄位

```json
{"ts": "<ISO8601 UTC>",
 "rule": "R7",
 "at_commit": false,
 "cmd_sha256": "<sha256(指令位元組)>",
 "cmd_verb": "<command_verb(指令)>",
 "cmd_len": 123,
 "message": "<擋下訊息全文>"}
```

- 前四個**沿用票 68 已經定案的指紋三欄**(`cmd_sha256` / `cmd_verb` / `cmd_len`),
  **不發明新的** —— 這樣影子側與 enforce 側的紀錄可以**用同一組欄位對帳**,
  9/15 評估時兩邊的樣本能合併看。
- **不記指令原文**,照票 68 的裁決(指令可能含個人 token / 路徑)。
- `message` 記全文:分類時要判「擋得對不對」,而**規則碼判不出來**
  (票 31:114 已經記過這一格 —— 帳本存的是 `blocked_by` 規則碼、不是訊息全文,
  於是判不出是哪一種擋)。

### 失敗方向:**跟著 `log_exemptions` 走 fail-closed**

`log_exemptions` 記不下來時 `raise SystemExit(2)`,理由是
「記不下來還照給,等於給了一個沒有人看得到的豁免」。

**這裡方向相反但結論相同**:記不下來時仍然要**擋**(本來就要擋),
但要**多印一行說帳本壞了** —— 否則「擋了但沒記」會靜默發生,
而那正是本提案要消掉的東西。**不得因為記錄失敗就放行。**

### 要不要進版控 —— **裁決:不進版控,改納入控制檔備份清單(第十處)**

~~**要**,與 `gate-exemptions.jsonl` 同軌(票 31 已裁 `.dev/` 證據進版控)。~~
(F-036 保留舊提案。裁決 2026-08-26,三個理由逐條:)

**(a) 8/28 開源在即,`message` 全文會含本機路徑。**
進版控等於**天天撞 `leak_scan`** —— 而那不是「記了」,是**「記了但推不上去」**。
一個每次 commit 都被擋下的帳本,實際效果是沒有帳本,
**而它看起來像有**(檔案在磁碟上、筆數在增加)。

**(b) 誤擋頻率未知,可能每天大量 diff 噪音。**
而**噪音會讓人先關掉紀錄,再也量不到頻率** ——
這是一個自我拆除的機制:它要量的東西,正是會導致它被關掉的東西。

**(c)「海運會沒」該由備份解決,不該用版控代替備份。**
兩者解的是不同的事(版控解「誰改了什麼」,備份解「東西還在不在」),
**混用會讓兩邊都做不好**。

### 為什麼它們也是空白 —— **`gate-exemptions.jsonl` 是豁免帳本,不是攔截帳本**

`log_exemptions` 第一行:

```python
def log_exemptions(bucket, verdict, at_commit, content=None, tool=None):
    if not bucket:
        return
```

`bucket` 是 `check()` 填的「這次判定**用到的豁免**」。**空的就直接返回。**

> **而「沒用到豁免的單純攔截」是最常見的那一種。**
>
> 豁免是例外路徑 —— 大多數攔截根本不會碰到任何豁免:
> 一個站別不對的寫入、一個缺測試檔的 `.py`、一條寫到專案外的指令,
> 都是直接判違規,`bucket` 從頭到尾是空的。
>
> 所以這個帳本記到的是**判定過程中順道用掉的豁免**,
> 而不是**「擋了什麼」**。它回答的是「哪些後門被走過」,
> 不是「閘門今天攔了幾次、攔了什麼」。

**兩者名字很像而問題完全不同**,這一格寫進票面是因為
上一輪我自己就把它們搞混過一次(說「其餘兩個呼叫點仍會寫帳本」,

### 輪替(2026-08-26 核准附加條件 a)—— **必做,不是可選**

**為什麼是核准條件而不是優化**:

> 它 **append-only、不進版控**,而**在 enforce 下誤擋是常態**,所以它**會一直長**。

> **一個越來越難複製的檔案,最後會被跳過。**

**這是 `F-031` 的形狀換一個地方出現**:F-031 是「誤擋累積起來規則會被關掉」,
本則是**被煩到跳過備份**。**同一個機制,受害者不同** ——
前者丟掉的是規則,後者丟掉的是證據,而**後者不會有人發現**
(規則被關掉時大家都知道;備份沒複製到,要到需要它的那天才知道)。

#### 單位:**時間(按月分檔)**,不是筆數

```
.dev/intercepts-2026-08.jsonl
.dev/intercepts-2026-09.jsonl
```

**選時間不選筆數的理由**:備份是**按次**發生的(換機器、打包),
而「複製最近幾個月」是一個**人做得出來的操作**;
「複製最近 5000 筆」不是 —— 它要先算,而**要先算的備份步驟會被跳過**。
月檔名還自然排序,`ls` 就看得出有沒有斷月。

#### 舊的去哪裡:**滾成每月摘要,原始刪除**

**保留原始的是「當月 + 前一月」,再舊的在下一次寫入時自動滾成一行摘要:**

```json
{"kind":"summary","month":"2026-08","rule":"R7","count":137,
 "by_verb":{"grep":41,"rm":12,"<unknown>":84},"rolled_at":"..."}
```

**然後刪掉該月的原始檔。**

**為什麼是「當月 + 前一月」而不是一個別的數字**:這是**推導出來的,不是挑的**。
只留當月的話,**每月 1 號手上幾乎沒有原始資料**;
留到前一月,則任何時點都保證**至少有一個完整日曆月**的原始紀錄可分析。
**它是滿足「任何時點 ≥1 完整月」的最小值。**

> **這一格特別寫出推導,是因為本票所在的這條線上剛出過事**:
> `F-124` —— `MAX_FALSE_POSITIVE_RATE = 0.05` 至今查不到出處,
> 而它靠**被引用**取得權威。**一個沒有推導的常數,寫下的當天就開始變成傳說。**

**滾動是自動的(構造),不是排程或紀律** —— 在 `log_intercept` 寫入前檢查,
發現有超過保留期的月檔就先滾。**沒有「要記得去整理」這件事。**

#### 摘要保留多久:**不刪**

摘要一行約 100 bytes,一年 12 行 —— **它不會成為複製的障礙**,
而它是「誤擋頻率隨時間怎麼變」唯一的長期訊號。**刪它省不到東西,只丟資訊。**

#### 明寫的取捨

**滾動會丟掉個別紀錄的 `message` 全文與 `cmd_sha256`。**
所以**要拿來分類的月份,必須在它被滾掉之前處理** ——
這是一個**真的損失**,不是無痛壓縮。寫在這裡而不是只寫在碼裡,
因為讀票面的人才是會被它咬到的那個。

### 理由脈絡

`F-123` 已證(2026-08-25 發現、8/26 A1 確認):

> **R7 的判準比 G1 第二級更寬 —— 凡是 G1 第二級會擋的,R7 都先擋。**

於是在**裝了 `gate.py` 的 repo 裡,G1 對 agent 這條路是結構性看不見的**。
G1 的活體價值只在兩個地方:

1. **沒裝 `gate.py` 的 repo**
2. **人自己開的終端機**

> **而那正是 9/11 之後「新機器只裝一半」的處境** ——
> 使用者層跟著人走(G1 先到位),專案層要等 clone + 安裝。

**所以:G1 若不記帳,搬家後那段期間唯一還在守的東西,擋了什麼一筆都不會留。**

G1 的空白是**整條規則沒有帳本這個概念**。
