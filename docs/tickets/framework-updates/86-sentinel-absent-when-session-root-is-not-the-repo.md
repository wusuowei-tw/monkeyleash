## 一、現象(實測,不是推論)

票 49 第一階段那一輪,session 的專案根是 `c:\projects`,而 repo 在
`c:\projects\agent-gates`。`.claude/settings.json` 的 `PreToolUse` hook 因此
**沒有掛上** —— hook 指令是 `python "$CLAUDE_PROJECT_DIR/.claude/hooks/gate.py"`,
而 `CLAUDE_PROJECT_DIR` 指的是 session 根,不是 repo。

**實測**:一條 R7 一定會擋的 Bash 寫入直接執行成功。

```
$ printf probe > /c/projects/agent-gates/notes-ticket49-probe.txt
(無輸出,檔案建立成功)
```

同一條指令餵給 `gate.py` 本身,它擋:

```
$ echo '{"tool_name":"Bash","hook_event_name":"PreToolUse",
         "tool_input":{"command":"printf probe > notes-ticket49-probe.txt"}}' \
    | python .claude/hooks/gate.py
[六站閘門/前哨] [R7][enforce] 這個 Bash 指令會寫到沒有被許可的位置(notes-ticket49-probe.txt)。
EXIT=2
```

> **規則沒有壞,規則沒有被叫到。**
> 而「沒有被叫到」與「叫了、放行」在終端機上**完全一樣**:兩者都是靜默。

## 二、為什麼這不是「登記就好」的既有缺陷

CLAUDE.md 已記過一個鄰居:

> 「**未安裝的副本上這句不成立**:`.git/hooks/` 不進版控,clone 不會帶走它,
> 而且完全靜默 —— 前哨照跑、測試照綠,沒有東西會說權威層不在。」

**那一句講的是 pre-commit(權威層)缺席,而它的安慰是「前哨還在」。**
本票缺的是**前哨自己**,所以那句安慰在這裡不成立 —— 兩層的空隙這次疊在一起。

**而且它現在是活的,不是一個理論缺口:**

- **session 開在 `c:\projects` 是預設情形**,不是誤操作
- **接下來三個工作天正好要在那個根目錄清工地**

## 三、★ 這一輪自己就落在洞裡(`F-133` 的形狀)

**票 49 第一階段的所有檔案改動,都是在無前哨狀態下做的。**
包含一次用 Bash heredoc 追加 `docs/agents/friction-log.md` ——
**R7 若在場,那一次會被擋。**

> **一輪工作的量測基準,不涵蓋那一輪自己產出的東西(`F-133`)。**
> 那一輪在報告裡量的是「攔截帳本有沒有記到攔截」,
> 而它**沒有量**「這一輪自己有沒有被閘門看過」—— 答案是沒有。

### 緩解:pre-commit 仍在場,但涵蓋面不同

`.githooks/pre-commit` 靠 `core.hooksPath` 接上,而那是 **local config,
與 session 根目錄無關** —— 所以 commit 那一刻它會跑,那一輪的改動仍會被判一次。

**但它只涵蓋進版控的東西。** 落在 `.gitignore` 裡的、寫到 repo 外的、
以及**根本不打算 commit 的動作**(讀寫暫存、刪檔、跑指令),
pre-commit 一律看不到 —— 而 R7 管的正好是那一類。

> **兩層合起來仍有一塊沒有人看:「不進版控、且發生在前哨不在場時」的動作。**

## 四、範圍

### ⚠ 範圍**不得**寫成「記得開對根目錄」

那是**紀律**,而紀律沒有主詞 —— `F-110` 在這裡會死:
不做的時候不會有任何東西叫,而下一台新機器上沒有人會想起這一句。

### 範圍寫成:**找一個在前哨不在場時仍會出聲的位置**

判準只有一條:**它的存在不依賴 session 根目錄**。

已知還在場的只有 **pre-commit**(`core.hooksPath` 是 local config)。
**本輪只做偵察** —— 列出候選位置與各自看得到什麼、看不到什麼,不實作。

偵察要回答的三件:

1. `CLAUDE_PROJECT_DIR` 與 repo 不一致時,**還有哪些東西會被執行**
2. 那些位置各自**看得見什麼**(工具呼叫?檔案?只有 staged 內容?)
3. 有沒有一個位置能**在前哨不在場這件事發生的當下**就說話 ——
   而不是等到 commit(那時動作已經做完了)

### ★ 偵察的第一個結果:**`gate-exemptions.jsonl` 已經在記這件事了**

立案當天(2026-08-28)把豁免帳本裡的 `gate-self-modification` 依
`(ticket, at_commit)` 分組數,**一眼就看得出來**:

```
ticket=13   at_commit=False  10      ticket=13   at_commit=True   1
ticket=21   at_commit=False   6      ticket=21   at_commit=True   2
ticket=36   at_commit=False   7      ticket=36   at_commit=True   1
ticket=47   at_commit=False  19
ticket=76   at_commit=False   7      ticket=76   at_commit=True   1
ticket=83   at_commit=False   2      ticket=83   at_commit=True   1
ticket=49   at_commit=True    1      ← 沒有任何 at_commit=False
```

> **每一張動過 `gate.py` 的票都有一串 `at_commit=False`(前哨逐次評估),
> 票 49 一筆都沒有 —— 全帳本 161 筆裡,它是唯一一張只有 commit 側、
> 沒有前哨側的票。**

`at_commit=False` 是**前哨在場**的直接證據:每一次編輯 `gate.py`,
前哨都會評估一次、記一次豁免。所以那個欄位的**缺席本身就是訊號**,
而且它住在**一個已經進版控的檔案裡**。

#### 這回答了第 3 件的一半,但只有一半 —— 限制寫清楚

| 它能做到 | 它做不到 |
|---|---|
| **事後**可判定:一張票收線時對帳就看得出前哨在不在 | **不是當下** —— 訊號要等到 commit 才出現,而那時動作已經做完了 |
| 訊號進版控,換機器不會消失 | **只涵蓋會動用豁免的檔案** —— 改 `docs/` 不產生豁免,也就不產生訊號 |
| 零額外機制,資料已經在那裡 | **沒有東西在看它** —— 這一格是人手動下去數才發現的,而那正是本票要消掉的形狀 |

**所以候選處置不是「加一個新位置」,而是「讓已經存在的訊號會叫」** ——
規模比預期小得多。但**本輪不實作**,照裁決只偵察。

⚠ **這一格自己也是 `F-133`**:這個訊號之所以被發現,
正是因為**本輪自己就是那張零前哨側的票**。
換一輪工作(前哨在場)去偵察,這一格量不到 —— 資料會長得跟每一張票一樣。

### ⚠ 關票判準(裁決 2026-08-28 寫死,不得被上面那條線索取代)

> **判準是「它在前哨不在場時會不會叫」,不是「事後查不查得出來」。**

**豁免帳本那條線索是偵測,不是守衛。** 它讓人**事後對帳看得出來**前哨在不在,
而本票要的是**當下有東西出聲**。

**若用它關票,就等於複製這一族四筆的共同形狀** ——
第六節那張表的共同句是:**守衛的「不在」與守衛的「放行」,
在觀察者那一端長得一模一樣**;而一條只有人手動去數才會說話的線索,
在「沒有人去數」的時候,與「一切正常」長得一模一樣。**那是第五筆,不是解法。**

所以上面那條線索的正確位置是:**偵察的產物、候選處置的起點**,
**不是驗收**。關票要拿出來的東西必須通過那一句判準。

### 誤報方向 —— **更正**(裁決 2026-08-28)

~~誤報方向:一張只改文件的票本來就不會有豁免,不能一律報。~~

**那個例子是錯的,不會誤報**:只改文件的票**兩側都是零**,
而條件是「**有** commit 側豁免、**零**前哨側豁免」—— 左半不成立,條件根本不觸發。
(舊文保留,照 `F-036`:它被寫進過票面,而讀的人會拿它當已知代價。)

**真正的誤報路徑是:人自己動手改 `gate.py`、不經 agent。**

前哨掛在 agent 的 `PreToolUse` 上,**人用編輯器改檔案不會經過它** ——
所以前哨側本來就不會有紀錄,而 commit 側照樣會有一筆。
**那是一次完全正常的人工編輯,卻長得跟「前哨不在場」一模一樣。**

⚠ **而這種情形在本票的時鐘內會變多,不是變少**:
搬家後筆電只裝一半(使用者層先到位、專案層還沒),
**人手動修東西正是那個階段的常態** —— 9/11 那個窗口同時是
本票要防的洞的發作期,**也是這條誤報的高峰期**。兩者疊在同一段時間裡。

> **所以這條檢查不能只看「零前哨側」——
> 它必須分得出「前哨沒被叫到」與「前哨不在那條路上」。**
> 那是下一輪要回答的,本輪只登記形狀。
