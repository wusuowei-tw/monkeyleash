# 25 — `variants()` 接受一種默默不生效的條目寫法(磁碟根目錄)

**排程**:票 24 之後。**本票只開票,不動碼。**

**缺陷家族**:**假保護陷阱** —— 守衛接受一種寫法,語意與作者意圖不同,而且**沒有任何訊號**。
`machine-init.md` 已經用人話寫過同一件事:「**驗收全綠 ≠ 保護對了地方**」。
這一票是那句話的機器版:連驗收工具都會給它綠燈。

## 現象

保護清單寫一條磁碟根目錄(`D:\`),看起來是「整顆磁碟都保護」。實際上:

| 清單條目 | `variants()` 產生的變體 | `ls /d/x/a.txt`(git bash 形態) |
|---|---|---|
| `D:\` | `['d:']` —— **只有一個** | **放行** ← 漏 |
| `D:\zzz_probe` | `['d:\zzz_probe', 'd:/zzz_probe', '/d/zzz_probe', ...]` | **擋** |

**兩個方向同時出錯,而且方向相反:**

1. **太寬**:`d:` 這個變體會命中該磁碟上的**任何**路徑
   (實測 `ls d:/other_dir/b.txt` → 擋)。寫一條變成整顆磁碟全擋。
2. **同時又漏**:`/d/...` 這個 git bash 形態**不在變體裡** —— 而那正是
   本專案 Bash 工具實際使用的路徑形態。**最寬的寫法漏掉最常用的形狀。**

誤擋不會有人抱怨(整顆磁碟本來就少碰),漏擋不會有人發現(沒有訊號),
兩者剛好互相掩護。

## 根因

`variants()` 的 git bash 分支靠正則 `^([A-Za-z]):[\\/](.*)$` 觸發,
而函式開頭的 `p = path.strip().rstrip("\\/")` 先把 `D:\` 削成 `D:` ——
正則要求磁碟代號後面**有一個分隔符**,`D:` 沒有,於是不匹配,
`/d/...` 與 `/D/...` 兩個變體都不生成。剩下的 `{p.replace(...)}` 只留下 `d:`。

`rstrip` 那一行本身是對的(讓 `D:\<某目錄>\` 與 `D:\<某目錄>` 等價),
只是**磁碟根目錄是它唯一會削掉語意的輸入** —— 對別的路徑削的是贅餘的尾斜線,
對根目錄削的是**構成路徑所必需的那一個**。

## 為什麼驗收擋不住(已驗證,這是本票的重點)

`g1_verify.py` 是從**實際清單**生案例的,理應「清單長出新條目就自動涵蓋」。
但它的探針是 `as_probe(p)`:

- `p = "D:\"` → `p.rstrip("/\\")` → `"D:"` → 探針指令 `touch "D:\g1_verify_probe.txt"`
- 這條指令**會**被 `d:` 這個變體命中 → 擋下
- 斷言是 `want in err`,`want = "D:"`,而訊息裡印的是原條目 `D:\` → **包含 `D:`** → **通過**

於是:**條目寫成磁碟根目錄,`g1_verify` 全綠,而 `/d/...` 形態的指令一路放行。**
綠燈的原因不是「這條保護生效了」,是「探針剛好用了那個唯一生效的變體」。
這是 F-032「綠的原因不是你以為的」在 G1 這一側的現身。

## 現況:是陷阱,不是活著的洞

**清單裡目前沒有任何磁碟根目錄條目。** 所以此刻沒有東西在漏。
本票排在票 24 之後、不是最優先,理由就是這個。

但這與票 24 是同一句話:**「今天沒踩到」是狀態,不是機制。**
而這條的踩中門檻特別低 —— `D:\` 是想保護整顆磁碟時**最自然**的寫法,
清單本身又寫著「成本近乎零……寧可多列」,等於在鼓勵人往那個方向寫。

## 候選修法(本票內議,未裁決)

1. **`variants()` 正確支援磁碟根目錄。**
   保留 `rstrip`,但磁碟根另走一條:`D:\` → `d:\`、`d:/`、`/d/`、`/D/`。
   優點:寫法直覺地生效。
   風險:`d:` 那個「命中整顆磁碟」的變體要不要留?留 = 一條進去全擋,
   而使用者未必意識到範圍;不留 = 行為又變了。**要議的是這一點,不是怎麼寫正則。**
2. **`protected_entries()` 讀到磁碟根目錄條目時大聲拒絕(fail-closed)。**
   不猜使用者要哪一種語意,直接說「這種寫法不支援,請逐條列出或改寫成 X」。
   優點:與 G1 全篇的判準一致 —— **解析不出來就擋,不要猜**;
   而且陷阱從「靜默」變成「吵鬧」,那正是這一族缺陷唯一的解。
   代價:整顆磁碟保護變成不可表達(可接受?這是要裁決的)。
3. 兩者合併:支援磁碟根,**但**要求顯式寫成某個不會誤讀的形式。

**判準不是「哪個好寫」,是:使用者寫下一條保護,能不能在不讀原始碼的情況下
知道它實際保護了什麼?** 不能,就還沒修完。

## 證據:唯讀探針方法(本票的量測方式,建議修完後留成回歸)

不改任何檔案、不碰保護清單。用 `importlib` 載入 `g1_guard.py`,
直接呼叫 `variants()` 與 `level1_hit(text, [entry])`,清單參數傳**中性測試路徑**
(`zzz_probe` 之類),避免探針本身撞上第一級。

比對矩陣至少要有:磁碟根條目 × {反斜線形、正斜線形、git bash 形、同磁碟無關路徑},
外加兩條不該中的邊界案例(`--id: 3`、`cmd: hello` —— 實測皆放行,
`_prefix_in` 的前置字元檢查有效)。

上面那張兩行表就是這樣量出來的。**修完之後這個矩陣要進回歸集** ——
否則下一次有人把 `rstrip` 那行「整理」一下,不會有任何東西發現。

## 怎樣算做完

- 磁碟根目錄條目的語意**明確**:要嘛正確生成四種變體,要嘛被明確拒絕。**不存在第三種「看起來有效」。**
- `g1_verify` 對這種條目**不再給出誤導的綠燈**(這條是核心:修了行為卻沒修驗收,陷阱只是換個地方)
- 上述比對矩陣進回歸集
- 既有九條(檔案與目錄形態)行為零變化 —— 回歸證明,不是宣稱
