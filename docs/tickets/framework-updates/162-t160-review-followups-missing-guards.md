## 工作項

對象是票 160 在 `gate.redlight_missing` Python 分支加上的「確定不在 HEAD」三態判定。每一項補一條測試：

1. **`--show-toplevel` 不等於 `ROOT`**：把 `ROOT` 設為某 repo 的子目錄，HEAD 已誕生、實作不在 HEAD、帶 not-found 紀錄 ⇒ **擋**。這條同時是 `--show-toplevel` 這一道的獨立守衛（票 160 的 #3 由前一道 `rev-parse --verify` 擋，分辨不出這一道）。
2. **gitlink 底下**：
   - 實作落在 gitlink 底下，子模組的 HEAD 也沒有該檔，帶 not-found 紀錄 ⇒ **擋**。
   - 子模組的 HEAD 有該檔 ⇒ not-found 紀錄 **擋**，只有 `impl_hash` 等於子模組 HEAD 內容雜湊的紀錄才 **放行**（只走 HEAD 雜湊出口）。
3. **`_git_object_exists` 回 `(True, None)` 而 `head` 為 None**（檔在 HEAD 但拿不到雜湊）⇒ **擋**。
4. **`_under_gitlink` 回 None 的四條路徑**，各一條，帶 not-found 紀錄 ⇒ **擋**：
   - `ls-tree` 失敗；
   - `ls-tree` 回多筆；
   - 回傳路徑與前綴不相等；
   - 未知 mode（不在封閉集合 `040000`／`100644`／`100755`／`120000`／`160000` 內）。
5. **非 Python 檔在 HEAD 且帶 not-found 紀錄 ⇒ 仍放行**（結果與票 160 之前相同）。這是 Jeff 2026-10-22 約 15:23（美東）授權條件「由測試確認結果不變」的另一半；票 160 的 #7 只測了不在 HEAD 的情境，在 HEAD 的情境目前只有讀碼推論，**尚待補齊**。
