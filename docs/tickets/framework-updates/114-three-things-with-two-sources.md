每一件都要一條 **「兩處是同一個物件」的測試** —— 不是「兩份內容相等」:

```
內容相等的斷言:改了一份、忘了另一份 -> 紅(好)

同一物件的斷言:`a is b` -> 構造上不可能分岔
```

## 刀二 —— B-3:兩份「非原始碼目錄」清單

**受害符號**:`gate.NON_SOURCE_DIRS` / `redlight._SEARCH_SKIP`。

**分岔實測(2026-09-07)**:`scripts` 在 `gate` 那份裡、**不在** `redlight` 那份裡;
兩份都不含 `.claude`(後者是刻意的,理由寫在 `redlight._SEARCH_SKIP` 上方的註解裡:
跳過所有點開頭的目錄會跳過閘門自己)。

### 動工前必須先量(**這一刀不是純合併**)

> **把 `scripts` 納入之後,`redlight.find_implementation` 會少走哪些路徑?**

`find_implementation` 是**由測試找實作**(與 R3 反向),它決定紅燈紀錄裡的
`impl_file` / `impl_hash`。多跳過一個 `scripts/`,代表
**`tests/test_<x>.py` 對應到 `scripts/<x>.py` 的那些會從「找得到」變成「找不到」** ——
而「找不到」在紀錄裡是 `impl_exists=False`,那會改變 R3 的判定。

**要量的三個數字(帶單位)**:
`scripts/` 底下有幾支 `.py`;其中幾支有對應的 `tests/test_<name>.py`;
現行紅燈紀錄裡有幾筆的 `impl_file` 落在 `scripts/`。
**三個都是 0 的話這一刀是純合併;任一個非 0,就要先裁「該不該跳過 `scripts`」。**

### 方向的坑(立案時就寫下來,免得動工才發現)

票面原句是「`redlight` import `gate`」。**那個方向有循環**:
`gate` 已經用 `_redlight()` **以路徑載入** `redlight`(而且該函式的 docstring 寫了為什麼不能用
`import redlight`:測試以 `spec_from_file_location` 載入 `gate` 時,`.claude/hooks/` 不在 `sys.path` 上)。

三個候選:

| | 做法 | 代價 |
|---|---|---|
| **甲(建議)** | 清單搬去 `redlight`,`gate` 從那裡取 | 與現有載入方向一致(`gate` 已經會載 `redlight`),零新機制。但「非原始碼目錄」這個概念住在 redlight 有點怪 |
| 乙 | `redlight` 以同樣的路徑載入法載 `gate` | 兩支互相載入,任一支被單獨載入時都要能活 —— **要驗四種載入順序** |
| 丙 | 開第三支小模組放共用常數 | 最乾淨,但多一個檔案要進 manifest、進安裝、進下游 |

**紅燈形狀(一句)**:斷言兩處取到的是**同一個物件**;在其中一處加一個目錄,另一處立刻看得到。

## ⚠ 本票自己製造的一個缺陷,與它的處置(2026-09-08)

**處置(裁決 2026-09-08)= loud skip + 獨立的跳過條件:**

- 沒有票目錄時 `pytest.skip` 並印出理由,**讓人分得出「不適用」與「壞掉」**
