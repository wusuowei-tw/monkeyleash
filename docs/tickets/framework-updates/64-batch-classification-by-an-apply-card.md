## 為什麼要它

量化有 **222 筆**未分類紀錄(票 63 修好後才數得到),其中 **R7 佔 202 筆**。
現行 `review()` 是逐筆 `input()`,222 次互動 ——
而其中一大群是**同一個成因**(R7 對唯讀指令誤報,已記在量化 `friction-local.md`)。

> **逐筆判是對的判準,不是對的介面。**
> ADR 0012:「逐筆判,不算總數」要的是**每一筆都有一個判斷**,
> 不是**每一筆都要按一次鍵**。批次模式不放寬前者,只換後者。

## 五條約束(裁決給定)

| # | 約束 | 為什麼 |
|---|---|---|
| 1 | **識別唯一綁定** | 卡片指的是哪一筆,必須與**內容**綁死,不能靠行號或順序 |
| 2 | **全有全無** | 一張卡要嘛整張套上,要嘛一個字都不寫 |
| 3 | **dry-run** | 預設不寫;要看會動到什麼得先看得到 |
| 4 | **套用卡留檔** | 卡片是檔案,套用後留下它與它的指紋 |
| 5 | **紅燈含識別衝突整批拒絕** | 撞號不是警告,是拒絕 |

## 約束 1 的資料事實:`ts` **不唯一**,而且是真實資料撞的

量化 222 筆實測(唯讀):

| 候選鍵 | 相異數 | 撞號 |
|---|---|---|
| `ts` | **221 / 222** | **1 組,涉及 2 筆** |
| `ts` + `rule` | **221 / 222** | **1 組,涉及 2 筆** |
| `ts` + `rule` + `message` | 222 / 222 | 0 |
| 整筆(除 `classification`)sha256 | 222 / 222 | 0 |

> **撞號在生產資料上已經發生了,不是假想的邊界。**
> 用 `ts` 當鍵的批次工具,今天就會把兩筆不同的判定當成同一筆。

採用:**`record_id` = 除 `classification` 外所有欄位的正規化 JSON 的 sha256**。

**為什麼要排除 `classification`**:身分必須在**套用前後不變**,
否則套用完之後那張卡就再也指不到它動過的東西 —— **留檔會變成留一份指不回去的紙**。

**為什麼不用 `ts+rule+message` 三元組**:它今天唯一,但那是**這份資料**的性質。
欄位集合是封閉且可窮舉的(`ts` / `rule` / `message` / `verdict` / `at_commit`),
**封閉集合用枚舉勝過比對**(CLAUDE.md 常駐檢查項)——
整筆雜湊就是枚舉,而挑三個欄位是比對,漏的那一天不會有人知道。

## 卡片格式

一行一筆 JSON(與日誌同形態,不引進第二種格式):

```
{"id": "<record_id 前 16 碼>", "class": "1", "why": "R7 對唯讀指令誤報"}
```

- `id` 取前 16 碼(64 bit):人眼可讀,而碰撞機率在 222 筆的量級上可忽略 ——
  **但工具仍會檢查前綴在本份日誌內唯一**,不靠機率(約束 5)。
- `why` **必填**:一張沒有理由的批次卡,事後沒有人分得出它是判斷還是手滑。
- `class` 必須是 `CLASSES` 的鍵之一。

## 拒絕條件(全部整批拒絕,不部分套用)

| 條件 | 為什麼不是警告 |
|---|---|
| 日誌內有兩筆 `record_id` 相同 | 卡片指過去會指到兩筆,而「套哪一筆」不是工具能決定的 |
| 卡片內有兩行 `id` 相同 | 同上,方向相反 |
| `id` 前綴在日誌中對到 **0 筆或 ≥2 筆** | 對不到就是卡片與日誌不同步;對到多筆就是前綴不夠長 |
| `class` 不在 `CLASSES` | 打錯字會變成一個沒有人認得的分類 |
| 目標紀錄**已經有** `classification` | 覆蓋別人的判斷要是一個顯式動作,不是批次的副作用 |
| `why` 空白或缺席 | 見上 |

## 留檔(約束 4)

套用成功後,往 `.dev/shadow-cards.jsonl` 追加一筆:

```
{"ts": …, "card": "<卡片路徑>", "card_sha256": …, "applied": 50, "by_class": {"1": 36, "5": 14}}
```

**卡片本身不刪、不搬。** 留下的是「哪一張卡、內容的指紋、動了幾筆」——
與 provenance 同一個判準:**寫下來的東西要能被獨立查證**,
`card_sha256` 讓事後有人可以拿卡片重算一次。

## 本票不含

- 自動**判斷**分類 —— 工具只套用人寫好的卡,**不產生判斷**

# 追加(2026-08-26,裁決五):**利益衝突** —— 本票沒有處理它

## 缺口

本票五條約束處理的是:`ts` 不唯一、撞號整批拒絕、`why` 必填、
留 `card_sha256`、已有分類不得被批次覆蓋。**全部是「卡片本身可不可信」。**

而「**卡片是誰寫的**」沒有被規範。上面那句「工具只套用**人寫好的卡**」
**沒有指明是誰**,現況因此允許 **agent 起草分類、Jeff 核准**。

**問題是**:這裡要判的是「**這次擋得對不對**」,而**被擋的那一方就是起草人**。

CLAUDE.md 的 `F-112` 管的是**核准**不是**起草**,而它自己已經寫過這個失敗模式:

> **一個無從反駁的摘要,收到的核准也是無效的** ——
> 它證明的只是對方按了同意,**不是對方同意了什麼**。

## 第 1 層判準草案 —— **待核准,未套用**

**候選判準(一條)**:

# 判準修正(2026-08-26,第三方裁決)—— **三桶,不是兩桶**

## 我的原裁被改進了,缺陷逐字記在這裡

我上面起草的是「唯讀被擋 = 刻意 refuse」的**兩分法**。第三方裁決(Gemini)
選了乙方的方向,但給出**雙方都沒想到的第三種分法**:

| 桶 | 定義 | 修法 |
|---|---|---|
| **① True Positive** | 真的有危險寫入,被擋 | 無 —— 規則做對了 |
| **② Collateral Damage** | 指令其實**無害**,但觸及「無法可靠解析」的**安全底線**而被擋 | 改切分器,**或接受** |
| **③ False Positive** | **沒有分段符號、沒有寫入**,純因 bug 被擋 | **修 bug** |

**假陽率分子 = ② + ③**(對執行者都是白挨的成本),**但兩桶分開記**。

### 我原裁的缺陷(逐字)

> **把附帶損害與真 bug 壓成同一桶,會讓「切分器變差」與「規則寫錯」
> 在數字上無法分辨。**

兩者上升的意義完全不同:② 上升代表**切法本身不實用**,
③ 上升代表**有東西寫壞了**。壓成一桶,兩種病共用一個體溫計。

### 一併收 Gemini 的反例(它比我的反對理由更利)

> 一條「**擋掉所有含英文字母的指令**」的規則,永遠 100% 照設計運作,
> **FPR 永遠 0**,而它**毫無價值**。

這比我自己寫的那句(「一個把自己的成本定義成設計的規則,假陽率必然是 0」)
更硬 —— 我的是斷言,它是**可構造的反例**。**留著它,別留我那句。**

## 裁決一:那 130 筆按新口徑要**重分**

### 現有的「刻意 refuse」是混合桶

ADR 0012 §2 給它的定義是「規則做了對的事,而它有成本」——
落在新三桶裡,**它同時裝著 ① 和 ②**:

- 「切不出目標所以擋」+ 指令**真的要寫** → **①**
- 「切不出目標所以擋」+ 指令**無害** → **②**

**同一句話(切不出目標)在新口徑下對應兩個不同的桶。**

### 唯讀評估:重分的成本

**⚠ 第一項成本不是判斷,是機制** —— 本票約束 5 逐字:

> 不是批次的副作用

→ **這 130 筆走不了一般的套用卡路徑。** 重分需要一條顯式的

2. **它與 B2 的 40 筆上限互相咬** —— 重分後若有一批因訊息不足而落進

> 而兩者在事前分不出來。

## 裁決二:`MAX_FALSE_POSITIVE_RATE = 0.05` 的出處 —— **查不到理由**

### 查了哪些地方(全部唯讀)

| 來源 | 結果 |
|---|---|
| `docs/adr/0012-shadow-mode.md:44` | 「每條規則**自己** ≥10 筆已分類 且 假陽率 <5% 才可轉正」—— **陳述,無理由** |
| `docs/adr/0012-shadow-mode.md:63`(`## 參數`) | 「`SHADOW_MAX = 2026-09-15`(避開使用者八到十月搬家…)、窗 14 天、每規則 ≥10 筆已分類、假陽率 <5%」 |
| 原始 commit `4521540` 訊息 | 「每條規則自己 >=10 筆已分類且假陽率 <5% 才轉正」—— **重述,無理由** |
| `git log --all -S "MAX_FALSE_POSITIVE_RATE"` | 4 筆,全部是後續使用,無一給出理由 |
| 量化 `docs/adr/0012`(含 171 行補遺) | `:44` / `:63` 逐字相同;`§2` 只定義**分子分母**,不談 5% 這個值 |
| `docs/machine-init.md:456`、票 65:105、票 67:197 | **全部是引用**,且票 65 / 票 67 都明寫「那是 ADR 0012 的數字,不是本票的」 |

### 結論:**沒有出處。而 ADR 自己證明這不是體例問題。**

`## 參數` 那一節列了四個參數,**只有 `SHADOW_MAX` 附了理由**
(「避開使用者八到十月搬家,影子不能搬家途中過期」)。
窗 14 天、≥10 筆、<5% **三個都是裸值**。

> **作者在有理由的時候會寫理由。** 所以 5% 旁邊的空白不是省略,
> **是當時就沒有理由可寫。**

同一份 ADR 對**結構**倒是給了理由 ——
「全局比率會讓一條規則的真陽稀釋另一條的假陽」解釋了**為什麼 per-rule**。
**結構被論證過,數值沒有。**

### 附帶觀察:它是靠**被引用**取得權威的

票 65 與票 67 各自碰到這個數字時,都寫下「那是 ADR 0012 的數字,不是本票的」
然後繞開。**兩次正確的克制,累積成一次沒有人負責。**
每一次引用都讓它看起來更像被裁決過的東西,而**沒有任何一次引用檢查過它有沒有出處**。

### 因此按裁決二的分岔:**落在「當初憑感覺抓的嚴格值」那一邊**

裁決二給的兩條路:

- 若代表「系統容忍度」(agent 遇到 5% 阻擋仍能自行換寫法、不至於卡死)→ **不該調**
- 若只是當初憑感覺抓的嚴格值 → **應放寬**(建議 10~15%)

**查證結果支持後者** —— 沒有任何文件把 5% 連結到容忍度、到實測、或到任何論證。

**但我不主張直接改成 10~15%**,理由是換口徑與換門檻**不該同一刀**:

> 分子定義擴張(② 進分子)與門檻放寬(5% → 15%)同時發生的話,
> **假陽率的變化就歸因不了** —— 分不出是口徑造成的還是門檻造成的。
> **先換口徑、量一次,再談門檻。**

而換口徑後的第一次量測,正好給出這個門檻**第一份有實證的基礎** ——
5% 至今沒有,現在有機會讓它有。
