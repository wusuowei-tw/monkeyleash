#### 票 49 之外還剩什麼

票 49 的指紋寫在**被擋的那一刻**。所以它覆蓋不到:

| 剩下的 | 為什麼 49 到不了 |
|---|---|

| **而 `current_stage` 是人手動改的控制面板** | **改動它就是一次決策**,而決策沒有留下痕跡 |
| **`.dev/shadow.json` 從未存在**(附錄一) | 「本 repo 從未開過影子」這件事**沒有任何版控紀錄**,而它決定 R6 相關行為 |

> 49 讓**每一次擋下**可複現;本張問的是**兩次擋下之間**發生了什麼。
> 兩者不重疊,但**分不清楚的話會兩邊都以為對方處理了**。

### ② `.env.example` 的 `.example` 要不要進審查白名單

`leak_scan.py:69–75` 的 `REVIEW_ALLOWED_EXT` **沒有 `.example`**。
所以 `.env.example` 這類檔會落進「未內容掃描」清單。

**⚠ 上游實測:`.env.example` 在 agent-gates 不存在。**
所以本項在上游是**規則問題,不是檔案問題** —— 要決定的是白名單該不該收這個副檔名,
而不是「這個檔怎麼辦」。**下游有實際檔案,上游只有規則。**

判準兩面都成立,所以它是**判斷題不是缺陷**:

| 收 | 不收 |
|---|---|
| `.env.example` 依慣例只放佔位值,不掃它會讓一整類檔靜默略過 | 它的**近鄰 `.env` 正是最該掃的東西**,而白名單靠副檔名分辨,`deny-by-default` 的設計就是不猜 |

### ③ R4 的兩個鏡像目錄在上游不存在 —— **整條迴圈空轉**(2026-08-21 併入)

R4 守的是「正典 `.agents/skills/` 與鏡像 `.claude/skills/` / `skills/` 一致」。

上游 `8552830` 實測:

```
$ ls -d .claude/skills skills
ls: cannot access '.claude/skills': No such file or directory
ls: cannot access 'skills': No such file or directory
$ ls -1 .agents/skills/ | wc -l
13
```

**兩個下游都有齊三個目錄**(`.agents/skills` / `.claude/skills` / `skills`,量化與影音皆然)。

而 R4 的迴圈對「鏡像整個不存在」是 **fail-open,且那是明文設計**:

```python
        for mirror in mirror_dirs:
            # 鏡像整個沒建起來不是 drift,是還沒裝 —— 那由安裝流程負責,不是 R4。
            if not os.path.isdir(mirror):
                continue
```

→ **上游兩個鏡像都不存在 ⇒ 內層迴圈對每一個 name 都 `continue` ⇒
R4 在 agent-gates 自己身上的判定次數是 0。**

**而那個 fail-open 把責任交給「安裝流程」,票 26 已證明 agent-gates 從未被 `install.py` 裝過。**
兩者相乘:**上游的 R4 沒有任何東西會跑它,而下游天天在跑。**

#### ⚠ 這與 `CLAUDE.md` 已記的 R4 缺口**不是同一件事**

`CLAUDE.md` 現記:「硬連結佈局下內容由構造保證相同,**R4 的內容比對不會觸發**,
它實際只守得住『檔案在不在』。」

**本項在那一層之下**:上游連「檔案在不在」都不會被問到,因為迴圈進不去。

> **已知缺口寫的是覆蓋率降一階,實測是上游覆蓋率為零。**
> 兩句話在票面上長得很像,而它們差一個數量級 —— 分開寫,免得下一個人
> 讀到已知缺口就以為這一格已經被涵蓋了。

#### 為什麼掛本票(核,2026-08-21)

1. **同一個形狀,本票 ② 已經寫過一次**:「上游實測:`.env.example` 在 agent-gates
   不存在。所以本項在上游是**規則問題,不是檔案問題** …… **下游有實際檔案,上游只有規則**。」
   R4 這一格逐字同構。
2. **同一個檔的同一段**:① 引的 `.gitignore` 那句「下游反而都把 `.dev/` 進版控 ——
   上游對自己的紀律低於下游」,與 R4 鏡像的 `/.claude/skills/` `/skills/`
   **在同一個 `.gitignore` 裡**,而該檔開頭那段註解正是在解釋 R4 存在的目的。
3. **處置相同**:三項都要裁「上游要不要讓自己受同一條規則管」,
   不是修一段壞掉的判斷。

**形狀差異,寫明免得被推廣**(照票 51 ⑥ 的先例):

> **①② 是上游「選」的**(不進版控 / 白名單收不收)—— **裁決題**。
> **③ 是上游「沒跑到」的**(鏡像是 gitignored 的執行期產物,消失時完全靜默)—— **狀態題**。
> **併案的理由是處置相同,不是同類缺陷。**

**沒被採用的反方讀法(寫下來,免得下次被重新提出一遍)**:
③ 的處置也許只是「跑一次 `bash scripts/skills-update.sh` 重建鏡像」,
那樣它是維運動作不是票。**不採用的理由**:能被一個 gitignored 目錄的存在與否
**靜默**關掉的規則,問題不在目錄,在「沒有東西會說它關了」——
而那正是本票的題目。
