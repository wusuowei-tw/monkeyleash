### 五、⚠ ③ 偏離裁決字面一處 —— **允許三個值,不是只有「工作站數」**

裁決寫的是「**N 必須等於 ① 算出的工作站數**」(7)。**實作允許 `{8, 7, 6}`。**

**理由**:兩份 README 逐字寫著「**六站主線流程**」/「**Six-station main-line pipeline**」,
而它們接著列出六個 skill、並明說「另有兩個站不在主線上」——
> ### **那是一句正確的計數句,而它數的是 6。**

只認 7 的話,這句真話會被判成錯,**而唯一的修法會是把它加進白名單** ——
**於是它從此不受任何檢查**。那正是本票要修的那種「沒有人在守的數字」,只是換了個地方。

**所以 `main_line` 也從定義檔算出來**(`skill` 非 null 且沒有 `src_write_scope`),
**而不是寫死一個 6**。三個值都是推導值,失效時三個一起變。

### 六、兩個實測撞出來的偵測器缺陷(都由本檔自己的反控抓到)

1. **「哪一站」被讀成「1 站」** —— 第一版對 `README.zh-TW.md` 報了一個**假陽性**。
   > **一個把「哪一站」讀成「一站」的偵測器,在第一次跑就製造一個假缺陷,
   > 而修它的人會去改一句完全正確的散文。**
   誤擋的代價在這裡不是不方便,是**這條規則會被關掉**(同票 23 的判準)。
   處置:數字前面若是指示詞/序數(`哪每這那上下同前後第各本某整全`)就不算。
2. **`"" in "任何字串"` 在 Python 是 `True`** —— 於是「出現在字串開頭的計數句」
   **全部被靜默跳過**,而那正是最該抓到的那種(標題、表格欄位的第一個字)。
   處置:`if before and before in ...`。**兩條反控在寫完的第一次跑就抓到它。**
