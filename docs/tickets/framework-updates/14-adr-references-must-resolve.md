## 由來

`F-` 改名那一輪(`6b08c8a`)逐筆更新了 9 處引用,**靠的是 grep 加人工判定**。
`adr-numbering.md` 已經寫下這件事的風險:

> 追溯改名要逐筆改引用,而**漏改是靜默的** —— 一個指向不存在檔案的引用
> 不會有任何東西出聲,只會在有人去點的時候才發現。

那一輪只有一個東西真的在守:`RULE_DIVERGENCE` 的 ADR 路徑有測試驗它存在
(`test_every_divergence_is_declared_by_its_rule`)。**其餘八處全靠我沒有漏看。**

## 範圍

一條檢查:**原始碼與文件裡出現的 `docs/adr/...` 路徑,對應檔案必須存在。**

- 掃描集合用**出貨集合**(manifest `copy` 桶推導),不是 `git ls-files ROOT`
  —— F-075 的判準,別再犯第五次
- 路徑形式的引用是硬性的(指向不存在的檔案 = 壞掉)
- 散文形式的號碼引用(「見 ADR F-0013」)**不在本票範圍**:
  那是可讀性問題,不是壞掉。硬要驗會逼出一堆為配合工具的改寫(票 07 的教訓)

## 它會順帶抓到的東西

影音 repo #5–8 那一批的**錯誤訊息**裡有指向已改名 ADR 的路徑。
本票的檢查上線時會抓到它們 —— 而那正好給那批修改一條**合法的紅燈**:
先紅、再修,不必為了改一行訊息去製造一條假的紅燈。

這也是 `sync.py:65` 那一筆的歸屬:

- 現況:`.claude/portable/sync.py:65` 的散文引用維持「ADR 0013」
- 不現在改的理由:R3 擋下(`tests/test_sync.py` 全綠),而那是純註解改動,
  為它製造紅燈就是為配合工具而扭曲產出
- **本票執行時一併處理**:那時 `tests/test_sync.py` 會因為這條新檢查而真的紅
