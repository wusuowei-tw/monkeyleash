**為什麼這些加起來就沒有循環依賴**:

> commit 物件的雜湊只由它自己的內容決定(樹、parent、身分、時間、訊息)。
> 根沒有 parent;**身分改寫不動樹與 blob**;而要替換的字串 `45a8d16`
> **不可能出現在根自己的樹裡** —— 那需要一個雜湊不動點。
> 所以**不論後面的 commit 怎麼被改,根的新 sha 都是固定的**,
> 於是它可以先在複本上讀出來,再餵回正式那一刀。

**這是從方法推出來的保證,不是從這次的資料看出來的**(CLAUDE.md 那條判準):
事實 3 的**構造理由**是雜湊不動點不存在,而 91 檔全掃只是**佐證**,不是依據。

#### 方法(定死,演練照這個跑)

**不得用 `--replace-text`。** 實測 HEAD 樹裡有 **3 個路徑**含**全行** `# go-live: 45a8d16`:

```

docs/agents/friction-log.md:2154                            ← 史料,不動
docs/tickets/framework-updates/39-…md:12                    ← 史料,不動
```

全域替換會把後兩份史料一起改掉,與「史留不動」相衝。

**封閉集合用枚舉,不用比對** —— 比對的漏是未知的,枚舉的漏是不存在的。
