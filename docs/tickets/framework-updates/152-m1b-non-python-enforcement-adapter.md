### 4.3 全套回歸的比較方式（AC-B11，批一、批二都適用）

**紅燈站開始前**，在當時 HEAD 量一次全套基準，記錄：

1. 收集範圍：收集到的測試識別（nodeid）清單與總數；
2. 排除項：所有 deselect／ignore／指定排除，逐條列出與理由；
3. 跳過：每一個跳過的 nodeid 與跳過原因；
4. 失敗：每一個失敗的 nodeid；
5. 執行指令原文與退出碼。

**驗收時**以同一指令、同一排除項重量，要求：

- **沒有新增失敗**：逐個 nodeid 比對，不是只比數量。基準就失敗的項目要逐條列出，並說明與本票無關的依據。
- **收集範圍**：基準有的 nodeid 不得消失（除非本票明文改名或刪除，並逐條說明）；新增的 nodeid 逐條列出。
- **排除項**：與基準逐字相同；有增減要逐條說明並送 Jeff。
- **跳過**：逐個 nodeid 比對跳過原因；新增的跳過或原因改變要逐條說明。
- 有任何排除項時，報告一律稱「**指定排除後的全套**」，不得稱「全套」。
