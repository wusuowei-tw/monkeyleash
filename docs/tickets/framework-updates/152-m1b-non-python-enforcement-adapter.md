### 4.3 全套回歸的比較方式（AC-B11，批一、批二都適用）

**紅燈站開始前**，在當時 HEAD 量一次全套基準，記錄：

1. 收集範圍：收集到的測試識別（nodeid）清單與總數；
2. 排除項：所有 deselect／ignore／指定排除，逐條列出與理由；
3. 跳過：每一個跳過的 nodeid 與跳過原因；
4. 失敗：每一個失敗的 nodeid；
5. 執行指令原文與退出碼。

**驗收時**以同一指令、同一排除項重量，要求：

- **沒有新增失敗**：逐個 nodeid 比對，不是只比數量。基準就失敗的項目要逐條列出，並說明與本票無關的依據。
- **收集範圍**：基準有的 nodeid 不得消失（除非本票明文改名或刪除，並逐條說明）；新增的 nodeid 逐條列出。
- **排除項**：與基準逐字相同；有增減要逐條說明並送 Jeff。
- **跳過**：逐個 nodeid 比對跳過原因；新增的跳過或原因改變要逐條說明。
- 有任何排除項時，報告一律稱「**指定排除後的全套**」，不得稱「全套」。
- **跨 checkout 位置比對（G6；Jeff 2026-10-14 裁定，裁決助手記錄，非逐字原話）**：基準與驗收若在不同的 checkout 位置收集，nodeid 參數中含 repo 根絕對路徑的項目（例：`tests/test_ci_workflow.py` 以 workflow 檔絕對路徑參數化），只可把**已確認的兩個 repo 根路徑**（基準根、驗收根，都必須是已知輸入，不得從比對結果反推）替換成同一代號 `<ROOT>`，其餘逐字比對。報告必須：①同時附上**未替換**的原始比對結果；②列出每一個被替換的 nodeid；③確認替換前後兩份清單的 nodeid 總數不變、各自沒有重複（沒有不同 nodeid 因替換而合併）。

- **H4**：Dart 絕對 `suite.path` 在 repo 內部段落大小寫（或 junction、8.3 短檔名）與磁碟不同時，判成「沒有出現」，該記的紅燈沒記。方向是多擋，不會誤放。依階段 3 真實輸出再定。

- **S5h3-K1**（威脅模型外）：`run()` 對同一輸入做兩次 `str()`。程式內呼叫端若刻意傳入 `str()` 結果會變的物件（含覆寫 `__str__` 的 `str` 子類別），冒號檢查可被繞過。CLI 經 argparse 一律傳字串，碰不到這條路。包裝器不是防範「同一行程內惡意程式碼」的關卡：能這樣做的程式本來就能直接存取檔案系統。Jeff 2026-10-16 選擇記為已知限制。
