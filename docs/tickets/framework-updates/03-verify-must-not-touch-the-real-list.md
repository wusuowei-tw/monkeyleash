# 03 — g1_verify.py 不得動到正式保護清單

## 問題

`g1_verify.py` 驗 fail-closed 的方式是**把正式的 `~/.claude/g1-protected.txt`
搬走再搬回來**。這是**結構性需求**,不是一次次的權宜:每跑一次驗收就動一次,
而驗收是常態動作。

兩個後果:

1. **實際風險**:測試在改名與還原之間掛掉(例外、Ctrl-C、機器當掉),
   正式清單就停在「不在原位」的狀態。而清單不在 → G1 fail-closed → 所有指令被擋。
   復原要人手動改名回來,而那時 G1 正在擋所有東西。
2. **計數被污染**:ADR 0008 的殘留路徑登記目前 5 次裡有 3 次是驗收自己造成的。

## 判準

**殘留路徑的計數如果被驗收用途消耗,計數就在量錯的東西。**

那個計數要回答的是「這條缺口是不是變成日常繞路的預設路徑」。
驗收造成的次數與那個問題無關 —— 它量的是「我們驗了幾次」而不是「我們繞了幾次」。
混在一起的話,門檻會被無關的東西觸發,真正該觸發它的訊號反而被稀釋。

## 決定(已裁決)

### 一、覆寫來源用**聯集**,不用取代

額外來源**只能增加**保護路徑,**不能移除**。因此:

- 傳一個空檔 → 聯集不變 → **等於沒作用**,關不掉 G1
- 傳一個不存在的檔 → 同上(或 fail-closed,見下)
- 沒有任何輸入能讓保護範圍**變小**

**與豁免清單的方向刻意相反,對稱寫死:**

| 清單 | 允許的變化方向 | 理由 |
|---|---|---|
| `legacy-no-redlight.txt`(豁免) | **只能減** | 增加豁免 = 放寬權限 |
| `g1-protected.txt`(保護) | **只能增** | 增加保護 = 加強防護 |

**放寬權限要有證據,加強保護不需要。**

### 二、fail-closed 用**函式層注入**測,不搬檔案

`read_protected_list(path)` 做成**純函式**:吃一個路徑,回清單或 None。
測試傳一個不存在的路徑,斷言回 None(呼叫端據此 fail-closed)。
**正式清單完全不動。**

### 三、入口點永遠用寫死路徑

`main()` 不吃環境變數、不吃參數 —— 它呼叫 `read_protected_list(PROTECTED_LIST)`,
而 `PROTECTED_LIST` 是模組常數。可注入的只有那個純函式,不是入口點。

這樣「覆寫來源會不會變成關掉 G1 的路徑」這個問題**在設計上就不存在**:
沒有覆寫入口。

### 四、剩下的那一行接線,由**人**跑一次 live 探針

「入口點真的傳了寫死路徑」是 **F-044 的接線** —— 純函式測不到它。
需要一次真實觸發:把正式清單改名 → 跑一個會碰保護路徑的指令 →
確認 fail-closed 擋下 → 改回來。

**這一步由人手動做。** 人做的不算殘留路徑,**計數不會被驗收吃掉**。

## 佐證:裁決仍未落地,風險是真的(2026-08-14)

票 22 走到「驗一次保護清單」那一步時,**拒絕執行 `g1_verify.py`** —— 理由正是本票:
它會 `shutil.move` 走使用者剛手改完、還沒被任何東西驗證過的那一份清單。
裁決者核准該次拒絕。**本票裁決至今未落地,程式碼仍是原樣**,
所以每次要驗收都得繞路一次。這一則記在這裡,是為了讓「還沒修」有代價可數。

替代做法產出了一支唯讀探針(草稿區 `probe_g1_entries.py`),
**它就是本票決定二「`read_protected_list(path)` 純函式」的雛形起點**:
吃一個路徑、回清單或 None,呼叫端據此 fail-closed;全程不搬檔案。
移進 `g1_guard.py` 本體、並讓 `main()` 永遠傳寫死路徑(決定三),本票即可收尾。

探針比 `g1_verify` 多兩件事,落地時一併帶進來:

1. **斷言 `level1_hit()` 的回傳值**,不比對 stderr 子字串 ——
   後者會因為「訊息裡剛好包含這個子字串」而假通過(票 25 那條假綠就是這樣來的)。
2. **第五段:條目指向的東西真的存在嗎**(裁決 Aug 14 增列)。
   前四段的探針字串都是從條目本身組出來的,**打錯字的路徑照樣全綠** ——
   `g1_verify` 有同一個盲區,而 `machine-init.md` 第二節末正是警告這件事。
   產出是**待人工對帳的序號**,不是失敗判定:不存在未必是錯,但它保護不到東西。

## 怎樣算做完

- `g1_verify.py` 跑完之後,`~/.claude/g1-protected.txt` 的 mtime 與內容都沒變
  (要實際量,不是宣稱)
- `read_protected_list()` 有 fail-closed 的單元測試
- 聯集語意有測試:額外來源為空 / 不存在 / 含新路徑,三種都驗
- 那一行接線由人跑過一次 live 探針,結果記在票裡
