### 二、改了什麼

`tests/test_bootstrap.py`:`SH = shutil.which("sh")` → `SH = find_sh()`,依序試

```
which("sh") → which("bash") → C:\Program Files\Git\usr\bin\sh.exe
                            → C:\Program Files\Git\bin\bash.exe → None(照舊 skip)
```

**PATH 優先**:使用者的殼裡有什麼就用什麼,不拿寫死的路徑去蓋過它。

### 三、🔴 方向 3 自己帶出來的**第二個缺口** —— 實測撞到的,不是想出來的

接上 `sh.exe` 之後,那 5 條**真的開始跑了**,而其中 3 條當場紅:

```
bootstrap.sh: line 61: cut: command not found
```

**成因不在 `bootstrap.sh`**:PowerShell 的 PATH 上沒有 coreutils,子行程繼承的就是那個 PATH。

> ### **一個叫得動 `sh.exe` 卻沒有 `cut` 的環境,不是「跑得動 `bootstrap.sh` 的殼」。**
>
> **只挑殼、不帶它的工具鏈,換來的是一個【紅得不是地方】的結果 ——
> 它看起來像 `bootstrap.sh` 壞了,而三道檢查其實一道都還沒跑到。**
>
> **那比 skip 更糟**:skip 至少誠實說「沒有被證明過」,
> 而這種紅會讓人去修一個沒有壞的東西。

**處置**:新增 `sh_env()` —— 走寫死路徑那條時把 `C:\Program Files\Git\usr\bin`
**前置**(不覆蓋)到子行程的 PATH。**只有那一條會動 PATH**:
PATH 上就有 `sh` 的機器(Git Bash、Linux CI)本來就帶著自己的工具鏈,
再前置一個 Windows 專屬目錄等於**在 CI 上憑空插一個不存在的路徑**(有反控釘著)。

### 五、測試(紅燈先行,7 條)

`TestFindingShFallsBackToGitForWindows`,**每一條各封住一個退化解**:

| | 驗什麼 | 少了它 | 開工當下 |
|---|---|---|---|
| ① | PATH 什麼都沒有、Git for Windows 在 → **回那條路徑**,且 PATH 那輪依序試過 `sh`/`bash` | 這是病灶本身 | 🔴 紅 |
| ② | PATH 有 `sh` → **回 PATH 那個** | 一個「一律回寫死路徑」的實作也會讓 ① 綠 | 🔴 紅 |

| ④ | 兩邊都沒有 → **回 `None`**(skip 那條路還在) | 一個「永遠找得到東西」的實作會讓 skip 悄悄消失 | 🔴 紅 |
