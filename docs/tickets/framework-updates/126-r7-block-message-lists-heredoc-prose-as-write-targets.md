## 現象

一條 `mkdir -p .dev/reports && cat > '<檔>' <<'REPORT_EOF' … REPORT_EOF` 被 R7 擋下。
**擋得對**(fail-closed,方向正確),但擋下訊息把 heredoc 的**中文散文內文**
切成約一百段,當作「不在許可清單裡的段落」逐一列出。

列出來的東西裡包含 `項`、`筆數`、`---`、`1570`、`3` 這種**明顯不是路徑**的 token,
訊息開頭的「寫入目標」清單也出現
`本檔本身寫入`、`上面那次量測是在寫入本檔**之前**跑的。` 這類完整的中文句子。

## 證據(今日原始擋下訊息,首尾原文;中段列舉過長故省略,省略處已標明)

```
PreToolUse:Bash hook error: [python "$CLAUDE_PROJECT_DIR/.claude/hooks/gate.py"]: [六站閘門/前哨] [R7][enforce] 這個 Bash 指令會寫到沒有被許可的位置(FETCH_HEAD、(引號或跳脫使目標無法可靠切分)、本檔本身寫入、上面那次量測是在寫入本檔**之前**跑的。)。
     **許可是逐段比對的**(`&&` / `;` / `||` 各算一段)。
     這幾段不在清單裡:`mkdir -p .dev/reports`、`cat > '.dev/reports/2026-09-08T233524Z-laptop-align-verify.m…`、`61 ++ .claude/hooks/gate.py`、`357 ++++++++++- .claude/hooks/redlight.py`、
     〔中略:約一百段,全部是 heredoc 內文被切出來的片段〕
     …、`項`、`筆數`、`---`、`---`、`passed`、`1570`、`failed`、`0(結尾統計行**沒有** failed 欄位)`、`skipped`、`3`、`deselected`、`1`、`xfailed`、`3`、`耗時`、`228.28s (0:03:48)`、…、`ls -l .dev/reports/`
     其餘各段本來就許可 —— 把它們拿掉就過得了。
     **切分不認引號,也不認 heredoc 內文**:`<<'EOF'` 到 `EOF` 之間、
     以及引號裡的每一個 `;` / `&&` / `||`,一樣會被切成一段。
     所以「整條以 `git` 開頭」不代表安全 —— 訊息或腳本內文裡的一個分號,
     就會切出一段不以許可前綴開頭的段落。
     出口:**內文用 Write 寫成檔案**,再 `git commit -F <路徑>`
     或 `python <路徑>` 餵進去 —— 內文完全不進指令字串,
     就沒有東西可以被切。
     理由不是風格:從指令字串解析『寫到哪』解不完,而半套的解析器
     比零涵蓋更危險 —— 零涵蓋你知道它是零。所以入口收成一個,
     走檔案工具的話 R1–R6 全部適用。
     例外(附理由)在 gate.py 的 BASH_ALLOWED_CMDS / BASH_ALLOWED_TARGETS。
     指令裡出現 /dev/null **不會**讓其他寫入一起免檢。
(R7 只活在前哨:commit 看得到檔案內容,看不到你用什麼工具寫的。
 繞過前哨就沒有第二道了 —— 見 docs/adr/0008)
```

處置:照擋下訊息**自己指定的出口**走(改用 Write 寫檔),未繞過。

## 為什麼要緊

**擋得對,但訊息幫不上忙。**

擋下訊息的用途是讓被擋的人知道**為什麼**與**怎麼辦**。
這一則把兩件有用的事(「切分不認 heredoc 內文」與「出口是用 Write」)
埋在一百段噪音的後面 —— 而那一百段裡多數是中文句子,
讀的人第一眼看到的是「這些是我的寫入目標?」而不是「我該改用 Write」。

**這是訊息品質問題,不是判定問題。** 判定沒有錯:
不可判定就擋,那是票 112 定下的姿態。

## 方向(先寫死一句)

**不解析引號內文。** 票 112 明文禁止:
半套的解析器比零涵蓋更危險 —— 零涵蓋你知道它是零。
**所以本票不碰切分邏輯,只碰輸出。**

只在**段數超過門檻**時,把列舉改成摘要形式:

> 共 N 段、其中 M 段不在清單、列前 K 段、其餘未列出

門檻、`K` 的值、以及「前 K 段」怎麼挑(前 K 個?最像路徑的 K 個?)
**本票不預設**,留給動工時決定。
