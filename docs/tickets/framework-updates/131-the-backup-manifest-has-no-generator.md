## 為什麼要緊

### 1. 每次備份的成本是「一輪 agent」而不是「一行指令」

而備份要做的次數不是一次:9/7 做過、9/9 在做、**十月在美國還要重做**。

### 2. 十月在美國重做時,整個從零開始

那時:

- 這台桌機不在手邊
- 產出它的那幾輪對話早就結束
- **只剩下 `manifest.json` 這個成品,而成品不含產生它的方法**

### 3. **這是 `F-110` 那一族:規矩寫了,而沒有變成機器**

`CLAUDE.md` 逐字:

> **「要留存」是祈使句,而祈使句沒有主詞。**
> 每寫下一句「X 要留存 / 要記得」,立刻問「**不做會有什麼東西叫?**」——
> 答不出來的,就改寫成一張票,或當場做掉。

有一條裁決:**每一包要附機器產的路徑清單。**
**「機器產的」這四個字,目前是由一個人每次手工執行的。**
⇒ **沒有東西會叫。** 這張票就是「改寫成一張票」的那個動作。

> **⚠ 這條裁決現在住在哪裡 —— 本窗查證後的更正**

> 立案時我把它寫成「票 87 §八」。**查證後那是錯的。**

## 方向(**草案,不是裁決**)

寫一支產生器,**吃暫存夾 + 路徑清單,吐 manifest**。

### 輸入

| | |
|---|---|
| 暫存夾路徑 | 例:`C:\projects\_backup_stage_2026-09-09` |
| 路徑清單 | 例:`delta-2026-09-09.txt`(四欄:來源代號 / 相對路徑 / 位元組 / mtime) |

### 輸出

| 欄 | 怎麼來 |
|---|---|
| 逐檔 sha256 + 位元組數 | **機器算** |
| repo 座標(HEAD / porcelain) | **機器問 git** |
| `git bundle verify` 原始 stdout | **機器跑,原文照收不轉述** |
| 快照格(日期 + repo HEAD) | **機器填** —— `F-147` 的要求:沒有快照格,一張表分不出「沒變」與「沒重算」 |
| `method` / `media` / `done_at` / `done_by` / `notes` | **留空給人填**,而**空的要長得像空的**(見下) |

### 順便解掉的那條裁決

「**每一包要附機器產的路徑清單**」(2026-09-09 裁決,目前只住在 `.dev/reports/`)——
產生器把清單當輸入,**順手把它寫進 manifest**,那條裁決就從紀律變成構造。

### 動工時的四個判準(**逐條回答,不得跳過**)

| # | 判準 |
|---|---|
| ① | **一份檔案放不進自己的雜湊。** manifest 自己的 sha256 要放哪裡?9/7 是怎麼處理的?**先讀 rev-d 再動手** |
| ② | **人工欄位空著的時候,要長得像空的。** 9/7 主庫那包 `method`/`done_at`/`done_by` 全空,而**沒有東西說它們是空的** —— 產生器要讓「未記錄」是一個**顯式的值**,不是一個缺席的鍵 |
| ③ | **產生器的輸出要能與 9/7 的 `rev-d` 對得起來。** 換格式的話,舊備份就讀不了 —— 那是把已有的東西弄壞去換一個新東西 |
| ④ | **不得讓產生器去碰主庫那顆磁碟(G1 第一級保護路徑)或 `~/.claude/`(界線 A,票 130)。** 那兩塊的欄位一律留空給人填。**路徑本身刻意不寫在這裡** —— 它是 `leak_scan` 的個人 pattern,寫進版控會被擋(2026-09-09 實際攔下);要它的話讀 G1 的保護清單 |

> **② 是本票最容易做出反效果的地方。**
> 一支產生器會讓 manifest 看起來更完整、更權威 ——
> 而**它填不到的那幾格,在一份看起來完整的檔案裡更不容易被發現是空的。**
> (`CLAUDE.md`:「**留白比蓋章誠實**」;上游票 67/68 的 72 筆「無法判定」桶是同一句話。)

## 未證明

- **本窗沒有重算 `manifest.json` 的 sha256。** §2 只比對了位元組數(61798)。
  **位元組數相同不等於內容相同。**
- **沒有讀 `manifest.json` 的內容。** 「逐檔 sha256 / 五個 repo 座標 / 四段 bundle verify 原文」
  這三句是從 `.dev/reports/` 的描述來的,**不是本窗從該檔讀出來的**。
  ⇒ 動工第一步應該是**真的打開它**,把欄位結構量出來。
- **「rev-a → rev-d 全部手工組」是從報告的敘述來的**,不是從 git 歷史證出來的
  (那個暫存夾不在版控裡)。
- **沒有量寫那 61,798 B 一共花了幾輪、幾分鐘。** 「一輪 agent 工」是那份報告的估計,
  **不是計時**。⇒ 本票不宣稱省下多少時間,只宣稱**成本的量級是「輪」不是「秒」**。
- **沒有查下游有沒有同樣的東西。** 本輪不碰下游。
- **沒有寫任何一行產生器的程式碼。** 上面〈方向〉全部是草案。
