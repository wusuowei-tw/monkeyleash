## 一、事實(2026-08-29 唯讀實查)

四個使用者層控制檔的讀取端,**三個用 `utf-8-sig`,一個用 `utf-8`**:

| 檔 | 讀取端 | 編碼 | 有 BOM 時 |
|---|---|---|---|
| **`g1-protected.txt`** | **`g1_guard.protected_entries()`** | **`utf-8`** | 🔴 **BOM 黏進第一條路徑** |
| `shadow-clamp.txt` | `gate.read_shadow_clamp()` | `utf-8-sig` | ✅ 免疫 |
| `leak-patterns.local.txt` | `leak_scan._read_patterns()` | `utf-8-sig` | ✅ 免疫 |
| `upstream-roots.txt` | `gate.read_upstream_root()` | `utf-8-sig` | ✅ 免疫 |

**那三個不是碰巧** —— 它們的 docstring 逐字寫著理由:

> **用 `utf-8-sig`:PowerShell 的 `Set-Content -Encoding utf8` 寫的是帶 BOM 的 UTF-8,
> BOM 黏上鍵名就解析失敗 —— 而 fail-closed 系統的故障是隱形的,
> 輸入端的坑要在進門前排掉。**

## 二、🔴 現況:**目前沒有 BOM。這是理論風險,不是現況**

**實測(2026-08-29,裁決者在自己的終端機)**:

```
g1-protected.txt 前三位元組 = 35, 32, 71    ( "# G" )
              **不是** 239, 187, 191
```

**⇒ 這一條現在沒有在發作。** 票面不得寫成「保護清單目前有洞」——
那會讓一個理論風險穿上事故的衣服(`F-149`:嚴重度不要跑在證據前面)。

**它會在什麼時候變成現況**:`g1-protected.txt` 是**新機器上第一次建檔**的四份之一,
而 PowerShell 最自然的兩種寫法(`Set-Content -Encoding UTF8`、
`Add-Content -Encoding UTF8` 對不存在的檔)**都會寫 BOM**(`F-146` 實測)。
**入口已先擋住**:`docs/machine-init.md` §一之零 指定建檔方式與三位元組驗收。
**但那是紀律,不是這一條的修法。**

## 三、發作時會發生什麼(**這一格是本票的分量所在**)

BOM 黏在第一條路徑前面 ⇒ 那條路徑**再也不會被命中**。而現場長這樣:

| 觀察點 | 看到的 |
|---|---|
| `cat` 清單 | 那一行**在** |
| 行數 | **正確** |
| `ls` | **正常** |
| 那條路徑的保護 | **沒有了** |
| 有沒有東西叫 | **沒有** |

> ### **這是 `F-139` 的第二個實例:沒跟上慣例的那一個,正好是守自己的那一個。**
>
> `F-139`:第一級擋不住 `~` 寫法,**而它保護的第一個對象就是自己**。
> 本票:四個讀取端只有一個沒改用 `utf-8-sig`,**而它讀的正是保護清單**。
>
> **兩次都不是隨機落點。** 保護清單是唯一一個「守衛自己是它的讀者」的檔案,
> 而**守衛自己那一份程式碼,是唯一沒有別人在替它跑同一套慣例的地方**。

### 🔴 失去保護的會是哪一條 —— **實測,不是慣例**(修正 2026-08-29)

**本票初稿寫**:「清單第一行**慣例上**寫清單自己(`machine-init.md` §一.2 的範例就是這樣),
所以最可能失去保護的是 `ADR 0009` 的地基」。

> ### **那句話在這台機器上不成立。**

**實測(2026-08-29,裁決者在自己的終端機看)**:

| | 這台機器的實際情形 |
|---|---|
| **第一段第一條** | **OneDrive 備份資料夾** |
| **清單自己** | 在**第 3 段**,不是第一條 |

**⇒ BOM 若發生,失去保護的是【備份資料夾】,不是 `ADR 0009` 的地基。**

**仍然嚴重,但嚴重的方式不同**:那是**備份**——
而票 87 整條線(9/11 海運、控制檔備份、`_ticket84_backup` 不刪不改名)
都站在那顆資料夾上。**失去保護的是那個。**

> ### ⚠ **初稿那一格本身就是 `F-152` 的實例(退化情形):
> 我用【慣例】推導出一個關於【這台機器】的結論,而沒有量它。**
>
> 「用通則推導個案而不量它」是量測獨立性的極端情形:**獨立性是零** ——
> 那個結論百分之百來自我對那個對象的模型。
> **而它比一個壞掉的量測更難察覺,因為它連一個數字都沒有留下,只有一句聽起來合理的話。**

**⇒ 本節的依據是【實測】。** 清單內容不抄進票面(`F-122`:票面裡的內容快照
是一份沒有人在守的副本),只記**結構事實**:第一條不是清單自己。

## 四、修法(**一行,但不在本輪**)

`g1_guard.protected_entries()` 的 `encoding="utf-8"` 改成 `"utf-8-sig"`,
與其他三個讀取端一致。

**驗收(正反控,缺一不可)**:

| 方向 | 要驗什麼 |
|---|---|
| **正控** | 一份**帶 BOM** 的清單:第一條路徑**仍然被擋** |
| **反控** | 一份**不帶 BOM** 的清單:行為與現在**完全相同**(沒有多擋、沒有少擋) |

**少了反控**,一個「把整份清單讀壞」的改動也會讓正控全綠。

## 五、為什麼**不排上線前**

**它是動守衛,而守衛週一公開。** 與票 88 第五節同一條理由:

> **上線前改守衛,等於在沒有人手的那一週,把最後一道防線換掉。**

而本票的急迫度比票 88 更低,因為 **第二節:現在沒有 BOM**。
**入口已由 `machine-init.md` §一之零 擋住(紀律),真正的修法排 9/11。**

## 六、⚠ 本輪**不**放進 `KNOWN_GAPS`

`KNOWN_GAPS` 的語意是「**放行 → 印已知缺口並通過;擋下 → 記為不合格**」。
**而這一條現在不會放行任何東西** —— 沒有 BOM,清單讀得好好的。

> **把一個沒有在發作的東西放進 `KNOWN_GAPS`,會讓那一桶從「已知漏擋」
> 變成「已知的擔憂」,而那兩件事的驗收語意相反。**

**⇒ 有票號(本票)但不進那一桶。** 這兩件事不是同一件,
本票的存在已經滿足「不是沒人管的洞」那個門檻。
