## 現況

`sync.py` 的護欄:

| 護欄 | 涵蓋 |
|---|---|
| `refuse_if_unclassified` | 來源 |
| `refuse_if_dirty` + `gitlink_unsettled` | 目標工作樹 |
| `refuse_if_duplicate_headings` | **只有 `docs/agents/friction-log.md`** |
| `unmigrated_friction` | **只有 `docs/agents/friction-log.md`** |
| 寫後 hash 重驗 | 這一輪寫過的檔 |
| `untouched` 桶 hash 不變 | 非 `copy` 桶 |

**`copy` 桶的其他檔案,下游寫進去的東西一律靜默被覆蓋。**

## 觸發它的實例(不是假想)

2026-08-19,票 63/64 推送後的 dry-run:

```
M docs/adr/0012-shadow-mode.md
```

| | 行數 |
|---|---|
| 量化 `docs/adr/0012-shadow-mode.md` | **206** |
| 上游同檔 | **63** |

量化當天(`962133f`)寫了 143 行〈補遺〉,內容是**裁決**不是筆記:
零筆規則的出口、假陽率採三分類、`shadow.json` 進 G1 保護清單。

**`--apply` 會把它們刪掉,而且不會有任何訊息。**
擋下它的是**我剛好去查為什麼那個檔在清單裡** —— 那不是機制。

> `unmigrated_friction` 的 docstring 自己寫著:
> 「覆蓋會把它們刪掉,所以這是拒絕的條件,不是警告 —— 警告會被略過,
> **而被刪掉的條目沒有第二份**。」
> **那句話對 ADR 一字不差地成立,而守衛只裝在 friction-log 上。**

CLAUDE.md 常駐檢查項的又一個實例:
**收了一個入口,就回頭問它的同類入口在哪。**
問法不是「我還想得到什麼」,是**去列舉 `copy` 桶裡所有「下游會自己往裡面寫」的檔案**。

## 這是設計題,難在「比什麼」

friction-log 好比,因為它有**機器可辨識的條目邊界**(`^## F-\d+`),
差集是條目號碼的集合。ADR 沒有那個結構:

| 候選判準 | 問題 |
|---|---|
| 比行數(目標比來源長就拒絕) | 下游把上游一段**刪短**同樣是本地改動,而它不會被抓到;而且上游正常增長也會誤觸 |
| 比 `#` / `##` 標題集合 | ADR 的標題不是識別碼(`## 現況` 在每份 ADR 都有),集合差集會噪音滿天 |
| 目標檔案的 hash ≠ 上游任何一個歷史版本的 hash → 判為「下游改過」 | **這個判準最接近正確**:它問的是「這份檔案是不是某個上游版本的原樣」。代價是要查上游的物件庫,而票 59 剛記過「上游的歷史可能被改寫」 |
| 用 provenance:同步時記下寫進去的 hash,下次比對「目標現值 ≠ 上次寫入值」→ 下游改過 | **不需要查上游歷史**,只需要本地的一筆紀錄。與現有 `.dev/provenance.jsonl` 同一個機制 |

**傾向最後一個**,理由是它把問題從「內容比對」換成「**這個檔案自從我上次寫它之後有沒有被動過**」——
而那是一個**封閉且可判定**的問題,不需要理解檔案格式。
**對封閉集合用 pattern 不是防線弱,是選錯工具**(CLAUDE.md)。

### 設計時要先回答的

1. **`copy` 桶裡哪些檔案下游會自己寫?** 先列舉,不要猜。
   已知:`docs/adr/`(本票)、`docs/agents/friction-log.md`(已有守衛)。
   **其餘的要逐一問過**,而不是等下一次撞到。
2. **provenance 目前只發給「與上游逐位元組相同」的檔**(`identical_copy_files`),
   而那正好是**沒有被下游改過**的那一群 —— 所以「有證 = 沒被改過」可能已經成立,
   要查的是它是不是每個 `copy` 檔都有一筆。
3. **第一次同步(下游還沒有任何紀錄)怎麼辦?** fail-closed 要倒向拒絕還是放行?
   倒向拒絕會讓全新安裝的 repo 第一次 sync 就被擋 —— **票 19 的死循環形狀**。
4. **拒絕之後的出口是什麼?** friction-log 的出口是「搬去 `friction-local.md`」。
   ADR 沒有對應的「本地檔」概念 —— **要不要有一份 `docs/adr-local/`?**
   若沒有出口,這道守衛會變成「永久拒絕同步」。
   > **這一題比機制本身重要。** 一道沒有出口的 fail-closed 守衛,
   > 第一次擋住的時候就會被繞過或拿掉。

## 落地驗收要多兩項(2026-08-21,上游輪裁決)

**由來**:影音 sync 輪曾裁「上游開票把 `certify` 發證判準從『`copy` 桶』改成
『與上游逐位元組相同』」。上游輪全庫查證的結果是 **那張票沒有開**
(`grep -rln "certify" docs/tickets/` 只命中票 39,而票 39 是史料手術票,
`--certify` 在那裡只是修復手段,不是題目)。

**而問題本身成立** —— `docs/adr/` 於 2026-08-19 標 `ask` 止血之後,
**15 份 ADR 補不了證**(`git ls-files docs/adr | wc -l` = 15,
`0001`–`0012` + `F-0013` / `F-0014` / `F-0015`)。

**裁決:不開新票,掛本票。** 理由:本票落地時 `docs/adr/` 改回 `copy`,
那 15 檔的發證問題**自動消失** —— 開一張獨立票去改 `identical_copy_files()` 的
集合語意,很可能在本票落地後整個不需要,而它要動 `sync.py` 核心 +
重評 `tests/test_sync.py` 的四條 certify 測試。

**所以本票的落地驗收多兩項:**

1. **`docs/adr/` 標記改回 `copy`**(`.agents/portable-manifest.txt` 的 `ask` 註解
   已寫著到期條件「票 66 落地時改回 `copy`」,引用不重述)。
2. **兩個下游各跑一次 `python .claude/portable/sync.py <target> --certify --apply`**,
   替那 15 檔補證,並確認 `.dev/provenance.jsonl` 逐筆對得上。
3. **(2026-09-02 加)改回 `copy` 那次 `--apply` 落地之後,兩個下游各跑一次
   `status` 的 Sync Health,`waterline` 行要回到 **1 個 commit**。**

   這一格是前兩格的**外部觀測**:第 1、2 項驗的是「我做了那個動作」,
   第 3 項驗的是「那個動作在下游身上生效了」——
   **參照物不同,盲區就不同,所以不是同一個檢查跑兩遍。**
   而它便宜到不該省:一行輸出,而且是別人(`status.py`)算的,不是本票自己算的。

### 順帶記一行:`identical_copy_files()` 的 docstring 與程式不是同一個判準

```
sync.py  def identical_copy_files(src, target, marks):
             """`copy` 桶裡**與上游逐位元組相同**的檔案。…"""
             …
             if manifest.explicit_mark(rel, marks) != "copy":
                 continue
             if file_hash(sp) is not None and file_hash(sp) == file_hash(tp):
```

**docstring 講的是一個條件,程式做的是兩個條件的交集**(在 `copy` 桶 **且** 逐位元組相同)。
`--certify` 與一般 sync 共用這個集合,所以桶標一改,發證範圍就跟著變 ——
**而讀 docstring 的人不會預期這件事。**

> **記這一行的理由**:只把桶標改回 `copy` 會讓症狀消失,而**語意差留在原地**。
> 下一次有人把某個 `copy` 檔改成 `ask` 或 `generate`,同一件事會再發生一次,
> 而那時 15 檔那個標本已經沒有人記得了。
> **症狀消失與缺陷修好,在驗收表上長得一樣。**

### 登記(2026-09-02,票 100 waterline 首跑):**`ask` 桶的憑證會凍結**

上面第 94 行說的「**15 份 ADR 補不了證**」,現在有了**下游側的實測長相**。

`docs/adr/` 標 `ask` 之後,`sync` 不會替那 15 檔重發憑證,
於是它們的 `upstream_commit` 永遠停在最後一次人工帶過去的時點。
而票 84 的身分改寫把那個時點的 sha 換掉了,所以現在兩個下游的實測是:

| 下游 | waterline | 活著那批 | 凍結那批(死 sha) |
|---|---|---|---|
| 影音 | **2 個 commit** | `50251de…` 96 個 path | `a9242cc97599…` **15 個 path** |
| 量化 | **2 個 commit** | `1a096507…` 90 個 path | `11613002c2af…` **15 個 path** |

兩邊那 15 個 path **逐字相同**,就是 `docs/adr/` 的全部 15 份。
完整數字與主展品在**票 59** 的〈現況證據(2026-09-02)〉,本節不重述。

> **⚠ 這一則不是要本票提前動工。**
> 要緊的是:**在本票落地之前,`waterline` 印「2 個不同 commit(未收齊)」
> 是一個正確的訊號,不是噪音。**
> 沒有這一行的話,下一個看到它的人會去「修」那個顯示,
> 而那正是把一個真的偵測到的洞當成誤報關掉 —— 三次 fail-open 的同一種起手式。

裁決者 2026-09-02 裁 **C:不開新票** —— 現場證據進票 59,凍結這件事登記在本票。
