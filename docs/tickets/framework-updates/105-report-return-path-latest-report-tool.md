```
①切分 ^#{2,3}\s*第一段【給裁決者】\s*$ 與第二段同式,兩級都吃;
  CLAUDE.md 改 ## 登記候選不動

```

### 裁一的背景:**規範寫 `###`,而實作一直寫 `##`**

```
CLAUDE.md:329:### 第一段【給裁決者】
CLAUDE.md:343:### 第二段【給裁決助手】
```

而 2026-09-04 這一整天產出的回報,**每一則都是 `##`(二級)**。

> **一個照 `CLAUDE.md` 寫死 `^### 第一段` 的切分器,對今天全部的回報一條都切不到** ——
> 而它會回「未切分」,**看起來像格式壞了,實際是切分器抄錯了層級**。

⇒ 裁一取 `#{2,3}`:**兩級都吃**,不賭哪一種是對的。

### 裁三的背景:**mtime 的失敗是無聲的**

| 判準 | 什麼時候挑錯 |
|---|---|
| 檔名字典序 | 命名格式不固定寬度;**有人手動改名或補寫一份舊的** |
| **mtime** | 🔴 **`git checkout` / `clone` / 解壓縮會把 mtime 重設成當下**(`F-135` 逐字:「逐位元組相同的複本」在**內容**上成立,在**時間屬性**上不成立);編輯一份舊回報改錯字就讓它變成最新;跨機器同步不保證保留 mtime |

> ### **兩者的失敗方向相反,而這決定了該選哪個:**
> **檔名排序錯在「有人做了什麼」;mtime 錯在「檔案系統做了什麼」。**
> 前者看得見(改名是一個動作),**後者完全無聲** —— 沒有人會記得 `git checkout` 動過 mtime。

**⇒ 裁三:字典序,且【不用 mtime 當備援】** ——
兩個判準混用時,「它們不一致」這件事不會有人發現。

## 🔴 收票時裁決者抓到的缺陷:`report:` 第三欄答錯了問題

裁決者在 Desktop 上看到第三欄印 **`樹共 348 筆 commit`**,當場問「這是什麼」。

**它是 `git rev-list --count HEAD`** —— **HEAD 可達的 commit 總數**。

| | |
|---|---|
| 欄名問的 | 這份回報**過期了沒有** |
| 那個值答的 | **這棵樹有多大** |
| 為什麼撐過了驗收 | **它每一輪都會變大,所以看起來像在動、像有意義** |
| 誰抓到的 | **裁決者看一眼** —— 25 條測試、十條紅燈、三層驗收,**沒有一條問過這件事** |

**修法**(裁決指定):`git rev-list --count --since=<回報檔名的時間> HEAD`,欄名改「回報後 N 筆」。

**時間取自【檔名】不取 mtime** —— 與 `latest_report_name()` 同一條理由
(`F-135`:mtime 會被 `git checkout` 重設,而那件事完全無聲)。
**同一份資料只能有一個時間來源**,混用的話「它們不一致」不會有人發現。

**補的三條測試**(`TestReportLineSaysHowStaleTheReportIs`):

| 測試 | 判準 |
|---|---|
| `test_a_report_newer_than_head_counts_zero` | 回報比 HEAD 新 → `回報後 0 筆` |
| `test_commits_after_the_report_are_counted` | 三筆 commit(一前兩後)→ `回報後 2 筆` |
| `test_the_field_is_not_the_total_commit_count` | **負控**:兩筆 commit **都在回報之前** → `回報後 0 筆` 且**不得出現「樹共」**。這一格才真的分得開總數(2)與回報後(0) |

紅燈原文(修之前),**三格逐字印出缺陷**:

```
AssertionError: …;HEAD 2026-09-04T08:00:00Z;樹共 1 筆 commit     (要 回報後 0 筆)
AssertionError: …;HEAD 2026-09-04T10:00:00Z;樹共 3 筆 commit     (要 回報後 2 筆)
AssertionError: …;HEAD 2026-09-04T08:00:00Z;樹共 2 筆 commit     (要 回報後 0 筆)
```

修後對**真實 repo** 實測:

```
report: 2026-09-04T083627Z-ticket-105.md;HEAD 2026-09-04T16:38:36+08:00;回報後 1 筆  (source: .dev/reports/)
```

`回報後 1 筆` 正確 —— `9b165a5` 是那份回報寫完之後的那一筆。

### ⚠ 這一格對本票方法論的意義

**十條紅燈、25 條正控、三層驗收全過,而一個【答錯問題的欄位】從頭到尾沒有被問過。**

> **測試問的是「這個值算得對不對」,沒有問「這個值答的是不是那個問題」。**
> 而後者**只有讀的人問得出來** —— 因為只有他知道欄名在問什麼。

這不是測試寫得不夠多,是**測試與欄名之間沒有一條線**:
我寫的每一條斷言都是拿實作的行為去比實作的行為(材料同源,`F-152` 的形狀),
**而「欄名」這個獨立來源從來沒有進過斷言**。
