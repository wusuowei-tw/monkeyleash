## 三、六條裁決(2026-09-04,Jeff,逐字)

```
①切分 ^#{2,3}\s*第一段【給裁決者】\s*$ 與第二段同式,兩級都吃;
  CLAUDE.md 改 ## 登記候選不動
②part=all 上限 40000 字,截斷帶 [截斷:原 N 字/回傳前 M 字] 標記,
  其他三支無上限登記候選
③檔名 YYYY-MM-DDTHHMMSSZ-<slug>.md 字典序取最新,不用 mtime
④三種空各回不同「未記錄(…)」,切不到回整份加 [未切分:找不到段落標題]
⑤乙段:status.py Evidence 加一行 report:(最新檔名、HEAD 時間、落後幾筆 commit;
  三種空同 ④),friction 候選「看得見不是擋得住」收票時重查號
⑥REAL:Jeff 重啟 Desktop 後先叫 latest_report 當重啟證明。
```

### 裁一的背景:**規範寫 `###`,而實作一直寫 `##`**

```
CLAUDE.md:329:### 第一段【給裁決者】
CLAUDE.md:343:### 第二段【給裁決助手】
```

而 2026-09-04 這一整天產出的回報,**每一則都是 `##`(二級)**。

> **一個照 `CLAUDE.md` 寫死 `^### 第一段` 的切分器,對今天全部的回報一條都切不到** ——
> 而它會回「未切分」,**看起來像格式壞了,實際是切分器抄錯了層級**。

⇒ 裁一取 `#{2,3}`:**兩級都吃**,不賭哪一種是對的。

### 裁三的背景:**mtime 的失敗是無聲的**

| 判準 | 什麼時候挑錯 |
|---|---|
| 檔名字典序 | 命名格式不固定寬度;**有人手動改名或補寫一份舊的** |
| **mtime** | 🔴 **`git checkout` / `clone` / 解壓縮會把 mtime 重設成當下**(`F-135` 逐字:「逐位元組相同的複本」在**內容**上成立,在**時間屬性**上不成立);編輯一份舊回報改錯字就讓它變成最新;跨機器同步不保證保留 mtime |

> ### **兩者的失敗方向相反,而這決定了該選哪個:**
> **檔名排序錯在「有人做了什麼」;mtime 錯在「檔案系統做了什麼」。**
> 前者看得見(改名是一個動作),**後者完全無聲** —— 沒有人會記得 `git checkout` 動過 mtime。

**⇒ 裁三:字典序,且【不用 mtime 當備援】** ——
兩個判準混用時,「它們不一致」這件事不會有人發現。

### 🔴 裁六:**先叫 `latest_report` 當重啟證明**

**改 `mcp_server.py` 之後,Desktop 裡那個還活著的行程跑的仍是舊碼** ——
Desktop 是用 `claude_desktop_config.json` 的 `args` 起一個**子行程**(票 101 `:669`),
而 stdio server 的程式碼在**行程啟動時**載入。
票 101 `:584` 逐字:「**重啟 Claude Desktop**(改設定不重啟不生效)」。

**沒重啟的兩種假訊號:**

| 情況 | 看起來像 |
|---|---|
| 沒重啟就叫 `latest_report` | 「未知工具」→ 看起來像**沒註冊成功** |
| 沒重啟而繼續叫三支舊工具 | 照常回答 → 看起來像**一切正常** |

⇒ **REAL 的第一步固定是叫 `latest_report`**:
它**存在**就證明跑的是新碼,**不存在**就證明還沒重啟 ——
**這個觀測本身就是重啟證明**,不必相信任何人的記憶。
(票 101 用過同型的觀測:該票 `:645` 用 server 起動時間戳分辨「Desktop 自己起的」與 agent 起的。)

## 六、⚠ 乙段的誠實標註(**收票時不得因為做完而改口**)

> ### **`report:` 那一行是【看得見】,不是【擋得住】。**

| | |
|---|---|
| 它做什麼 | 在 `status` 輸出裡印一行 |
| 它**不**做什麼 | 不擋 commit、不擋工具呼叫、不讓任何東西失敗 |

**選它的理由是「便宜且零誤報」,不是「它解決了問題」** ——
擋 commit 會誤擋(有些輪次本來就不該有回報檔),而**被煩到的規則會被整條關掉**。

> `CLAUDE.md` 那句「**被看到與被處理之間沒有任何東西**」
> **對這個提案本身也適用**。寫在這裡,免得收票時那一行被讀成「F-110 已修」。
