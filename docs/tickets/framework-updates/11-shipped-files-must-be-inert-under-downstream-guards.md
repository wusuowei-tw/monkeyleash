# 11 — 框架出貨檔案必須在下游守衛底下惰性

## 由來

影音 repo 的 D21 cookie 護欄擋下了框架出貨的 `tests/test_scanner.py`:
它拿 cookie 選項名當正控樣本,**靜置成文**,pattern 直接比中。

框架的測試檔在下游是**被掃描的資料**,不是可信的自己人。
出貨檔案會落進每一個安裝的 repo,而那些 repo 各自有自己的內容守衛 ——
框架不知道有哪些,也不該知道。所以出貨檔案必須對**任意**內容守衛惰性。

## 查證結果(2026-08-13,對整棵出貨樹跑三條下游 pattern)

| 位置 | 比中 | 說明 |
|---|---|---|
| `tests/test_scanner.py:41` | `--cookies\b` | 拼接點切在 `-from-` 之後,前半仍含完整 `--cookies` |
| `tests/test_scanner.py:48` | 三條全中 | `RuleGroup` 的 **regex 字面量**本身就是完整字串,原診斷沒點到 |
| `docs/agents/friction-log.md:963` | 三條全中 | F-061 的內文;標 `copy`,會裝進每個 repo |

## 範圍

- 正控字串一律**執行時拼裝**,拼接點必須讓三條 pattern 對靜置檔案全部比不中
- **測試效力不得下降**:掃描器收到的仍是拼好的完整字串
- 檔內註明為什麼這樣寫(下游守衛惰性要求)
- 加一條**自我檢查**:本檔不得含有自己用到的樣本字串字面量 ——
  否則下一個人把它 inline 回去,沒有東西會出聲

## 散文的邊界(要裁,不在本票自決)

`friction-log.md` 那一處目前無害,**但只是因為下游守衛豁免散文**
(`cookie_ban` 的 `DOC_SUFFIX`)。那是下游的一個決定,不是框架能倚賴的性質。

兩難:改寫散文以規避字面,正是 `DOC_SUFFIX` 存在要避免的稅
(「規則的說明本身必須寫得出來」,F-062 學到的:防禦清單長得像它要擋的東西)。
本票只處理**非散文**出貨檔;散文那一處留著並記錄理由,見 F-073。

## 怎樣算做完

- 三條 pattern 對出貨樹的非散文檔案零命中(機器檢查,不是人工掃過)
- `tests/test_scanner.py` 的正反控行為與修改前完全相同
- 有一條測試會在樣本字串被 inline 回去時變紅
