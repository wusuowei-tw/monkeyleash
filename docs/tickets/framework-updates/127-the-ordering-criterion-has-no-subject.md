# 票 127 —— F-164 的順序判準沒有主詞

**狀態**:立案。**本票今日只立案,未動工。**
**發現於**:2026-09-09,筆電(hostname `14X`),上游 HEAD `63cd0fa`。
**排期**:筆電期(2026-09-10 – 2026-09-28)。

## 現象

F-164 留下一條可搬走的判準(失敗訊息分不出兩個原因時,把能區分其中一個的檢查排前面),
而**執行它的只有文字與記性**。F-164 自己在最後一行明說了這件事。

## 證據(今日從檔案讀出的原文)

### 一、F-164 自己的收尾(`docs/agents/friction-log.md:7293` 起,該則最末段)

```
### ⚠ 這一則沒有解決的部分

**沒有任何機器在管它。** 守它的只有這段文字加上下一個人記得把順序排對。
```

### 二、判準本體住在票 87 §十六(丙)(`87-backup-has-no-staleness-trigger.md:1263-1277`)

```
#### (丙)★ 判準:**順序決定了診斷能力**

**先驗 `sha256`、後驗密碼** —— 所以密碼失敗的那一刻,
**我們已經知道檔案是好的**,問題只可能在密碼。

**反過來做的話**,那一小時會花在猜「該重下載,還是該重打包」——
而那是**打包前兩天最貴的一小時**。

> **這是「順序決定安全性」判準的實例,記進票面。**
>
> 一般化:**當一個檢查的失敗訊息無法區分兩個原因時,
> 把能區分其中一個原因的檢查排在它前面。**
> 那不會讓失敗訊息變好,但會讓失敗**發生時你已經知道答案的一半**。

**⚠ 這一次的順序是刻意排的,不是碰巧。** 記下來是因為
**碰巧對與排過,在結果上長得一樣** —— 而下一次要靠的是後者。
```

**它是一段散文,不是一份會被照著跑的清單。**

### 三、⚠ 同一張票已經指名過這個缺陷族(`87-...:623`)

```
**⇒ 所以修法不能是「協調」或「講好順序」**(那是祈使句,`F-110`),
```

**票 87 在第 623 行認出「祈使句」是 `F-110` 那一族並據此否決了一個修法,
然後在第 1263 行寫下另一條沒有機器的順序判準。**
同一張票、同一個族、相隔 640 行。

## 為什麼要緊

這是 **`F-110` 家族**:**「要留存 / 要記得 / 順序不可反」是祈使句,而祈使句沒有主詞。**
判準寫在**正確的地方、正確的時點**,而**搬到哪裡都沒用** ——
它需要的不是位置,是執行者。

而第三項證據讓它更難堪:**族已經被命名,而且就在同一張票裡。**
`CLAUDE.md` 那條逐字適用 ——
**「命名是為了讓它可搜尋;只命名不搜尋,等於把索引建好然後不查。」**
這一次連搜尋都不必:兩處在同一個檔案裡。

**下一次做備份驗收的人**,若沒有讀到票 87 §十六(丙)那一段散文,
會很自然地先跑 `7z t`(那是最直覺的「測一下檔案好不好」),
而那正是被否決掉的順序。**不會有任何東西出聲。**

## 方向

**把驗收順序寫成一份會被照著跑的清單。**

「會被照著跑」是本票的重點,不是「寫下來」——
現在已經寫下來了,寫下來不夠。
清單長什麼樣(腳本?驗收表?測試?)、住在哪裡、由誰觸發,**本票不預設**。

判準:**做完之後要能回答「不照順序做的話,什麼東西會叫?」**
答不出來就還是一句安慰。

## 未證明

- **裁決者轉述的那句話與原文不同,今日已核對。**
  裁決寫的是「F-164 自己寫著『順序目前寫在票 87 §十六 的判準裡,
  而那是一句祈使句』」—— **F-164 裡沒有這一句**。
  F-164 實際寫的是「沒有任何機器在管它。守它的只有這段文字加上下一個人記得把順序排對。」
  **兩句意思同向,但不是同一句。本票用的是檔案裡的原文。**
- **這條判準至今被違反過幾次。** 沒有回頭掃過任何既有的驗收流程 ——
  `CLAUDE.md` 那條「修好一個偵測器之後回頭重掃既有資料」在本票**尚未執行**。

  不是搜「祈使句」這個概念 —— 概念搜不到。
