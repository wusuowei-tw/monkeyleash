## 排水紀錄格式(本票的權威定義)

```
# drained: <path> <YYYY-MM-DD> <ticket>
```

| 規矩 | 值 | 為什麼 |
|---|---|---|
| 行首 | **必須是 `#`** | `_entries_from_lines()` 照舊把它丟掉 —— **排水紀錄永遠不會被讀成清單條目**。讀成條目就等於發一張豁免 |
| 辨識 | `#` 之後去空白,**必須以 `drained:` 起頭** | 不以它起頭的註解 = 一般散文,**忽略,不算格式錯誤**(舊的散文排水紀錄因此原地保留不刪,F-036) |
| 欄位 | `drained:` 之後以空白切成**恰好三段**:路徑、日期、票號 | 三段是「至少含路徑、日期、依據票號」的最小形 |
| 日期 | `\d{4}-\d{2}-\d{2}` | 固定寬度,排序即時序 |
| 票號 | `[A-Za-z0-9-]+` | 下游用自己的三字母前綴(`TSA-001`),前綴進號碼本身 |
| **格式錯誤的處置** | 認得出是排水條目、欄位不合格 ⇒ **malformed**:**不計入 `drained`**,**且要出聲** | 不計入的方向是 **fail-closed**(少算一筆排水 ⇒ 完整性判定**轉紅**,不會誤放行);出聲是因為**一個打錯字的控制行若靜默地不生效,它看起來與生效一模一樣** |

**契約**:`drained_from_lines(lines) -> (drained: set[str], malformed: list[str])`
—— **只解析傳入的 `lines`,不自行開檔**。

### ⚠ 消費端限制

**只有測試用它。R3 / R6 / #10 任何判定都不得讀排水紀錄。**
讀了就等於讓「清單以外的一行字」也能影響豁免,而那正是 R6 存在的理由
(ADR 0006:「被 R3 擋下的人只要在清單末尾加一行就豁免到手」)。

## 完整性判定的新形狀

`go_live` / `entries` / `drained` **必須從同一次成功讀取的 `lines` 解析** ——
工作樹的排水紀錄配 index 的條目會混出一份誰都沒寫過的清單(票 55 同形)。

保留原有斷言,再加三條:

| 約束 | 意思 |
|---|---|
| `entries ⊆ expected` | **原有,一個字沒放寬**:清單只減不增 |
| `expected − entries − drained = ∅` | 少掉的每一筆都要有排水紀錄(**取代**舊的「每筆都要 `redlight_missing() is None`」) |
| `drained ∩ entries = ∅` | 不能同時在清單又被排水 —— 兩種互斥狀態 |
| `drained ⊆ expected` | 被排水的必須曾在 go-live 樹裡 |

**不再呼叫 `redlight_missing()`、不再讀 `.dev/test-runs.jsonl`** ——
環境相依整條就來自那一次呼叫。
讀取失敗 / `git ls-tree` 失敗 **一律明確失敗**,不得當成空集合而意外通過(F-001 的形狀)。
