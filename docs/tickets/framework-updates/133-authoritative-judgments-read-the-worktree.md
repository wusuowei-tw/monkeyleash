## 問題陳述

**不是「把 N 個呼叫點改成讀 index」。** 正確的問題句是:

> **每一格在不同的執行上下文裡,權威輸入到底應該是哪一個版本?**

理由寫在〈修法方向〉的更正段:**R4 / R5 / R6 / R9 沒有現成的分岔點**,
所以這不是一個「換 reader」的工程,是一個**每一格各自回答「該信哪個版本」**的判斷題。

### 兩個攻擊面,不是一個

| | 讀錯的是什麼 | 後果 | 症狀 |
|---|---|---|---|
| **原七格**(#1–#7) | **被判的那個檔**從工作樹讀 | 規則**看錯東西** | 判定跑了,答案是對著錯的內容算的 |
| **新七格**(#8–#14) | **決定要不要判**的控制檔與豁免紀錄從工作樹讀 | 規則**根本不啟動** | **沒有任何訊息** —— 它認為這個檔不歸它管 |

**後者更安靜。** 判錯至少留下一次判定;不啟動連一次判定都沒有發生,
而「沒有違規訊息」與「規則跑過而且過了」在輸出上**完全一樣**。

原七格的繞法是 add-then-revert 三步:

```
① git add <違規版>   ② 工作樹改回合規版(不重新 add)   ③ git commit
```

> **★ 本輪推論(不是量測,標明):新七格【不需要】這三步。**
> 控制檔與豁免紀錄是**固定路徑的無條件 `io.open`**(這一點是**讀程式碼讀出來的**,
> 見各格〈鏡頭〉欄),**與它有沒有被 `git add` 無關** ⇒
> 只要改磁碟上那一份就夠,連 staging 都不必碰。
> **所以新七格的門檻比原七格【更低】,而它的症狀比原七格【更安靜】。**
> ⚠ 這個推論**本輪未實測**,列進〈未證明〉。

## 修法方向(立案不定死,但這是起點)

**本票不是「發明一個新東西」,是「把已經寫對的那一支接到它其餘的消費者身上」。**

## ⚠ 硬限制:shared 那一類**不得做全域替換**

**這不是修法建議,是實作限制。** 放在這裡是因為它與〈爆炸半徑〉同一層級。

「兩邊共用」那一類**同一支讀取函式,兩邊需要不同對象**:

- 前哨要的是「這次寫入之後會有的內容」(或算不出來時的磁碟現況)
- commit 要的是「要進 commit 的那一份」(index)

⇒ **把那支函式整支改成讀 index,會讓前哨開始判一個還沒發生的東西;
反過來留著工作樹,commit 就繼續判錯對象。**
**沒有一個全域答案** —— 每一格要帶著它的執行上下文各自決定。

> 理由與票 132 的 `--review` 那一格逐字相同:
> **共用一個讀取函式,不等於共用一個正確對象。**
> 票 132 那次的結論是「來源要綁 `--staged`,不是綁 `--review`」——
> 也就是**綁執行上下文,不綁函式**。這裡同理,但上下文有三種不是兩種。

### ⚠ ① 過程中撞到的兩件事,都不是「換來源」那麼簡單

**第一件 —— 我自己的實作缺陷:相對路徑不得從絕對路徑反算。**

第一版用 `rel(FRICTION_LOG)` 算要交給 `git show :<path>` 的相對路徑。**那是錯的**:
`rel()` 用**當下的** `ROOT`,而 `FRICTION_LOG` 是 **import 時**凍結的絕對路徑。
測試只 patch 其中一個(`monkeypatch.setattr(gate, "ROOT", tmp)`)時,`rel()` 吐出:

```

  `…` 不在 index 裡(`git show :../../../../../../../../projects/…` 問不到)
```

> **判準(可搬走)**:**要交給 git 的相對路徑,不得從一個絕對路徑反算回來** ——
> 反算的結果取決於**兩個可以各自漂移的東西**。
> 讓**相對的那一份當來源**,絕對的那一份長出來。

處置:新增 `FRICTION_LOG_REL` 為單一來源。**這一格是「換來源」會順手製造的新缺陷**,
而它只在 `ROOT` 被 patch 時現形 —— **正常執行永遠碰不到**。
⇒ **批二那七格會遇到同一個陷阱**(它們也要相對路徑),寫在這裡先行預警。

**第二件 —— 改動照出一個既有的證據隔離漏洞(不是我造成的)。**

`tests/test_r5_mounts.py::_wire_pre_commit` 的 docstring 第一句說
「把 `mode_pre_commit()` 的鄰居**全部**停掉」,而它**一直沒有停 R9** ——
卻一直是綠的。原因:舊版 R9 讀 `FRICTION_LOG` 這個**絕對路徑常數**,

而那份剛好乾淨。

> **一條宣稱「只留 R5 是活的」的 fixture,實際上讓 R9 讀了真 repo。**
> 它綠的原因不是隔離成立,是**被讀到的資料剛好乾淨**(`F-032`:綠的原因不是你以為的)。

處置:**把 R9 也加進那份停用清單**(它本來就該在裡面),**不放寬 R9 的 fail-closed**。
