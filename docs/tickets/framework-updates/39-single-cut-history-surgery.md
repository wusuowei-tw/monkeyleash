### 4.1 約束 1:登記表作為「藏寶圖」的風險

- **現行緩解(公開前清除/泛化)是否足夠?**:**不足。**
- **分析**:Git 的核心是不可變性。即使檔案已修改,只要未利用 `filter-repo`
  將帶有洩漏的歷史 Commit 徹底剷除(包含 SHA),攻擊者仍可循索履查找舊物件。
  此外,若用新 Commit 覆蓋洩漏,該 Commit 的 Message(如 "Remove credentials")
  即為歷史路標。
- **要求**:登記表上的項目,必須在 `filter-repo` 執行、原 SHA 成為
  Dangling Object 並被 `git gc` 徹底清除後,方能視為安全。

### 4.2 約束 2:`filter-repo` 只跑一次的原則門檻

因「找齊」在原理上(見軸二)不可證明,為避免草率宣告完成,
執行 `filter-repo` 改寫全 SHA 前,必須滿足以下**硬性基準門檻**,方可動刀:

1. **多引擎交叉驗證(Two-Engine Consensus)**:
   禁止單點依賴 `agent-gates`。必須引入至少一套具備高熵值特徵庫檢測的
   業界標準掃描器(如 `Gitleaks` 或 `TruffleHog`)。
   透過雙引擎在歷史掃描的回報零(或全為已知豁免),方視為達標。
2. **入口面窮舉驗證**:
   必須提交測試證據〔字面模糊,依上下文還原〕,證明「軸一」所列之
   非常規入口(包含 `commit msg`、`author/committer`、`refs/stash` 等)
   已納入掃描器接管管線,無盲點遺漏。
3. **明確的妥協聲明**:
   必須於 ADR 中明確宣告:
   **「本機制不防禦刻意混淆(如 Base64 隱藏、字串分割拼接),
   僅防禦開發過程之意外洩漏。」**
   劃定此防線,以避免為追求無法達成的「100% 絕對涵蓋」而無限延宕整理作業。

### 本 repo 據此新增的執行要求

**4.1 的「要求」比原本的階段三多一步**:清除不等於 `filter-repo` 跑完 ——
舊 SHA 成為 dangling object 之後**還要 `git gc` 真的回收掉**。
已補進階段三與驗收(見下)。

**4.2 第 2 點與本票的 ★ 那一節同向**:窮舉要有**證據**,不是宣稱。
底本仍是**委託書的來源表**(裁決 1),不是回件的清單。

**涵蓋範圍**(裁決 5),妥協聲明的文字要涵蓋到:

- 編碼:**Base64 / URL 編碼 / Quoted-Printable / HTML entity**
- 跳脫:**shell · regex · YAML · Markdown**
- **字串分段**(被換行、串接、註解切開,重組後才是秘密)
- **擴充屬性**(xattr / ADS —— 不隨 git 傳輸,但要說出來)
- **同形字**(見下方「量到的更正」)—— 它**不在**已修好的那一格

## ★ 階二「入口面窮舉」的驗收底本

> **底本是委託書的來源表,不是回件的清單。**(裁決 1)

`docs/audits/2026-08-15-going-public-attack-surface.md` 指定的三個來源 ——
**git 物件型別表、refs 命名空間、檔案系統中繼資料** —— 逐一走過才算窮舉。

理由是這條規矩最容易被倒過來用:拿回件的清單當底本,等於
**讓被審的那一方定義「審完了」的範圍**。回件答得好不好是另一回事;
**答漏的地方不會自己出現在回件裡**,只會出現在來源表上。

實例就在裁決 3:**大小寫不敏感比對是委託書列了、回件漏答的** ——
若以回件為底本,那一條會靜靜消失。

#### ⚠ 量到的更正:**NFKC 折不動同形字**

回件第 3 節把「同形字 / 零寬字元」列在**同一列**,代價寫「低」,
處置寫「強制做 NFKC 正規化並濾除 ZWJ」。**那一列裡有兩種東西,而處置只蓋得住一種。**

P2 動手前實測(`unicodedata.normalize`):

| 形式 | NFKC | +濾零寬 | +casefold |
|---|---|---|---|
| 全形拉丁 `Ｃ` | ✅ | ✅ | ✅ |
| **西里爾 `С`(U+0421)** | ❌ | ❌ | ❌ |
| **希臘 `Ϲ`(U+03F9)** | ❌ | ❌ | ❌ |
| 零寬 ZWSP / ZWJ / ZWNJ / U+FEFF | ❌ | ✅ | ✅ |
| 全部大寫 | ❌ | ❌ | ✅ |

NFKC 折的是**相容性**差異(全形、連字),**不是視覺相似**。
同形字要另一套映射(Unicode TR39 的 confusables / skeleton)。

**所以:同形字歸妥協聲明,不歸「已修好」。**
把它放進已修好那一格,就是製造一格假涵蓋 ——
**而假涵蓋正是這整份 ADR 從頭到尾在打的東西。**
(是否值得為它引入 confusables 表,另案再議;本票不做。)

裁決 4 的方向要看清楚:**這是黑名單改白名單,而且方向是對的** ——
一般規則是「黑名單、fail-closed」(ADR 0003),但那裡的黑名單列的是
**不管的東西**;這裡的副檔名清單列的是**要跳過的東西**,
所以「白名單」在這裡等於 **deny-by-default**,同一個方向。
**別把它讀成 ADR 0003 的例外。**

裁決 2 的後半是**鎖死條款**:個人 pattern 的分歧問題,
**不得以「進版控」解決** —— 無論流程多卡。這一條寫在停止條件裡。

### P2 第五件(2026-08-15 核准加入):跳過清單的比對要帶邊界

**發現方式值得記**:它是**審查模式的「未內容掃描」清單**照出來的 ——
Q5 那條「清單必須是報告的一部分」在落地第一天就付了一次房租。

`SKIP_PARTS` 有一條裸的 `skills/`,為了跳過**鏡像**
(`.claude/skills/`、`skills/`,兩者 gitignore)而放,但比對是**子字串**,
而正典 `.agents/skills/` 的路徑裡剛好含有 `skills/`:

> **39 個進版控、會跟著公開走的正典檔,在兩種模式下都從來沒有被內容掃描過。**

#### 這一族在本 repo 早就被命名過

`g1_guard.py` 的 docstring 寫著:

> 前綴要帶邊界。`startswith("/tmp")` 會命中 `/tmpdata`、`/tmp_backup`
> —— **與 `.gitignore` 的 `skills/` 缺前導斜線同一族**。

**教訓學在一個地方,而隔壁的資料從來沒有回頭重掃** —— F-082 的形狀,
只是這次「隔壁」是同一個 repo 裡的另一個模組。
正確形狀也早就有:`gate.py:is_source_path` 取 `r.split("/")[0]`,根錨定 + 分段。

#### 家族掃(條件 1)找到的受害者不只一個

| 形狀 | 舊行為 |
|---|---|
| `.agents/skills/**`(正典) | **被吞** |
| `src/myskills/**`、`docs/skills-guide.md` | **被吞**(名字結尾剛好是標記) |
| `vendor/foo.git/**` | **被吞** |
| `a/my.cache/**` | **被吞** |

#### 修法:兩種錨定,不合成一種

- `SKIP_ROOTS = ("skills/", ".claude/skills/")` —— **根錨定**。
  鏡像的位置是構造決定的,不會浮動
- `SKIP_PARTS = (".git/", "__pycache__/", ".pytest_cache/", ".cache/")` ——
  **任何深度,但兩側帶 `/` 邊界**

判準:**這個東西是「某個固定位置的目錄」,還是「任何深度都算」?**
合成一種就是把兩個不同的問題用同一個式子答。

### 量測時撿到第四條 ⚠(不在裁決指定的三條裡)

**遠端存在第二條分支**:`refs/heads/wip/f062-installer-defaults`

該分支相對 `master` **有 0 個獨有 commit**(它是 master 的祖先),
所以它**不影響「要清什麼」**。但它影響**「清乾淨了沒有」**:

> `filter-repo` 改寫本機所有 ref,**遠端那條 wip 分支不會自己消失**。
> 它留在遠端,就把**改寫前的整段物件圖釘在那裡** ——
> 於是 force-push 了 master,舊歷史仍然可達,而**看起來像是清乾淨了**。

處置(裁決:**寫成類,不寫成那一條分支**):

> **開刀後以 `git ls-remote` 列出遠端全部 refs,逐一確認每一條都指向
> 改寫後的新物件圖,且沒有任何 ref 可達舊物件。**
>
> `wip/f062-installer-defaults` 是**本類的已知實例**,不是這條驗收的全部。

寫成類的理由與 F-085 同:**修的時候人看到的是那一條分支**,
而驗收要問的是「**遠端還有幾條 ref**」。今天是一條 wip,
明天可能是一條 tag、一條 PR ref、一條別台機器推上去的分支 ——
**逐一列出**才擋得住那些,點名一條擋不住。

#### `git-filter-repo` 是否也被攔

**沒有證據顯示被攔,但這是「沒看到」不是「沒發生」** ——

**含 `.git/` 是重點** —— 開刀改寫的就是歷史,少了它的備份在單刀那天等於沒有備份。
只排除快取目錄。備份腳本在目標檔已存在時**中止不覆寫**
(備份 = 讀取 + 複製;涉及覆蓋就停,票 22 R5)。

### 活標本:本節第一版被 leak_scan 擋下,而它同時證實了 K3

第一版把兩個路徑寫成完整絕對路徑,`leak_scan` 命中**個人 pattern** 擋下 commit。
擋得對,已改成 `<家目錄>` 佔位符 —— **沒有加豁免**。

真正的收穫是對照組:

| 形式 | 出處 | 掃描結果 |
|---|---|---|
| `C:\Users\…`(未跳脫) | 本節第一版 | **命中,擋下** |
| `C:\\Users\\…`(JSON 跳脫) | K3(`friction-log.md:803`) | **零命中** |

**同一個字串、同一組 pattern、同一支掃描器,差別只在跳脫。**
這就是 K3 為什麼活到現在,也是為什麼跳脫形式必須寫進妥協聲明 ——
P2 收的 NFKC / 零寬 / 大小寫**都不碰跳脫**。

## 執行順序

**#1–#7 對應 ADR F-0015「開刀前要量的清單」。** 順序不可交換。

### 階段零:K3 的現樹遮蔽(裁決 6,**可先做**)

K3(`docs/agents/friction-log.md:803`)**裁決:遮**。

- 形式照**票 32 的整行遮蔽**,**留記號** —— 不是刪掉那一行
- **裁決者明示授權**動這段引用的證據原文(TSI-002 的例外,逐次授權)
- **現樹遮蔽先做;歷史那一份在階段三連同 K1/K2 一起清**

分兩個時點的理由:現樹遮蔽是可逆的、隨時能做;歷史清除只有一次機會。
**能先做的先做,不要把可逆的動作綁進不可逆的那一刀。**

### 階段一:找齊(刀還沒下)

1. 裝 `git-filter-repo` 與 `gitleaks`,記版本
2. **雙引擎全歷史掃描**(P3):兩個引擎各跑一次全歷史,
   **取聯集不是交集** —— 交集是「兩個都認得的」,那比任何單一引擎都窄
3. 結果併入 `going-public-known-items.md`;**新命中一律先定性再登記**
4. 對每一筆登記項確認**期望值方向**(未清除→掃得到;已清除→掃不到)
5. **入口面窮舉**照 ★ 那一節:走**委託書的三個來源表**,逐項留紀錄

### 階段二:量參照(刀還沒下)

6. **#1** `.agents/legacy-no-redlight.txt` 的 `# go-live: 5180678` ——
   **9 條目**。開刀後該 sha 消失,`gate.py:1098` 會讓 **9 條全部變違規** →
   R6 擋掉所有 commit。該檔 **gitignored,不會自動更新**。
   **產出**:舊 sha → 新 sha 的對照,以及重新指向的步驟
7. **#2** 下游 provenance —— 本 repo `.dev/provenance.jsonl` **不存在**。
   **這一項要去問下游**,本 repo 量不到。P6 的凍結就是為了讓這個數字維持在 0
8. **#3/#4** 追蹤檔裡的 sha 形狀字串(**15 檔**)—— 多為散文引用。
   測試裡的是 `deadbeef` 假資料(安全)。**產出**:要改的引用清單
9. **#5** `.dev/gate-exemptions.jsonl` —— 已確認 `at_commit` 是**布林值不是 sha**,
   **不受影響**。本項結案,不必重量
10. **#6** 登記表自己的 sha(K1 = `3a265f2`)—— 開刀後失效,**必須同步改**
11. **#7** 遠端與既有 clone —— 列出遠端**所有** ref(含自查撿到的 wip 分支)

### 階段三:動刀(**只跑一次**)

12. 備份確認(P5),**異地副本先於手術**(具名原則:順序決定安全性)
13. `filter-repo` 一次跑完**全部**改寫:身分欄位 → `noreply`、
    **K1 / K2 / K3 三筆的歷史內容清除或泛化**。**不分兩次**
14. **`git gc` 回收 dangling object**(回件 4.1 的「要求」)——
    `filter-repo` 跑完只是讓舊 SHA 變成孤兒,**孤兒還在 `.git/objects` 裡**,
    而 clone 有可能帶走它。**沒 gc 就不算清除**
15. 重寫 `#1` 的 go-live sha、`#6` 的登記表、`#3/#4` 的散文引用
16. force-push `master`;**處理遠端全部 refs**(見上方「寫成類」那條)

### 階段四:驗收

17. 雙引擎全歷史**重跑**:登記表逐筆比對**期望值**
    (已清除的要**掃不到**)
18. 全套測試綠;R6 不再報違規
19. **`git ls-remote` 列出遠端全部 refs**,逐一確認指向改寫後的新物件圖,
    **無任何 ref 可達舊物件**
20. **確認 dangling object 已回收** —— 回件 4.1 的判準是
    「原 SHA 成為 dangling 並被 `git gc` 徹底清除後,方能視為安全」
21. **自查三條重跑**(裁決 7)—— 開刀會產生新的物件,
    「開刀前乾淨」不蘊含「開刀後乾淨」
22. 妥協聲明定稿:**回件 4.2 第 3 點的原句 + 裁決 5 的涵蓋清單
    + 同形字(量到的更正)+ 引擎版本 + 明文排除項**

## 驗收範圍:**「push 會帶走的」有限清單**

照 ADR F-0015 階二門檻(分格版)。**範圍是列舉的,不是「所有東西」** ——
無限的範圍等於沒有範圍。

**在範圍內**:檔案模式位元、GPG 簽章、`refs/replace`、tag、notes、
submodule 指標、時間戳、以及**所有遠端 ref**。

**明文排除,理由寫在驗收報告上**:

| 排除項 | 理由 |
|---|---|
| `reflog` | **push 不傳輸** |
| `stash` | **push 不傳輸** |
| `.git/` 底下的本機檔(`config`、hooks…) | **push 不傳輸** |

> 這三項歸**本機衛生**,不是公開審查的對象。
> 明文寫出來,是為了讓「沒查」與「查過沒事」在報告上分得開 ——
> 與 Q5 的跳過清單同一條規矩。

**時間戳的時區**:**聲明接受**。它可推斷作息與大致地理位置,
但改寫時間戳會讓整段歷史失去時序意義,代價大於收益。**寫進妥協聲明。**

## 停止條件

- 執行門檻三條(回件 4.2)任一條未滿足 → **停**
- 出現「把個人 pattern 進版控就解決了」的念頭 → **停**。
  裁決 2 是**鎖死條款**:無論流程多卡,一律走 age 匯出
- 掃描器改動(裁決 2/3/4)未落地 → **停**,不得先跑 P3
- 雙引擎結果不一致而無法定性 → **停**,登記為未決項,不自行判斷「應該沒事」
- 任何一筆登記項的期望值**說不出來** → **停**(ADR:說不出期望值本身就是 refuse 的理由)
- 下游 sync 凍結已被打破(P6 不成立)→ **停**,先重量 `#2`

## 明確不做

- 不改寫時間戳 / 時區(已聲明接受)
- 不處理 `reflog` / `stash` / `.git` 本機檔(明文排除)
- 不把個人 pattern 清單改成進版控 —— **任何流程鎖死都不得以此解決**(裁決 2)
- 不由代理人執行 force-push 與遠端分支刪除
