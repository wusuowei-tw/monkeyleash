## 零、**第一個實例 —— 而且發生在本票立案之前**(2026-08-28)

**本票預測的是控制檔會過期。實際上先過期的是備份清單自己(`README.md`),
而且在本票立案之前就已經發生了。**

時序:

```
1. agent 產出暫存夾(含 README.md,乙組標「待裁 / 不想上傳就不要上傳那個子夾」)
2. Jeff 手動上傳             ← 雲端拿到的是這一版
3. 裁決:乙組「上傳」
4. agent 改寫 README 乙節     ← 本機這一版與雲端那一版從這裡開始分歧
```

> **雲端那份 `README.md` 現在寫著一句已經被推翻的話**
> ——「不想上傳就不要上傳那個子資料夾」。
> 而**它看起來完全正常**:檔在、開得起來、內容是通順的中文。

### 為什麼這一格放在第一節

**已發生的事實比預測強。** 本票原本第一節舉的是兩個「會變 / 即將變」的例子
(`leak-patterns.local.txt` 35→43 行、`g1-protected.txt` 即將 +1 行),
那些是**論證**;這一格是**已經發生的事**,而且它示範了一件論證沒說到的事:

> **最先過期的不是被備份的東西,是備份清單自己。**
>
> 清單是「哪些檔、什麼指紋」的**當下快照**,而它同時也是**還原時唯一的權威**。
> 它過期的時候,不只少了一項資訊 —— **它會拿一個舊答案去回答一個新問題,
> 而且答得很有自信**(有表格、有 sha256、有取樣時間)。

**這也是 `F-122` 的形狀**(票面裡的內容快照是一份沒有人在守的副本)
換到備份清單上:F-122 講的是**排版帶來的權威**,而一份逐檔列了 `sha256`
的清單,權威感比一段散文更強。

### 對範圍的影響:**清單自己也要進被檢查的集合**

原本第二節寫「把**十項**掛進一條檢查」。**十一項** ——
`README.md`(或它的後繼者)必須檢查它自己,否則
**檢查的基準本身可以過期而不出聲**,而那是一個會自我拆除的機制。

## 一、問題:**一次性備份會安靜地變成過期快照**

`docs/machine-init.md` 的控制檔清單有十項,判準是「決定閘門行為、卻不進版控」。
2026-08-28 產出了第一份備份暫存夾。**而那一份從產出的下一秒就開始過期。**

**這不是假設,是同一天已經發生兩次的事:**

| 檔 | 什麼時候變的 | 幅度 |
|---|---|---|
| `~/.claude/leak-patterns.local.txt` | **2026-08-27**(票 84 加 pattern) | **35 → 43 行** |
| `~/.claude/g1-protected.txt` | **即將**(裁決 2026-08-28:加 `C:\projects\_ticket84_backup`) | +1 行 |

> **兩項都是控制檔,兩項都在同一週改,而備份是 2026-08-28 做的一次性動作。**

### 為什麼它不會被自己發現

備份的產物是**一份清單 + 一堆檔案**,而它們**不會因為來源改了就長得不一樣** ——
雲端上那一份看起來永遠是完好的:檔名在、大小合理、開得起來。

> **一份過期的備份與一份最新的備份,在雲端硬碟的檔案列表上長得一模一樣。**
> 而差別只在**還原的那一天**才會顯現 —— 那天你沒有第二次機會。

**`F-110` 逐字**:「要留存」是一個祈使句,而**祈使句沒有主詞**。
「記得定期重做備份」也是一個祈使句。

## 二、最便宜的版本(**這是範圍,不是設計**)

**把十項掛進一條檢查:任一項的 `sha256` 與最近一次備份清單不符就出聲。**

暫存夾的 `README.md` 已經逐檔記了 `sha256` —— **那份清單就是基準**,
不必另造一個資料結構。

```
讀 <最近一次備份清單>  →  逐項重算現況 sha256  →  不符 / 缺項 / 多項  →  出聲
```

### 三種不符要分開講,不要合成一句「備份過期」

| 情況 | 意思 | 該不該叫 |
|---|---|---|
| **sha 不同** | 控制檔改了,備份是舊的 | **叫** |
| **來源缺項** | 檔不見了(或本來就刻意不存在,如 `shadow.json`) | **看情況** —— 見下 |
| **來源多項** | 清單有新的第 11 項,而備份清單不知道 | **叫**(這條最容易被漏掉) |

**⚠ `shadow.json` 那一項必須能表達「刻意不存在」** ——
否則這條檢查每次都會為它叫一聲,而**一條每次都叫的檢查會被關掉**(`F-031`)。
這是本票最容易做錯的一格。

## 三、要偵察的(本輪不回答,只列)

1. **這條檢查住在哪裡?** 候選:pre-commit(但控制檔多半不在版控裡,
   改它不會觸發 commit)、測試套件的一條、或一支手動跑的腳本。
   **判準同票 86:它在沒有人記得的時候會不會叫。**
2. **它的觸發時機是什麼?** 「改了就叫」做不到(那要監看檔案);
   「每次跑測試時叫」可行但可能吵;「換機器前叫一次」最準但最晚。
3. **`~/.claude/` 那四項怎麼算?** 它們在 repo 之外,而檢查住在 repo 裡 ——
   跨界讀取要不要?讀不到時 fail 往哪邊倒?
4. **第 11 項出現時怎麼被發現?** 清單本身會長,而
   **`F-137`:一份清單不會帶著它自己的長度。**

5. **🔴 跟誰比?** —— **這一問不是第 2 問的一部分,不要併進去。**

   第 1–4 問問的都是**「來源有沒有變」**。但這條檢查
   **證得了「來源沒變」,證不了「雲端那份存在而且相同」** ——

   > **兩者中間隔著一個手動上傳動作,而那個動作沒有回執。**

   ### ★ **回執找到了(2026-08-28)**

   > ## **不是「上傳成功」,是「下載回來還是它」。**
   >
   > 上傳之後把它**下載回來,逐位元組比對 `sha256`**。

   **這一句就是第五問要的那個回執**,而它是被 Google 雲端的轉檔逼出來的
   (第八節):`.txt` 被轉成 Google 文件、下載回來是 `.docx`,
   **而「上傳成功」那個訊號完全正常**。
   
   **為什麼它答得了第五問**:它不去比對「來源有沒有變」,
   它比對的是**雲端那一份實際交還給你的東西** ——
   把「跟誰比」的那個「誰」變成一個**可以拿在手上的檔案**,而不是一個假設。
   
   同一句已寫進 `docs/machine-init.md` 的硬條件四。**兩邊互指,不各寫各的。**

   **零那一節的 `README.md` 就是從這個縫掉下去的**:來源(本機)確實變了,
   而即使有一條檢查在看來源,它也只會說「本機改了」——
   **它說不出「雲端那份還停在上一版」**,因為它從來沒看過雲端那一側。

   **第 2 問問的是「什麼時候比」,本問問的是「跟誰比」。**
   合成一問的話,做完之後會得到一條**準時去比對一個空位**的檢查 ——
   而它會準時回報綠燈。

   **方向只點名,不設計**(照裁決):上傳後把**雲端側的檔案清單與大小抄回一份
   當回執**,讓「我上傳了」從一個記憶變成一筆資料。
   **回執機制不在本輪設計範圍。**

## 四、這是 `F-110` 形狀的修法

> **機器出聲,不是人記得。**

本票不是「要更常做備份」,那句話沒有主詞。本票是
**「讓備份過期這件事變成一個會出聲的狀態」** ——
出聲之後要不要重做仍然是人決定的,但**「不知道它過期了」這個狀態被消掉**。

**與票 86 的關係**:兩張票同一個判準句(「它在沒有人記得的時候會不會叫」),

**兩張票都不要用「記得做某件事」收尾。**

## 🔴 七、題目變了:**不只是「備份會過期」,還有「備份可能只是其中一份」**(2026-08-28)

**來源**:票 91(兩台機器的個人 pattern 清單分歧)。

### 事實

`~/.claude/leak-patterns.local.txt` 有**兩份正本,而它們的內容不同**:

| 位置 | 條數 | 各自長了什麼 |
|---|---|---|
| **桌機** | **18 條**(2026-08-28 實測) | 票 84 §4-5 在這裡加了舊帳號那一條(35 → 43 行) |
| **筆電** | 16 條起算 | **K1 / K2 那一條 pattern 在這裡**,而它從未到過桌機 |
| **雲端備份** | 某一次匯出的快照 | 它是**其中一份的某個時點**,不是聯集 |

### 為什麼這改變本票的題目

本票原本問的是**時間**:「這份備份是什麼時候做的、什麼時候該重做」。
而本則問的是**完整性**:

> ### **這份備份是「那個檔案」,還是「那個檔案的其中一份」?**

**兩個問題的失效方式相反:**

| | 過期的備份 | **只是其中一份的備份** |
|---|---|---|
| 還原之後 | 回到一個**較舊但真實存在過**的狀態 | 回到一個**從未存在過**的狀態 —— 另一台的增修被抹掉 |
| 會不會發現 | 對帳日期就看得出來 | **看不出來。** 條數對、sha256 對、清單全綠 |
| 修法 | 重做備份 | **不是備份問題,是「還原」這個動作本身錯了** |

### 🔴 因此:「還原」對這一類檔案是**破壞性動作**

`docs/machine-init.md` 與 26 步筆電劇本的第 09 步原本寫「**還原**取回
`leak-patterns.local.txt`」。**照那樣做會把桌機這 18 條裡的新增直接蓋掉,而且無聲。**

**⇒ 已改成「合併」**(劇本第 09 步,2026-08-28;同時在三選一圖例裡新增
**第四個處置類別:合併**)。**正本 `machine-init.md` 要不要跟著補 —— 待裁**,
理由與票 88 §八之三(四)同一格:**它牽涉使用者層控制檔,執行者是人。**

### 判準(可搬走)

> **「還原」預設了正本只有一份。**
> 一個檔案只要在兩台機器上各自被編輯過,**「還原」就從恢復變成刪除** ——
> 而刪掉的是**另一台上的那些**,所以在這一台上看不出任何異常。

**同族但方向相反**:`F-108`(把 A 併進 B 要驗兩個方向 ——
「A 的都到了嗎」證明你做了事,「**B 的都還在嗎**」證明你**只**做了那件事)。
本則是那條判準的**前一步**:先問「**B 有沒有東西是 A 沒有的**」,
沒問就直接用 A 覆蓋,方向 B 連驗的機會都沒有。

### 對本票驗收條件的影響

本票的驗收原本會是「備份有沒有過期的觸發條件」。**現在要加一問**:

> **每一份控制檔備份,要能說出它是【聯集】還是【某一台的快照】。**

`user-layer-manifest.txt` 的四個桶(`export` / `age` / `human` / `never`)
**表達的是「怎麼搬」,不是「有幾份正本」** —— 那正是票 28 的標題句
(「檔案是好的 ≠ 它保護的是這台機器」)再往前一步。**登記,本票不擴充範圍。**

## 🔴 八、Google 雲端硬碟會**把純文字換掉**,而下載的當下看不出來(2026-08-28,時鐘 8/29)

**發現者:Jeff(裁決者側),實測。**

> ### **上傳 `.txt`,雲端把它轉成 Google 文件;下載回來是 `.docx`。**

**逐字證據(裁決者提供)**:

```
桌機收到的檔:前四位元組 80, 75, 3, 4   <- PK,zip 標頭(docx 是壓縮包)
              6870 bytes
而那三行純文字只需要一百多 bytes。
筆電上的原檔是好的 —— 被換掉的是【中間那一段】。
```

### 為什麼它比「檔案傳錯了」嚴重

**被換掉的不是檔名,是內容,而且是在你沒有動它的時候。**
`docs/machine-init.md` 的備份硬條件一逐字寫過這個形狀:

> 一個會自動同步的資料夾,它的內容**在你沒有動它的時候會改變** ——
> 而本清單裡每一項的價值都建立在「它是我放進去的那一份」。

**硬條件一防的是「自動同步」,而這一次的動作是「手動上傳」——
它完全符合硬條件一,然後內容還是被換掉了。**

> ### **「我親手放進去的」不等於「那裡現在放著的是它」。**
> 手動上傳把「誰動的」這一格填成了人,而**那一格從來不是真正的保證** ——
> 真正的保證是**下載回來逐位元組相同**,而那件事沒有人驗過。

### 🔴 範圍:**11 / 11 全中招**(2026-08-28 實測,只看副檔名不讀內容)

```
_gdrive_upload_2026-08-28/

  shadow-baselines/  3 個:.jsonl
  README.md          1 個
備份檔總數(不含 README):11;其中純文字副檔名:11  -> **11 / 11**
```

**⇒ 若轉檔真的發生在全部檔案上,下載回來的 `sha256` 與 README 記的會【全部】對不上。**
那時 README 那張表不是「過期」,是**指向一份不可還原的備份**。

本票第零節記的第一個實例是**備份清單自己過期**;
第七節記的是**備份可能只是其中一份**;
**本節是第三個,而且它比前兩個都根本:備份可能根本不是那個檔案。**

| # | 失效方式 | 還原之後 |
|---|---|---|
| 一(§零) | 清單過期 | 回到一個舊但真實的狀態 |
| 二(§七) | 只是其中一份 | 回到一個**從未存在過**的狀態 |
| **三(本節)** | **內容被平台換掉** | **還原不了** —— 拿到的是 docx,不是原檔 |

### 🔴 硬條件四(裁決 2026-08-28):**現階段一律用隨身碟**

**⚠ 而這一條與備份硬條件三相撞,需要裁決:**

`docs/machine-init.md` 硬條件三:**backup zip 要上雲必須先加密**,
而**加密方案至今未設計**(該節自承「加密方案不在本輪設計」)。

| 路線 | 狀態 |
|---|---|

**⇒ 裁決(2026-08-28):現階段一律用隨身碟。**

**規則要寫成三句,不是一句** —— 只留「用隨身碟」而不說另一條為什麼失效的話,
下一個人會覺得 zip 比較方便,然後在不知道加密那一格的情況下走回去:

> 1. **純文字走雲端,一律先壓成 zip**(避開轉檔)

## 🔴 十二、**上傳閘門:上傳必須在所有編輯之後**(2026-08-29,`F-147` 的執行面)

### 閘門(已寫進暫存夾 `README.md` 的驗收那一節)

> ### **上傳必須在所有編輯之後,而 `README.md` 必須是最後一個被改的。**

### ★ 它是哪一族:**人的手動動作 vs agent 的編輯**

### 🔴 補:**收工前必須整包重傳重驗一次 —— 而它沒有前置條件**(裁決 2026-08-29)

> ### **「今天收工前跑一次」不因為待辦沒清光而延後。**

**由來**:本輪之後還會再動檔案,而「等都改完再傳」聽起來合理 ——

| 寫法 | 問題 |
|---|---|
| 「等待辦清光再傳」 | **待辦清光沒有時鐘**,而備份於是也沒有 |
| **「收工前傳一次」** | **有時鐘,而且與待辦無關** |

**這一條與 `F-110` 的差別**:它不是「記得要備份」那種祈使句 ——
**它綁在一個每天必然發生的事件上(收工)**,而不是綁在一個可能不發生的狀態上(待辦清光)。

> **一個以【狀態】為條件的規矩,它的觸發時機由那個狀態決定 ——

**⚠ 仍然沒有觸發器**(同 §十二 的誠實標註):沒有東西會在收工時叫。
**這一條把「什麼時候」從不確定變成確定,沒有把「誰來叫」從無變成有。**

### 十四之一、`paste-cache/` 為什麼是目錄前綴,不是逐檔

`manifest._best_entry` 只有 `/` 結尾的項目走前綴,其餘要**完全相等**才命中。
逐檔列的話,快取裡下次多一個檔就又是一次未分類拒絕 ——
**而那次拒絕會發生在下次匯出,不是現在。**

### 十四之二、`leak-patterns.local.txt.bak-20260828` 為什麼原本沒被涵蓋

同一條邊界:正本 `leak-patterns.local.txt` 是**不帶 `/`** 的項目,
所以它**不是**這個 `.bak` 的前綴 —— 兩者不相等,就不命中。
這是 `g1_guard` docstring 那條「前綴要帶邊界」在**擋對了**的一次:
若這裡是裸字串前綴,`.bak` 會被靜默判成 `age` 而**跟著加密匯出**,
一份多餘的明文洩漏面就這樣被帶上路,**而報告會顯示成功**。

**刪除順序不可反過來**:先由 Jeff 手刪檔案,這一行才能移除。
先移除行、檔還留著 = 下次匯出再被拒 —— **而那正是正確的行為**。
