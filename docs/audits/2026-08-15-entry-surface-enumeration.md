## 更正(2026-08-15,對回件原文重讀後):身分欄位那一列

第一版把 commit 身分欄位標成 **`[排除]`**,理由寫「掃描器**無入口**」。

**那個理由站不住。** 回件 4.2 條件 2 的原文點名要證明
「`author/committer` **已納入掃描器接管管線**」,而入口是**可以造的** ——
把欄位物化成文字送進去就有了。

> **「沒有入口」與「我沒去造入口」是兩件事,而前者聽起來像事實。**

已補做:86 個 commit × author/committer = **172 筆**物化成一個 `.txt`,
走完整管線(跳過清單未濾、審查模式白名單允許)。

### 結果:**命中 0** —— 而這個零要講清楚

**那 3 個身分裡有一個是真名 + 私人 gmail,它就在那 172 筆裡,而掃描器沒有反應。**
原因不是它乾淨,是**通用與個人 pattern 都沒有「人名 / 私人信箱」這一類**。

這是缺口二的同一個形狀第三次出現:**管線跑了、報告是零、東西還在那裡。**

### 處置:這一面**不靠 pattern,靠枚舉**

不建議為身分欄位加 pattern,理由是**枚舉在這一面嚴格更強**:

| | pattern | 枚舉 |
|---|---|---|
| 集合大小 | 開放 | **封閉且極小(3)** |
| 漏掉的可能 | 有(寫不全) | **無**(`git log --format=%ae` 就是全集) |
| 誤判 | 有 | 無 |

所以驗收改用**枚舉比對**:開刀後 `git log --all --format=%an <%ae>` 與
`%cn <%ce>` 的聯集,**必須只剩 `noreply` 那一種**。
這條寫進票 39 階段四。

**pattern 對這一面貢獻為零 —— 那不是缺陷,是選錯工具。**
記在這裡是為了讓下一個人不要「補一條 email pattern」就以為守住了:
那條 pattern 會抓到全世界的 email,而真正要確認的是**這個 repo 裡只剩哪幾個**。
