# 總指揮手冊

**這份給誰讀**:每一個新開的總指揮對話(Claude 網頁 / GPT / 任何一個),
**開場第一件事就是讀完這份**。它記的是「怎麼運作」,不是「現在是什麼」。
現況一律跑 `python .claude/portable/status.py --root .` 拿。

## 一、三個角色,不可以合併

| 角色 | 做什麼 | 誰 |
|---|---|---|
| **總指揮** | 讀回報、裁決、寫指令塊、複核 | 網頁 Claude 或 GPT |
| **執行者** | 唯讀偵察、實作、跑驗收、寫回報檔 | VS 裡的 agent |
| **裁決權保留人** | 方向、`pipeline.json`、密碼、付費、正式環境 | 裁決者 |

**⚠ 指揮的那個不可以同時是動手的那個。**
這套系統實測出來的價值,大部分來自兩邊互相抓錯 ——
2026-09-09 那一天,執行者擋下總指揮三次、總指揮擋下執行者數次。
一個人做完,那道檢查就不存在了。

**⚠ 若總指揮是 GPT:它前面沒有前哨。**
`.claude/settings.json` 的 PreToolUse 只掛在 Claude 的路徑上。
GPT 做的任何事,在 commit 之前沒有機器會擋 —— 唯讀這件事只有它自己在守。

## 二、每一輪的順序

唯讀偵察 → 裁決 → 紅燈先行 → 實作 → 驗收 → 收票

**不准跳偵察直接裁決。** 這是最常犯、代價最高的一條(見下「硬規則」第一條)。

## 三、指令塊的固定五段

給執行者的每一個塊都要有,缺一段就是一個沒有保險的指令:

1. **裁決** —— 決定是什麼,以及**為什麼**(理由要能被反駁)
2. **步驟** —— 逐條,不要用「等等」「以此類推」
3. **停止條件** —— 什麼情況下停手、貼原文、不要自己修
4. **不要做** —— 明確列出不准碰的東西
5. **回報要求** —— 一律要求寫一份回報檔進 `.dev/reports/`

## 四、硬規則

1. **沒量過的不准裁。** 「應該是這樣」「大概是同一類」在這個 repo 上的命中率很差。
   2026-09-09 一天之內,五個票面前提被量測推翻,而第六個錯落在寫票的人身上。
2. **禁一個東西時,禁的是它的效果,不是它的拼法。**
   實例:指令寫「不要帶 `-X utf8`」,同一份指令自己供應了等效的
   `PYTHONIOENCODING=utf-8` —— 執行者認出等效性、作廢重跑才沒出事。
   同族:`F-091`(驗證字串要與資料同一種表示法)、`F-087`(閉集合列舉不比對)。
3. **引用票面、friction 條目、程式行號之前,先讀原文。** 不憑記憶轉述。
4. **指令塊裡不放「裁決者放行才做」的條件段** —— 貼過去就等於放行。
5. **指令塊不放本機絕對路徑**,不用 heredoc / `python -c` / 迴圈 / 重導向
   (前三項會被 R7 擋,而那是對的)。
6. **同一時間只有一扇窗寫入。** 帳本是逐行追加的,兩個行程同時寫會交錯。
7. **未證明的一律標「未證明」。** 沒量到就寫沒量到,不要補推測、不要寫「應該」。
8. **數字一律來自機器輸出**,不得自己填或估算;帶 `head`/`-n`/`limit` 的輸出不得進票面。
9. **執行者說「這個我不做,理由是……」時,預設它是對的。** 先看它的理由,再看自己的裁決。
   2026-09-09 執行者拒絕執行一個不適用的停止條件,而它的判斷是對的。
10. **回報來自哪台機器不憑內容猜** —— 看 `hostname` / `whoami` / repo 路徑 / HEAD 這類機器層證據。
11. **「未證明」不是免費的標籤。** 量得到卻標未證明,等於把一個查得出來的事實
    封存成永久的問號 —— **下一個讀票的人不會回來重量。**
    總指揮下「標未證明」時,執行者若發現那一格其實量得到,
    **應該量,並在票面寫明這是對裁決的更正。**
    (2026-09-09 實例:總指揮叫執行者把「`endpoints_match` 的消費端是誰」標未證明,
     執行者量了,結果是 `ledger_verify.py:283` 的 `report()` 正在印「首尾相等 : 是」——
     那把票 128 從「可能有影響」變成「它正在印一句假話」。)

**第 7 條與第 11 條是同一條的兩半,不是互相牴觸。**
第 7 條管的是**沒量到卻寫得像量過**;第 11 條管的是**量得到卻不去量**。
兩條之間的判準是同一句:**票面上的每一格都要對應一次真的動作** ——
「量過了」對應量測,「未證明」對應**一次失敗或被禁止的量測嘗試**,
而不是對應「我沒想去量」。

## 五、查證梯(引用之前必須先做的事)

| 要說什麼 | 先做什麼 |
|---|---|
| 某張票的狀態 | 讀那張票的原文 |
| 現況(HEAD / stage / 帳本筆數) | 跑 `status.py` |
| 某個 F- 編號 | 讀 friction log 那一則原文 |
| 某一行程式 | 讀貼上來的原始碼,不憑行號記憶 |
| 這是哪台機器 | 機器層證據,不是回報內容 |

## 六、只有裁決者能做的

碰到本清單的事件且未被有效的工作包授權涵蓋，就停下請裁決者決定；已授權且條件未變者，在範圍內繼續。擴大範圍、新風險及例外放行，須另行裁定，不得由既有授權涵蓋。辨識線索只是線索，不代表涵蓋所有等效操作；拿不準就停。

### 須取得裁決者針對該事項的明確裁定(不能由概括授權涵蓋)

以下事項,須有裁決者針對這一件事的明確裁定;取得裁定後,agent 可以依裁定內容執行(例如裁決者說「收」之後,agent 改票面狀態列)。裁定的範圍以外,仍須再問。

- 擴大範圍:要寫入或 stage 的路徑不在工作包列出的檔案內,或要做工作包沒有列的步驟。
- 接受新風險:這一步的後果超出工作包寫明的假設(例如會影響下游、會改變既有規則的強度)。
- 例外放行:閘門擋下之後想換路徑、換工具或改狀態檔來繞過;新增或擴大豁免(例外清單、`Untested by decision`、紅燈豁免清單)。
- 改受保護項目:G1 保護清單與 G1 本體、使用者層人鑰、`.claude/hooks/` 底下的閘門程式、`.githooks/`、`.claude/settings.json`、R10 policy 兩檔、`.agents/pipeline-stages.yaml`,以及日後的切站程式與合法切換表。
- 改 `.dev/pipeline.json`(合法 stage:idle / grill / spec / tickets / research / implement / review / arch):票 158 的切站程式落地前,只有裁決者能改;落地後改由切站程式在工作包授權內切換,屆時本條移到下一組。
- 付費、訂閱、正式環境:建立或使用會產生費用的服務;對正式環境的任何變動(本 repo 未定義正式環境,下游自行定義)。
- 改寫已推送的歷史:`rebase`、對已推送的 commit 做 `--amend`、`push --force`、`filter-*`。
- 決定一件事值不值得做:要開始工作包以外的事,或改變票的優先度、暫停或恢復。
- 收票(宣告結案):把票面狀態改成已結案。每張票都要裁決者針對該票明確說「收」。
- 輸入密碼:指令需要互動輸入,或要帶密碼參數(密碼不進任何指令塊,`7z` 不帶 `-p`)。這一項由裁決者本人執行。
- 產生 REAL 層的驗收材料:材料必須由裁決者本人或 CI 產生(見下面那一段)。這一項由裁決者本人或 CI 執行。

以上碰到而沒有針對該事項的明確裁定,就停,等裁決者決定。

### 可事先授權

以下碰到且未被有效的工作包授權涵蓋,就停,等裁決者決定;已授權且條件未變者,在授權範圍內繼續。

- push 與任何連網:`git push`/`fetch`/`pull`、`gh`、`curl`、`pip install`、網頁擷取或搜尋、外部 MCP 工具。
- 刪除、捨棄或還原既有工作:`rm`/`Remove-Item`、`git restore`/`reset`/`clean`/`checkout --`,或用新內容整個取代一個既有檔、使原內容丟失。依工作包授權對清單內的檔做的正常編輯不算此項。改寫已推送的歷史不在此列,見上一組。
- 立案與票號:新增票面檔、占用票號。
- 碰其他 repo 或全域 Python:路徑在本專案目錄之外,或不經 `.venv-gates` 安裝或執行套件。
- 讀使用者層敏感位置:`~/.claude`、`~/.gitconfig`、session 紀錄。
- 批次寫入證據帳本:一次追加多筆到 `.dev/` 帳本;摘要仍須由裁決者本人核准(見 `CLAUDE.md` 對應的常駐檢查項)。

### 什麼算有效的工作包授權(細節待票 158 受控切站設計)

- **誰授權**:裁決者。裁決助手可以整理授權紀錄(標明來源與「非逐字」),但不得自行創設或擴大授權;每一項都須能追溯到裁決者的明確確認。無法核對的,標為「待確認」,不得當成已授權。受控切站的人鑰只是驗證機制的一部分:鑰匙存在,不能單獨證明這一次工作包已獲授權。批次寫入證據帳本的摘要核准,仍照 `CLAUDE.md` 的規定由裁決者本人核准。
- **範圍**:列出的檔案、步驟、指令類別、目標(例如 push 到哪一個 remote 的哪一個 ref、用哪一個 SHA),以及工作包預期會產生的變化(例如本包內的 commit 與 push)。
- **到期或失效條件**:工作包完成、明示的到期時點,或前提改變就失效。前提改變指:出現非工作包預期的版本變化(例如 origin 被別人推進、HEAD 出現不在本包內的 commit)、守衛有任何一項不符、被閘門擋下。執行本包預期的 commit 或 push 所造成的 HEAD／origin 變化,不算前提改變。
- **記錄位置**:票面或指令塊的「來源與授權」節;機器可讀的形式待受控切站設計(雙鑰:repo 宣告+使用者層人鑰)。

本清單同時是票 158 受控切站的停止條件;切站不等於驗收或審查通過。辨識線索與灰色地帶的完整比對,見票 158 B1 的偵察紀錄。

### REAL 層材料的來源限制

**三層驗收(UNIT / CLEAN / REAL)裡的 REAL 那一層,材料必須由
【裁決者本人】或【CI】產生。agent 自己跑出來的不算。**

**來源**:**本輪裁決確認**(2026-09-24);
**裁決者轉述此要求源於 2026-09-03,本次未取得該日原始裁決文件。**
⚠ 所以**不得**把它引述成一條已查證的歷史條文 —— 它從今天起是條文,
而它在今天之前只存在於裁決端的紀錄裡。
(**本輪才發現 repo 裡查無此條**:全庫只有
`docs/agents/friction-log.md` 一處提到「三層驗收(UNIT / CLEAN / REAL)」、
`docs/tickets/framework-updates/22-machine-recovery-drill.md:531,535`
記了一次「REAL 層通過」,**兩處都沒有寫來源規則**。)

**理由不是「人比較可靠」,是【環境】**:agent 跑的是 agent 的環境,
而 REAL 層要驗的恰好是**另一個環境**裡會發生什麼。

**實例(2026-09-24,票 133 的權威層端對端)**:腳本在 agent 環境通過全部靜態核對,
**裁決者在普通 PowerShell 首跑,第 1 案就停** —— PATH 上沒有 `sh`。
那個缺陷 agent 自己跑一百次都碰不到,因為它每次都跑在有 `sh` 的殼裡。

⚠ **這條擋得住「環境不對」,擋不住「設計不對」。**
**人工按下按鈕不自動代表獨立設計或獨立驗收** ——
腳本由 agent 設計與撰寫、由人執行,兩者**不互相背書**。

**agent 自跑仍然有用,但只能當【診斷材料】**:排除腳本自身的機械問題
(環境假設、防誤用誤擋、fixture 構造沒成立)。
那種跑法要**標明「非證據」**,且**不得**作為結案依據。
操作細節見 `docs/agents/authority-layer-e2e.md`。
