# ADR 發號規則

與 friction log 的發號規則(`friction-log.md` 開頭)同一套邏輯,同一個理由:
**決策紀錄會被照抄到每一個安裝的 repo**(`docs/adr/` 在 portable-manifest 標 `copy`),
所以號碼不是本地的事。兩本 log 各自發號,遲早撞號 —— friction 已經撞過一次(F-046)。

## 規則

1. **框架層 ADR 用 `F-` 前綴**:`F-0013-r3-redlight-judges-the-implementation.md`。
   前綴進檔名與號碼本身,貼出來就自我識別,不依賴上下文。
2. **每個安裝的 repo 用自己的三字母前綴**,與該 repo 的 friction 前綴一致:
   台股分析師影音 `TSA-`、台股資訊收集 `TSI-`。
   `docs/adr/` 標 `copy`,所以專案自己的 ADR 要用**單檔 skip** 列在 manifest 裡,
   否則下一次更新會被整份覆蓋。
3. **專案發現的框架層決策**回 monkeyleash(原 agent-gates)開票,落地才給 `F-` 號。
   專案那則**不刪不改號**,原地加一行指向新的 `F-` 號 ——
   歷史不為了整齊而動(與 wrapper commit 的歸屬同一條)。

## 切換點(A 案)

**`0001`–`0012` 維持裸號,不追溯改名。**

理由與「專案那則不刪不改號」同一條:已經發出去的號碼被引用在 ADR 內文、
CLAUDE.md、gate.py 的 `RULE_DIVERGENCE`、票、friction log 裡。
追溯改名要逐筆改引用,而**漏改是靜默的** —— 一個指向不存在檔案的引用
不會有任何東西出聲,只會在有人去點的時候才發現。
整齊不值那個風險。

**`0013` 起用 `F-`。** 切換點寫在這裡,不靠記性。

## 已知缺口(未關)

**沒有機器擋著「有人又發了一個裸號」。** 目前只有這份文件在約束。
`0013` 之後出現裸號會靜默通過 —— 而靜默正是這套東西一路在修的東西。
另立票處理(不綁在發號規則落地那一批)。

判準與 friction log 那條相同:**這一則搬到另一個專案還成立嗎?**
成立就是框架層,用 `F-`;不成立就是專案層,用該 repo 的前綴。
